Agents can retrieve documents and query databases, but reliability gates agentic analytics: a revenue metric answered faster is worth nothing if the number is wrong. Agents need a context layer that tells them where data lives, what it means, whether to use it, how to use it, where it came from, and what is similar. NVIDIA Auto Ontology is an open library that builds that layer from enterprise metadata, reconciles definitions across systems, and exposes it to any agent harness through MCP, CLI, and API. It complements the semantic models customers already own.
It enables developers to:
- Discover: generate enterprise ontologies from metadata; connect existing ontologies and semantic models; build AI-ready knowledge graphs.
- Ground: give agents trusted business meaning for metrics, entities, and relationships; reconcile inconsistent definitions across systems.
- Validate: check generated queries against certified definitions and lineage; return provenance with every answer.
- Expose: serve context to any agent harness through MCP, CLI, and API. Learn: fold certified corrections and usage back into the ontology, so shared context improves with every question.

You can set a full triplet, only some of its fields, or none at all — any field

LZ4 is a lossless compression algorithm, providing compression speed > 500 MB/s per core, scalable with multi-core CPUs. It features an extremely fast decoder, with speed in multiple GB/s per core, typically reaching RAM speed limits on multi-core systems.

Inside GitHub’s new Git storage architecture
GitHub’s new Git storage architecture is built so thousands of agents can push to a single repository at once. Here’s how it works.
Last week at GitHub Universe, we announced our new Git storage architecture, capable of handling thousands of writes per second with reads that scale on demand. Through internal testing, we’ve demonstrated the ability to support 5,000 concurrent agents working on a repository, sending 7,200 pushes per second to a repo, all while serving read traffic with consistently low latency. This new architecture is the foundation for GitHub to support agentic development for hundreds of millions of developers, and we’ve been building it underneath GitHub while it keeps running.
Over the past year, agents changed what a busy repository looks like on GitHub. In our first post in this series, we laid out the two principles behind our next-generation Git storage architecture: minimize coordination, and decouple storage from compute. In our last post, we covered the bridge: moving 99.99999% of repositories into Azure, scoping the write quorum to individual references, and standing up virtual replicas backed by Azure Blob Storage.
We also left off with an observation: very little of a write needs to be ordered. Git objects are immutable and named by their contents, meaning two writers can store them at the same time without agreeing on anything. The part of a push that needs agreement is the reference update, and a reference update is tiny in comparison. Virtual replicas were the first step toward building around that, and the means by which we onboard repositories to the new architecture.
The rest of the architecture builds on that observation. Only reference updates need agreement. That lets the parts of Git infrastructure that used to be tightly coupled (storing data, serving requests, and maintaining repositories) scale independently. For developers, Git stays Git: they push, fetch, and branch the same way, with the same protections in place. Below, we walk through the requirements behind the design, follow a request through the system, and dive deep into two of its components.
Building for agent scale
We think about the scale of the GitHub platform along two axes:
- Horizontal scale is how many developers and agents can work across many repositories. Many of GitHub’s current approaches on this axis have been battle-tested over the years and are carried forward to the new architecture: partitioning of tenants across infrastructure, isolation and/or fairness enforcement of tenant traffic, and load-aware routing, to name a few.
- Vertical scale is how many developers and agents can work on one repository. As agents write more code, we expect individual repositories to get larger and busier, so most of our requirements came from the vertical axis.
Today, the busiest repositories on GitHub.com receive at most dozens of writes in a single second, typically in short bursts. As more of that work shifts to agents running in parallel and around the clock, we expect those bursts to become a sustained rate within the next year. Each push leads to more reads: CI runs, deployment systems pull the new commit, and other agents fetch it for context. This read fan-out results in a large amplification effect on overall traffic that scales with writes.

- Accept thousands of writes per second.
- Support multiple writer nodes. There are two reasons for this:
  - Experience has taught us that indexing incoming packs and checking object connectivity are the most CPU-expensive parts of a write, and that cost scales with the size of the write, so a single node will become compute-bound quickly.

- Let each component scale independently.

[韩剧] Doctor X：白色黑手党时代
- 关键词：医疗 / 剧情
- 又名：Doctor X: 하얀 마피아의 시대 / Doctor X: Age of the White Mafia
- 片长：65 分钟左右（单集）× 12 集；豆瓣链接
外科手术之神降临！
@利兹与青鸟：疫情后，韩国医疗行业动荡，医护资源不足，在这个连救死扶伤都被金钱和权力左右的「白色黑手党时代」，自称 Doctor X 的桂秀晶横空出世，入职首尔一家重要的医疗中心，却无需听命于任何人，因为她是张社长代班中介所的外包医生，不必遵循医院的教条、等级秩序和交际，遇到不公平的事直接动手，遇到没医德的人直接开骂，最后凭自己精湛的外科技术让人心服口服。新来的实习医生、初来乍到但善良炽热的朴泰京就成了她的小粉丝。
本剧基于日剧《X医生：外科医生大门未知子》进行了较大幅度的改编，女主人设变为有战区创伤、有点天然呆的冷面毒舌形象，故事也更贴合韩国国情，涉及财阀和底层患者的阶级差距、医疗体系的弊病、职场与军队霸凌、医生职业道德等社会议题，完全可以脱开原剧当新故事看。有不同手术病例争分夺秒的紧迫感，也有镜头对准手术台的真实感；有团结反抗权威、揪出人渣的热血，也有普通人守望相助的感动，更有女主利嘴舌战群儒的畅快和搞笑，很是精彩。
[韩剧] 恋爱博士
- 关键词：剧情 / 爱情
- 又名：연애박사
- 片长：70 分钟左右（单集）× 12 集；豆瓣链接
不是所有人，在初次恋爱时就会成为专家。
@潘誉晗：朴民载曾是一名游泳健将，可惜因为患病，他的一条腿截肢了，永远离开了泳池。现在，他是一名博士生，生活平淡，学业顺遂，他尝试向心仪的女生告白，却发现她已经有了心上人。失意之际，他意外结识了一位名叫林宥珍的女生，林宥珍是和他同校的研究生，正值就业与学业困顿的时候。两个正烦恼的年轻人因意外相遇，磕磕绊绊，却也碰撞出了爱的火花，只是身上的那份残疾，让民载直觉自己并不适合林宥珍。
已故导演安畔锡的遗作《恋爱博士》，以年轻男女的相爱作为契机，讨论了两个心中有伤口之人的彼此治愈，加上男主人公设定的身体残缺，更有一份现实意义。安畔锡导演的个人风格配合这样的剧情，更加治愈。哪怕是这样一部有些小小忧伤情节，却也能在让人心酸的同时，感受到温柔。在那个瞬间，观众所感受到的，不单纯是主角间的爱意，更是通过这份爱，汲取好好生活下去的力量。
[美剧] 嗜血法医：杀魔复生 第二季

- 又名：Dexter: Resurrection Season 2

还有很多连环杀手等着海湾屠夫去解决呢。
@潘誉晗：隐藏身份当一个 Uber 司机之余，德克斯特的另一项事业，依然经营得很好。上季最后，他拿走了普雷特的杀手名单，追踪着上面的连环杀手。儿子哈里森从警校毕业了，就要成为一名刑警。另一边，一个自称「五区杀手」的人出现了，他给警方打去了杀手预告，然后按照预告杀了人并拍成了视频，在公园隔空投送给了陌生人。
《嗜血法医：杀魔复生》第二季的开播，恰逢系列剧开播第二十周年，于是剧集重置了原版片头。熟悉的配方惹得观众「爷青回」，有点遗憾的是德克斯特不再年轻，这也带来了本季一个重要设定：海湾屠夫迎来中年危机。人老了干啥都有点心酸，杀手也不例外，德克斯特会因为老花眼看错地址被差评，甚至体力也有点不如以往——德克斯特从未想到自己的五十多岁会是这样。
回归首集就是要素拉满，除了常规情节，更增加了「纽约开膛手」「五区杀手」两条 Boss 线，剧情丰满、节奏紧凑。
[美剧] 镀金时代 第四季
- 关键词：剧情
- 又名： The Gilded Age Season 4
- 片长：60 分钟左右（单集）× 8 集；豆瓣链接
马特·达蒙和大卫·莱特曼拿了群演费用客串第一集，8:29 左右，没台词默默地过了趟马路。
@潘誉晗：故事承接上季剧情，罗素夫人所扶持的大都会歌剧院，打败了老钱贵族坚守的学院派音乐，这件事就像是一道突然出现的峡谷，在纽约的上层阶级里形成了一道裂缝。她成功了，却也因此反噬到了她的家庭。曾经相濡以沫的罗素夫妇，竟然开始貌合神离；远嫁的格莱蒂斯因生产大出血，被医生摘掉了子宫。而另一边的玛丽安，开始专注自己的事业。
由《唐顿庄园》主创团队所打造的高分美剧《镀金时代》，于本月开播了第四季。这一季的内容，除了依然聚焦工业革命后，纽约社交圈这群新贵老钱的阶级碰撞之外，进一步地挖掘了女性角色的个人成长。于是，我们看到罗素夫人依然进攻着，看到了玛丽安努力挣脱了姑妈们的庇护，也看到了作为黑人女性的佩吉这一路的不易。剧集的服化依然精美动人，得益于著名服装设计师卡西娅的功劳，剧中每一幕，都完美捕捉到了 19 世纪末上流社会的奢华与精致。
[韩剧] 谎言
- 关键词：剧情 / 爱情 / 悬疑
- 又名：라이어
- 片长：65 分钟左右（单集）× 12 集；豆瓣链接
究竟是谁在说谎？
@潘誉晗：单身父亲闵俊浩，这天认识了儿子的老师姜智善。虽然两人的相识源于一场误会，但智善美丽、体贴又温柔的模样，还是在俊浩的心里泛起了涟漪。俊浩显然也给智善留下了一个好印象。后来，两人在校外偶遇，他们在海边漫步、在餐厅共进晚餐，然后，他们度过了甜蜜的一晚。可苏醒后，智善却崩溃了。她没想过在约会的第一天就和一个男人发生关系，于是，她选择了报警。面对指控，俊浩坚决否认。
根据英剧《谁在撒谎》改编的韩剧，讲述了一个恍如罗生门般的故事。关于同一件事，事件中心的男女有着不同的说辞。虽然失去了关键部分的记忆，智善坚信自己被性侵了，可俊浩却不这么认为，在他看来，这一晚是双方你情我愿的情动，测谎仪也证明他没说谎，可智善的失控也不像假的。围绕「谁撒谎」所展开的故事，关注了女性遭受伤害这一议题，演员们的精湛演绎，让这一话题更有讨论度。
[英剧] 嫌疑爱人
- 关键词：惊悚 / 犯罪
- 又名：The Blame
- 片长：60 分钟左右（单集）× 6 集；豆瓣链接
当女人不在场的时候，男人是不一样的。
@潘誉晗：瓦克斯特德小镇警局这天接到了一个报案，有位 16 岁的少女失踪了。前一晚，警方恰好接过一个被掐断的求救电话。很快，少女的尸体就被发现了。艾玛和搭档汤姆负责调查此案，在调查的过程中，艾玛在汤姆口中得知，这位死去女生的照片，曾被局里一位巡警打印下贴在储物柜上，甚至在照片上留下了不堪的语言。
虽然剧集较为冷门，女主角过度医美的脸也让一些观众诟病，但是凭借着不拉扯、不累赘的紧凑剧情，这部剧还是在小范围内收获了一定的好评。案件本身其实不算特别复杂，但胜在层层递进、环环相扣，不看到最后，你不能轻言断定凶手是谁。毕竟随着案件的深入，你发现好像所有人都心怀鬼胎，每个人都藏着秘密。寻找案件真相之余，所揭露的女性困境也很值得探讨。作为小镇警局里唯一一位女警，哪怕艾玛能力出众，但是在满是男人的警局里，她还是能感受到那种微妙的气氛。
[电影] 忘却之岛
- 关键词：奇幻 / 冒险
- 又名：Forgotten Island
- 片长：109 分钟；豆瓣链接
只要彼此不忘记，我们永远在一起。
@SHY：形影不离的菲律宾少女乔和莱莎，发誓要组一辈子好朋友，却敌不过现实的大手。高中毕业后，乔在快餐店打工，莱莎则要去加州理工深造，即将分别的两人，意外捡到一枚神奇沙币，来到被遗忘的纳卡利岛。这对迷失了方向的挚友，能否赶在航班起飞前，找到回家的道路？
曾带来《穿靴子的猫 2》的两位导演，以多年的深厚友谊和共同的菲裔联系为灵感，打造了这部扎根于菲律宾神话的原创动画电影。汲取前作的成功经验，本作调和多种视觉风格，梦工场的精湛 CG 与艺术家描摹的手绘场景交融，挥洒色彩斑斓的美术，赋予奇异生物别样的生命力，洋溢着喧嚣而热烈的东南亚风情。
当记忆成为代价，共度的时光更显得可贵，学会正确对待离别，才能迎来真正的成长。倘若过去的记忆造就了现在的自己，只要与朋友分享，就永远不会遗忘，无论相隔多远，都能重拾初心。编织天马行空的未知邂逅，谱写放飞自我的纵情狂欢，这部看似小众的动画电影，歌颂真挚的少女情谊，相信能让更多观众共鸣。
[电影] 逃出布迪秀
- 关键词：恐怖 / 奇幻
- 又名：Buddy
- 片长：95 分钟；豆瓣链接
Buddy is coming~
@利兹与青鸟：橘色的毛绒独角兽布迪，是一个画风古早的儿童节目的主角。节目里有色彩鲜艳的公园、房子、钻石城，会说话的邮箱、书包和水井。当孩子们有困难时只要呼唤布迪，布迪就会现身给予帮助，但孩子们一定要听布迪的话。不听话的代价很快显露端倪，孩子们也从蛛丝马迹中渐渐发现布迪的真面目。而另一边的现实世界，格蕾丝遭遇了一些怪异事件，于是找来通灵师，却召唤出了布迪的儿童节目。更诡异的是，格蕾丝被拽进了电视世界，在那里，她将和孩子们一起对抗神秘的布迪。
这部小成本邪典恐怖片将可爱的人偶化为无情的怪物，在经典的砍杀片套路里加入了一些反常规的点子，让人在挨过有些平庸的电影中段后，在结局收获了小小的惊喜。电影用布迪的形象和儿童节目的规则怪谈抛出家暴、有毒教育等隐喻，恐怖背景音和童趣音乐无缝衔接的设计也十分有趣。导演似乎还有着打造一个布迪宇宙的野心，在片中并未完整点明布迪的来历，反而一晃而过更多独角兽角色，试图为续作埋下伏笔。
[真人秀] 海波朗商会
- 关键词：真人秀 / 旅行
- 又名：맛따라 길따라 대명이따라
- 片长：90 分钟左右（单集，具体集数暂时未知）
- 观看渠道：YouTube
徒步的时候，吃到好吃的会很开心吧。
@潘誉晗：「跟着大明寻味」系列的出现，让韩国的民众越发认可演员金大明在食物上的口碑，罗英锡 PD 见状灵机一动，提议金大明把这些美食复刻，开家商会，招待、回馈大众。于是，海波朗商会就此诞生。
「海波朗路」是韩国四条著名沿海徒步路线之一。面朝东海的海波朗路，沿着韩国大陆的海岸线延伸，连接了釜山和江原道，是许多人选择体验大陆海岸风光的不二之选。制作组在第 24 段路的路上找了一家临海店铺，让金大明在这，为过路的徒步者们提供食物。
于是金大明提前私下跑到相熟的店家学习如何烹饪，学完了这家就跑那家；拿自己当小白鼠试验，怎么样的酱汁比例才能做出最完美的拌面。开业第一天，他煮了鸡蛋，用印章在鸡蛋壳上印下「做得好」，去亲自体验一下海岸线的风光，把鸡蛋分发给偶遇的徒步者。这档节目的预算有限，胜在大家都真诚——希望能为那些徒步者，带去心灵与胃的满足。

[加拿大] 雅嘎疑云 @潘誉晗：为调查渔业大亨儿子亨利的失踪事件，私家侦探诺亚来到了这所海边小镇。在这他见到了和亨利的室友洛根，洛根和亨利长得一摸一样。然后，洛根惨遭虐杀。诺亚不禁怀疑，洛根的遇害是因有着和亨利一样的脸。根据同名话剧改编的剧集，融合了关于女巫的传统故事，很有氛围感，在多伦多电影节首映时就收获过一波好评。

[电影] 爱语 @潘誉晗：露易莎的未婚夫悔婚了，坚持了许久小说梦也没有起色。六年了，她都写不出让自己满意的作品。阴错阳差下，她开始替人写婚礼誓词谋生。这天她接了一个新客户，而客户的未婚夫正是她大学时期暗恋过的人。看着很套路的都市浪漫电影，却透过婚礼誓言与重逢，让人反思真实语言的力量，也让人看到了一个浪漫的职业。

在 2025 年末 M5 版 MacBook Pro 的文章中，我给出的结语是「在 AI 和大模型的发展如火如荼的当下，M5 芯片无疑昭示了 Apple 的新野心——在这个领域，Apple silicon 将大有可为」。文章发完没多久，内存和硬盘的超级涨价潮就席卷了全球，Apple silicon 也因为采用统一内存架构而成为了 AI 世界的宠儿。一年之后，当我再次摸到搭载了 M6 芯片的 MacBook Pro，颇有时过境迁的唏嘘之感。
新的基础款 MacBook Pro 在外观层面依然没有任何变化，但 M6 芯片的性能进步却令人瞩目，也直接提高了这部基础款的竞争力。在这篇文章里，我就来谈谈这款几天使用产品之后的感受。
外观：一点儿也没变，重量都一样
M6 款 MacBook Pro 的外观相较前代没有任何变化，甚至连重量都完全一致，所以我也就不多赘述了。就我个人来说，目前 MacBook Pro 系列的造型已经达到了美观和实用的平衡，除非有功能层面的需要，否则我希望 Apple 继续沿用，不要更改。
与此同时，全新的 PROLED XDR 版 MacBook Pro 的造型其实也没变，主要区别是减重减厚，并换用了新的 PROLED XDR 显示屏。所以，如果你在新老两条产品线之间纠结，那就主要考虑一下高素质萤幕对你的来说是否重要吧。PROLED XDR 确实很棒，只要你需要，肯定会喜欢。
关联阅读：《开启 Mac 的下一世代：MacBook Pro (PROLED XDR) 首发体验》
性能：GPU 和 NPU 的大胜利
既然新老基础款 MacBook Pro 的核心区别就是 SoC 升级，那我就在这个部分多讲两句。
M6 采用了新的架构设计，从之前的 10 核 CPU、10 核 GPU 变成了 12 核 CPU、12 核 GPU，而 CPU 架构从之前的 4 个超级核心加 6 个能效核心变成了 2 个超级核心、4 个性能核心和 6 个能效核心。同时，M6 比 M5 多了一个神经网络引擎（Neural-engine），在处理 AI 运算时的理论速度更快。此外，M6 的内存带宽也从 153GB/s 提升到了最高 170GB/s，对于运行本地 AI 大模型更为友好。
从市面上各家的性能测试来看，M6 比 M5 的 CPU 单核性能提升了大约 10%、多核 20%，GPU 提升大约 20% 到 30%，NPU 则约 40% 到 50%。在实际的使用中，我也结合我的常用工具，针对性地做了对比。
这里要先提一点：我的 M5 版 MacBook Pro 是 16GB 内存的最基础款，但 M6 版则升级到了 32GB。更大的内存在一些项目里带来了更多优势，具体表现会在对应的测试里说明。
我首先尝试的是播客剪辑，使用《Reaper》渲染一个由两轨人声组成的对谈，全长超过一个半小时，且挂满了dxRevive Pro、VOTT 和 RX 系列插件，在播客项目里已经是比较重度的剪法。
播客渲染主要考验 CPU 部分的性能，M5 用时超过 15 分钟，M6 则只用 10 分钟就结束了战斗，领先优势甚至超过了通过跑分得到的理论数值。
第二项是使用《LM Studio》运行本地大模型，模型为 Gemma 4 12B。
两者的模型载入速度区别不大，都在 20 秒左右；token 的吐出速度 M6 略优，为每秒 19 左右，M5 则为每秒 16 左右。在这个项目里，M6 更高的内存带宽想必发挥了一定作用。
这里就谈到了前面提到的内存容量问题。我的最初计划是使用较新的 Qwen3.8 27B 模型进行对比，但无奈 16GB 的 M5 直接被客户端禁止加载，于是才被迫改用了更小的模型。其实 32GB 的电脑不仅可以顺利加载 Qwen3.8 27B，而且 token 生成速度为每秒 10 个左右，还多了推理能力，在真实场景里会更实用。
这正是 AI 为大内存赋予的新意义——更大的统一内存有机会容纳体积更大的本地模型，干活的质量和效率也得以更佳。如果你需要在电脑上长期运行 OpenClaw 之类的 AI 代理服务，那把钱花在大内存上，选一个品质更高的本地模型，长期来看可能更加划算。
接下来回到性能对比，下一个项目是《ComfyUI》文生图，我使用 Flux 2 base 4B 模型，生成一张 1024*1024 的图片。M6 从首次加载模型到出图用时 5 分 50 秒左右，M5 则需要 8 分钟。两者速度都不算快，相比之下，M6 仍节省了不少时间。
再下一项是使用《Whisper Transcription》将一段不到 12 分钟的英文 YouTube 影片转成文字，模型选择 app 自带的 Large V3 Turbo。这是我测试 Apple silicon 的经典项目，《Whisper Transcription》会同时调用 GPU 和 NPU，而且非常依赖 NPU 能效；语音转文字又是我的常用场景，所以既能展示性能差异，也有现实意义。M6 用时为 24 秒 26，从文件拖入之后就开始出字，非常迅捷；M5 则用时 41 秒 14，明显慢了非常多。
更下一项是用《Topaz Photo》的自动模式（Auto pilot）模式将 10 张低分辨率猫猫图自动优化为高分图片，M6 用时 10 秒 07，M5 则要用时 20 秒 58。《Topaz Photo》主要调用 GPU 和 NPU，所以 M6 赢得也很明显。
最后也是最重度的测试，使用《Davinci Resolve》进行视频渲染。我直接选择了刚刚发布的新片《iPhone 变强了，但我没有》。
这支影片的视觉灵感来自《SHOGUN》，除了使用 GENESIS 胶片模拟插件辅助调色，我还在大量镜头中用到了 Lens Node 插件，以模拟强烈的旋焦和模糊感。而 Lens Node 是个极吃性能的模拟插件，无论 M3 Max 还是 RTX5080，我手里还没有可以在开启它的时候能做到满帧预览的设备。所以，连续渲染几十个挂载了 Lens Node 的镜头，对市面上的绝大部分电脑来说都算是「地狱难度」。
M6 在离电状态下用了 59 分钟完成了渲染，M5 则要用到超过 1 小时 16 分钟。这里要再次强调：大内存直接利好视频剪辑。我一直很依赖第三方插件来模拟胶片光晕、颗粒等效果，此类插件恰恰是吃显存大户。
而且，就在撰写本文期间，我刚好带着 M6 版 MacBook 出差搞了个 Mac 新品上手的短片，虽然导出速度嗖嗖快，但挂载一堆节点加插件之后，还是能明显觉察到它的实时回放的速度不及我的 M3 Max 主力机（因为除了大内存，更多的 GPU 核心和视频编码核心也会影响回放速度），但已经明显强过 16GB 的 M5。所以，如果你的使用场景里也涉及重度调色，那大内存务必得选。
选购建议
内存和硬盘大幅涨价打乱了很多人对一部电脑的价值判断和购机思路，甚至让基础款 MacBook Pro 反而多了几分性价比。M6 芯片提供了足够的性能保障，无论修图、视频剪辑还是运行入门级的 AI 大模型，它都能应对。在此基础上，你原本可能需要加在 Pro 级 SoC 上的预算就能省下来，花给内存或者硬盘。虽然事实上内存和硬盘并没有真的变便宜，但⋯⋯钱包和心理，总有一个得先平衡 :)
而且，在我看来，考虑到涨价潮一时半会还不会褪去，「让用户在 SoC 上少花钱」这件事会显得愈发重要。只要 Apple silicon 的能效比持续进步，那基础款 Mac 的竞争力也一定会继续提升。
简单来说，如果你对电脑有一定的性能要求，但不需要极致澎湃，或者此前在用 MacBook Air，却想拥有更靓的萤幕、更猛的音响、更多的接口，那 M6 版 MacBook Pro 就是对的选择。

- [开启 Mac 的下一世代：MacBook Pro (PROLED XDR) 首发体验](https://sspai.com/post/118546) <sub>11-05 22:00</sub>

<details>
<summary>📄 展开阅读全文（5802 字）</summary>

让我们先从五年前说起。
当首款搭载 M1 Pro / M1 Max 芯片的全新 MacBook Pro 面世时，我称它开启了「Mac 的下一个五年」。如今，又是在一年中的最后一场 Apple 发布会上，MacBook Pro 不负五年之约，迎来了 Apple silicon 时代以来变化最大的一次迭代。
与五年前的彻底焕新不同，这一次 Apple 没有再将 MacBook Pro 推倒重来：熟悉的设计得以延续，机身变得更轻、更薄；最重要的变化，当然是这块 PROLED XDR 显示屏，这是 Mac 史上第一块 OLED 显示屏，也是第一块支持触控的显示屏。
看起来熟悉，拿起来不同
如果只看外观，这一款 MacBook Pro 似乎与此前并无二致：熟悉的深空黑色和银色选项，机身左右两侧依然是 MagSafe 3、三个雷雳 5、HDMI、SDXC 卡槽与 3.5 毫米耳机接口，键盘与触控板的布局也几乎没有变化。
但当你把这台 Mac从包装盒里拿出来的那一刻，就会感到不一样。
以我手上的 16 英寸机型为例，1.82 千克的重量比非 PROLED XDR 显示屏版的同尺寸机型轻了 320 克，厚度也从 1.68 厘米降到了 1.60 厘米。虽然 1.82 千克的重量并不能让这台笔记本电脑称得上轻巧，但是少了这 320 克，已经足以改变将这台 MacBook Pro 带在身边的感觉。
如果你非常看重便携性，又想兼顾性能，这一代配备 PROLED XDR 的 14 英寸 MacBook Pro 会是非常合适的选择。1.38 千克的重量比 15 英寸 MacBook Air 的 1.51 千克还轻了 130 克的重量，第一次上手这台 Mac 也要比 16 英寸 PROLED XDR 显示屏版机型的印象更深刻许多。
机身变轻，主要得益于更薄的 OLED 显示结构和重新设计的散热系统。为了配合触控，Apple 还重新设计了屏幕转轴，它的阻尼比过去稍大一些，点击屏幕下半部分时几乎不会晃动，只有触碰上半部分时才会出现轻微晃动，同时依然可以单手轻松打开上盖。
更窄的边框还让屏幕尺寸从 16.2 英寸增加到了 16.3 英寸，不过，这 0.1 英寸的增长几乎无法在日常使用中察觉，真正容易注意到的还是进一步收窄的边框。尤其是在显示纯黑背景时，OLED 像素会完全关闭，与四周边框融为一体，看起来仿佛屏幕一直延伸到了机身边缘。
值得一提的是，这台 MacBook Pro 机身背面的 Apple 标志也重新亮了起来，这项在 2016 年 MacBook Pro 改款后消失的设计，时隔十年终于回归。它没有单独的开关，亮度会随屏幕亮度一同变化，屏幕熄灭后也会随之熄灭。对于用过早期 MacBook 的用户来说，这或许也是新款最容易唤起熟悉感的细节之一。
黑色差别不大，屏幕变化不少
MacBook Pro 的这块全新屏幕有一个略显拗口的名字：PROLED XDR 显示屏。
简单来说，它是 Mac 上的第一块 OLED 屏幕，使用与 iPad Pro 类似的双层串联 OLED 结构。两层发光层共同产生画面，在达到相同亮度时，每一层需要承受的电流更低，因此能够同时兼顾亮度、功耗和使用寿命。
不过，与 iPad mini 从普通 LCD 直接换到 OLED 不同，MacBook Pro 原本的 Liquid 视网膜 XDR 显示屏虽然仍是 LCD 屏幕，但是凭借出色的 mini-LED 背光技术，日常正对屏幕使用时，已经能够呈现足够深邃的黑色。因此，在大部分画面中，OLED 带来的黑位提升并没有想象中那么明显。
但 Liquid 视网膜 XDR 显示屏依赖 mini-LED 背光，背光分区始终不可能与像素一一对应。播放星空、夜景，或者黑色背景上只有少量文字的画面时，明亮内容周围仍然会出现一圈轻微的光晕；电影字幕出现在黑边区域时，也能看到背光分区随着字幕亮起和熄灭。
OLED 的每个像素都能独立发光，显示黑色时可以直接关闭。没有背光与分区，明亮内容周围的光晕也随之消失，黑底白字的边缘更加干净，暗场中靠近高光的阴影也不会被一起抬高。尤其是在关灯后观看 HDR 电影时，这种差别会变得十分明显。
Apple 为 PROLED XDR 显示屏标出了 10000000:1 的对比度，是上一代 1000000:1 的十倍。不过，这并不意味着实际观感也会随之提升十倍。对于大部分明亮、色彩丰富的照片和网页，两块屏幕本来就都足够出色，很难一眼分出高下。这个数字更多意味着，当极暗与极亮的内容同时出现时，OLED 可以让高光保持足够明亮，同时关闭周围的黑色像素，不再受到背光分区的限制。
比起对比度数字上的十倍提升，OLED 响应速度带来的变化反而更容易被察觉。PROLED XDR 显示屏的 ProMotion 自适应刷新率依然是 10Hz 至 120Hz，但 OLED 像素的响应速度比 LCD 快了一个数量级。快速滚动网页、拖动窗口或者转动游戏视角时，文字与物体边缘的拖影更少，画面看起来也更加清楚、利落。
对摄影和设计工作者而言，PROLED XDR 显示屏对 Adobe RGB 色域的支持，才是更有意义的升级。继 Studio Display XDR 显示器之后，Apple 第一次在 Mac 的内置屏幕上同时原生支持了 P3 和 Adobe RGB 广色域。处理照片、印刷设计或进行现场预览时，Adobe RGB 能够呈现 P3 无法完全覆盖的绿色与青色；这也意味着，部分工作不再必须依赖外接专业显示器。
OLED 早已不是什么新技术，MacBook Pro 却直到现在才用上它，一个重要原因是笔记本电脑的屏幕更大、静态内容更多，连续使用时间也更长，对亮度均匀性、功耗和面板寿命的要求都比移动设备更高，烧屏风险也更难忽视。
Apple 在 PROLED XDR 显示屏技术白皮书中特别提到，这块面板采用了全氧化物晶体管层，M5 Pro 和 M5 Max 中的显示引擎还会实时调整每个像素，以维持画面均匀性并降低烧屏风险。有行业消息认为，这块由三星显示供应的面板还使用了 HMO (High Mobility Oxide) 技术；如果这项消息准确，HMO 可以在驱动大尺寸、高分辨率 OLED 面板时降低功耗，并让不同区域的亮度与灰阶保持一致。
多了触控，还是熟悉的 Mac
MacBook Pro 首次支持屏幕触控，听起来像是一次足以改变交互方式的更新。真正上手之前，我也很好奇 Apple 会如何为 macOS 设计触控交互。实际使用下来，它带来的变化并没有我想象中那么大。
MacBook Pro 原本就有一块足够好用的触控板，macOS 中的大部分界面也依然围绕指针设计。在选择文字、移动窗口，或者操作专业 app 中密集的按钮和菜单时，触控板与鼠标通常更加精准，也更加省力。使用 MacBook Pro 时，双手本来就在键盘和触控板附近，多数时候没有必要特意抬起手臂触碰屏幕；如果连续使用触控，手臂也更容易感到疲劳。
因此，触控并没有改变我使用 Mac 的主要方式，也很难成为一项高频操作。对我来说，它的意义并不在于取代触控板和鼠标，而是作为一种补充，在少数适合直接操作屏幕的时候派上用场。
比如查看照片时，可以直接在屏幕上双指缩放，或者用手指在几张照片之间快速切换；使用 Xcode 调试 iPhone 模拟器时，也能像操作真正的 iPhone 一样点击、滑动和使用多指手势，不再需要用鼠标模拟触摸。
新款 MacBook Pro 的触控体验本身也足够成熟。触控传感器被直接集成进显示面板，实际使用时几乎感受不到延迟，滑动和缩放都足够跟手。
应用方面，大部分现有 app 不需要更新适配，就能在这台 Mac 上完成点击、滚动和拖动等基本触控操作。macOS 会将触摸转换成 App 能够识别的鼠标操作，因此即使没有经过专门适配，大部分现有 App 也可以直接使用触控。
不过，能够触控并不等于已经为触控优化，第三方 App 的适配重点之一，是让系统理解每一次触控想要完成什么操作。比如在 3D 建模软件中，同样是用手指拖动，可能意味着转动模型，而不是滚动界面；双指操作则可能对应缩放、旋转或移动视角。与此同时，细小控件的操作区域也需要适当扩大，依赖鼠标悬停的功能则要提供其它触发方式。
整体而言，我不认为触控是 Mac 或 macOS 必不可少的一项功能，它在少数场景中确实会更方便；但对我来说，这仍然更像是这块屏幕附带的一项能力：用得上时伸手点一下，不需要时也不会改变原有的使用方式。如果完全不需要触控，也可以在「系统设置」中将屏幕触控关闭，让这块屏幕只保留显示功能。
看得见，也用得上
2021 年重新改款的 MacBook Pro 用「刘海」换来了更窄的屏幕边框。当时，这块区域除了容纳摄像头，并没有承担更多功能。尤其是在 iPhone 引入灵动岛之后，希望 Apple 将它带到 Mac 的声音便一直没有消失。五年之后，灵动岛终于来到 Mac，开始承担信息显示与交互功能。
单从外观来看，灵动岛已经比过去自然许多：OLED 可以完全关闭摄像头开孔周围的黑色像素，让它更容易融入界面；更小的宽度也为菜单栏腾出了空间，可以容纳更多图标。变化也不仅限于外观，Apple Music、电话、AirDrop 和计时器等实时活动会出现在这里，并且可以直接用触控操作。
与灵动岛一同到来的，还有 macOS 原生的实时活动。预装 macOS 27.2 的 PROLED XDR 版 MacBook Pro 已经支持了这项功能，连接外接显示器时，相同的内容会出现在菜单栏中，类似 iPhone 实时活动在 Mac 上的显示效果。从目前处于测试版本的 macOS 27.3 开始，其它非灵动岛 Mac 机型也会在菜单栏中支持原生的实时活动显示。

            Abstract:Evolution has shaped intelligence for billions of years. Artificial intelligence (AI) now raises a striking possibility: intelligence may begin to direct its own evolution. As AI agents become capable of modifying and evaluating their own behavior, how quickly could they improve, and how can that improvement remain safe? We develop a theoretical framework comparing Darwinian, Lamarckian, and agent-directed evolution following environmental change.
