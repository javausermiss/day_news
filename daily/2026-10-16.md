The other half of the context problem.
Every MCP tool call dumps raw data into your context window. A Playwright snapshot costs 56 KB. Twenty GitHub issues cost 59 KB. One access log — 45 KB. After 30 minutes, 40% of your context is gone. And when the agent compacts the conversation to free space, it forgets which files it was editing, what tasks are in progress, and what you last asked for. On top of that, the agent wastes output tokens on filler, pleasantries, and verbose explanations — burning context from both sides.
Context Mode is an MCP server that solves all four sides of this problem:
- Context Saving — Sandbox tools keep raw data out of the context window. 315 KB becomes 5.4 KB. 98% reduction.
- Session Continuity — Every file edit, git operation, task, error, and user decision is tracked in SQLite. When the conversation compacts, context-mode doesn't dump this data back into context — it indexes events into FTS5 and retrieves only what's relevant via BM25 search. The model picks up exactly where you left off. If you don't --continue, previous session data is deleted immediately — a fresh session means a clean slate.
- Think in Code — The LLM should program the analysis, not compute it. Instead of reading 50 files into context to count functions, the agent writes a script that does the counting and console.log()s only the result. One script replaces ten tool calls and saves 100x context. This is a mandatory paradigm across all 17 supported clients, plus the OpenClaw gateway integration: stop treating the LLM as a data processor, treat it as a code generator.
// Before: 47 × Read() = 700 KB. After: 1 × ctx_execute() = 3.6 KB. ctx_execute("javascript", ` const files = fs.readdirSync('src').filter(f => f.endsWith('.ts')); files.forEach(f => console.log(f + ': ' + fs.readFileSync('src/'+f,'utf8').split('\\n').length + ' lines')); `);
- No prose-style enforcement — context-mode keeps raw data out of context but never dictates how the model writes its final answer. Brevity, completeness, formatting — your model's call (or yours via your own CLAUDE.md / AGENTS.md). Aggressive brevity prompts have been shown to degrade coding/reasoning benchmarks (Moonshot AI on kimi-k2.5) — the routing block stays focused on where data goes, not on how the model talks.

nvm is a version manager for node.js, designed to be installed per-user, and invoked per-shell. nvm works on any POSIX-compliant shell (sh, dash, ksh, zsh, bash), in particular on these platforms: unix, macOS, and Windows WSL.

Running either of the above commands downloads a script and runs it. The script clones the nvm repository to ~/.nvm, and attempts to add the source lines from the snippet below to the correct profile file (~/.bashrc, ~/.bash_profile, ~/.zshrc, or ~/.profile). The Short Version
I think I have good news about the nature of neural networks.
After many months studying neurons and circuits in image and language models, I’ve come to believe a network’s own mechanisms are its legible building blocks, and that the outlook for mechanistic interpretability may be far better than I’d feared. The canonical evidence of polysemanticity and superposition that convinced much of the field, including me, that networks pack concepts arbitrarily was misread. What looked like arbitrary packing was mostly a motif I’ll call recursive generalization, which is much less concerning. This means we can study networks directly, instead of first untangling them. Neural networks are already clean.
There are at least two ways to approach mechanistic interpretability. The first is rapid normal science on the network itself: look at a network’s neurons and circuits, study how they relate, watch data flow through them, and run experiments at agentic scale to test explanations. The second starts from a list of hypothesized features and tries to extract them all, designing increasingly sophisticated reconstruction objectives and usually ignoring the original.
The field began with the first approach and fell back to the second because neural networks seemed to be tangled knots. We had canonical examples of polysemantic neurons, the broad name for a neuron that appears to have multiple unrelated jobs or that looks impossible to understand. The most famous one, in an image model, responded to both cat faces and the fronts of cars. And the last layer of the early field’s model organism, InceptionV1, seemed so full of arbitrary mixtures it wasn’t clear how to study it: almost none of the neurons were easily interpretable.
The leading explanation for polysemanticity was superposition. This proposed a new learning principle: when a neural network runs out of neurons, it stops grouping related things together and instead begins folding unrelated things together, simply because they don’t interfere. The result is a kind of knot: the network could have folded in many almost equally good ways, so which things a neuron groups together tells you almost nothing. You have to unfold the knot before you can study anything. In practice that means training a second model – a decomposition such as a sparse autoencoder – to approximate the network as it would look unfolded and studying that instead. If the network really is knotted, there may be no alternative.
One main result is that superposition was the wrong explanation for InceptionV1. Architectural problems made later layers overflow. Weak interpretability tools amplified these problems, making the late layers seem incoherent. Pushing existing reactors to produce more could help provide more clean power for data centers, quickly. But just how much additional power can we count on?
Upgrading equipment at existing nuclear power plants can allow them to reach a higher capacity; the process is called a power uprate. Operators have been doing this since the 1970s in the US, but it’s been less common in recent years as demand for electricity plateaued and cheap natural gas put financial pressure on nuclear power plants. Some plants closed, and putting in more money to produce more electricity didn’t make much sense at others. Between 2001 and 2010, the US Nuclear Regulatory Commission approved over 80 uprates. Between 2011 and 2020, the number was 33.
But with the rise of AI and the related boom in electricity demand, there’s been a shift. We’re seeing shuttered plants like Palisades and Three Mile Island race to reopen. And existing plants are looking to uprate again.
Some uprates are minor, involving changes to instrument setpoints or calculations at the plant. But more major overhauls, which can boost reactor power by as much as 20%, require replacing plant equipment.
Generally, uprates involve using fuel that’s more highly enriched, or a higher volume of fresh fuel, in the nuclear reactor. That helps produce more steam, which is used to turn a turbine and generate electricity. To handle that additional energy, the main turbines and equipment such as pumps, motors, generators, and transformers are upgraded.
The most recent major uprate approved in the US was for three reactors at the Browns Ferry nuclear power plant in Alabama. A $475 million project saw that plant expand its power capacity by 14% between 2018 and 2019.
Things could pick up soon, though. Constellation announced plans this week to spend more than $4.3 billion on uprates to 11 reactors. The additional electricity will be enough to power roughly 700,000 US homes.
Behind it all? Big Tech money. Google agreed to buy electricity from these plants, and the 20-year agreement was a major factor in making the uprates happen. A note about cost: On a per-kilowatt basis, that Constellation project is less expensive than building a new reactor, but it’s still more expensive than building a new utility-scale solar farm with energy storage or a combined-cycle natural-gas plant.

“With real organ banking … instead of the patients waiting for the organ, it’s the organs that are waiting for the patients,” says Finger.
Scientists have been able to cool cells to ultra-low temperatures through a process called vitrification, which essentially turns them to something like glass. This procedure is already used to store eggs, sperm, and embryos. Vitrifying whole organs is much harder.
Some problems can be avoided with cryoprotectants—chemicals that work like antifreeze and prevent damaging ice crystals from forming. But these chemicals tend to be incredibly toxic. It’s also difficult to rapidly and uniformly cool large tissues, and just as hard to evenly rewarm an organ all the way through.
Working with John Bischof, a bioengineer at the University of Minnesota, Finger and colleagues have come up with a solution. Once an organ has been loaded with a cryoprotectant, they infuse it with iron oxide nanoparticles. These nanoparticles don’t do anything to the cells. But when it’s time to rewarm the organ, they can be activated with an electromagnetic field.
When the radiofrequency of that field switches between two states, the particles also flip, realigning themselves with the field. That causes them to release heat throughout the organ. Adjusting the power of the field allows the team to control the rate of heating so that it gets faster once the organ reaches -120°C.
The researchers successfully vitrified rat kidneys using this approach in work published in 2023. Back then, they were able to rewarm kidneys that had been kept in a freezer for up to 100 days before transplanting them into rats.
Since then, the team has been trying to achieve the same success with bigger organs. Pig kidneys are thought to be a good model for human ones—they’re about the same size and look similar. Rat kidneys weigh around one gram; pig kidneys are around 100.
It hasn’t been easy. The cryoprotectant used for vitrifying rat kidneys didn’t work as well in the pig organs. “We had to rediscover and modify the cocktail,” says Bischof. “That’s why it’s taken us three years.”

Then they start to load it up with the cocktail of cryoprotectants, slowly enough to ensure an even spread through the organ but quickly enough to minimize any toxic effects. It takes around two hours.

- [顺应变化，重申标准：《少数派创作手册》修订说明](https://sspai.com/post/116181) <sub>10-15 16:09</sub>

四年前，我们发布了《少数派创作手册》（manual.sspai.com），旨在让作者更快捷地获得创作过程中所需的信息，以及更一致地传达对于内容选编的标准和主张。四年来，《创作手册》获得了作者们的广泛查阅，也帮助我们持续吸引着新作品。
不过，上一版《创作手册》也存在一些不足。例如，关于何种文章可获精选或首页展示，旧版只给出了若干原则。在实际沟通中，这未能有效向作者解释疑问及提供改进建议。又如，旧版未能充分解释「社区作品」及「投稿作品」适用的不同提交与审阅流程，导致了不必要的沟通成本。此外，随着作品中自我宣传内容、AI 生成内容的增多，以及签约、审阅流程的变动，有关规则也需要继续更新。
为此，我们最近在上一版的基础上，对《创作手册》做了一次大幅修订。其中，本次修订最主要的更新，就是新增了《少数派作品审阅规则》（《审阅规则》）。在《审阅规则》中，我们首次以条文形式，订明审阅文章的流程和标准，以便作者了解对文章不同层次的要求，并为编辑部作出一致的判断提供依据。
立足一般读者视角的分层级要求
《审阅规则》总结过往实践，将作品的处理方式分为发布、精选、首页展示（或例外首页展示），并提出不同层次的要求。
其中——
- 「发布」是指文章公开、可通过用户主页及文章链接访问，但并不会在少数派其他位置获得展示。要使作品适于发布，只需做到内容合规、基本完整可读、并在事实及技术上基本可靠。对于现有作者而言，其作品推定为适于发布，亦即一经提交即可公开访问（因选择投稿而待审阅的作品除外）。对于新作者提交的前三篇文章（即所谓「新手上路」文章），编辑部将在人工审阅后决定是否适于发布（第 2.1 条）；
- 「精选」是指将作品展示于「社区」页面及桌面端首页侧边栏。要获得精选，作品需要围绕一个明确主题充分展开、体现独立成果、内容可靠，及对一般读者有价值（详见下文）（第 2.2 条）；
- 「首页展示」顾名思义，是指将作品展示于首页主时间流。要获得首页展示，作品还需要是少数派首发、表达规范、篇幅适当、主题新颖，并体现出一些明显优势（第 2.3 条）。特殊地，如果一件作品未满足首页展示的全部条件，但在选题、深度、创意等方面有突出优势，或者发布后获得相当积极的读者反响，那么也有机会获得例外首页展示（第 2.4 条）。
以近年颇受作者青睐的游记题材为例。如果一篇游记能以图文并茂的方式，翔实、清楚地阐述旅程，一般都可以达到精选的标准。但至于是否能进一步获首页展示，我们还会考虑配图是否美观、篇幅是否适中、语言是否流畅，以及是否不会与首页近期其他游记显得重复等等。因此，一篇关于热门目的地的「流水账」，尽管可能写得颇为认真，也无法获选在首页展示。
值得强调的是，根据《审阅规则》，编辑部站在「本站一般读者」的视角上考虑问题。例如，获得精选的标准之一，就是文章颇有可能令本站一般读者感兴趣、顺畅理解并有所收获（第 2.2(5) 款）。
所谓「本站一般读者」，是指这样一名读者：他或她的技术水平、知识储备及兴趣爱好均与较大比例的少数派用户相近，理解能力、观察力和谨慎程度均达到合理水平，但未必具有任何领域的专业知识（第 1.3 条）。因此，一篇涉及过于垂直领域的艰涩技术文章，或者一篇介绍过于浅显的操作流程简介，都无法通过上述「本站一般读者」的测试。
我们鼓励作者在开始投稿前，先做一番少数派站内的「文献回顾」，阅读一些过往的受欢迎同主题文章及其评论互动，以便了解少数派一般读者对拟议主题的兴趣和了解程度，相信能帮助你写出更受欢迎的作品。
当然，编辑部在审阅时只能根据经验推知本站一般读者的情况，也未必能对作品的原创性和内容真实性作出完全正确的判断。因此，我们可能在文章发布一段时间后，结合读者的反馈情况，重新作出适当的处理，例如给予例外首页展示，要求作者补充修订，或撤下原创性存疑的文章（第 4.9 条）。
最后，有必要区分几个易混淆的概念，即作品的提交方式、处理方式和稿酬等级。其中——
- 提交方式是由作者在提交文章时自主选择的，包括直接发布（适合短篇、即兴分享的内容）和投稿（适合原创、首发的深度长文）。无论选择哪种方式提交，审阅的流程和标准都是相同的，但在同一日提交的作品中，编辑部会优先审阅投稿作品（第 4.5 条）；
- 处理方式是由编辑部根据《审阅规则》决定的，分为发布、精选、首页展示和例外首页展示。处理方式主要取决于文章质量，但由于首页展示要求文章为首发的投稿作品（第 1.4 条），一般只有投稿作品可获首页展示，而社区作品一般可获例外首页展示；
- 稿酬等级是根据处理方式决定的，分为第 1 级（发放给获例外首页展示的作品）和第 2 级（发放给获首页展示的作品）。两种稿酬等级的计算方式参见《创作指南》的「稿酬标准与发放」一节。
如我们在《创作指南》中指出，将提交方式的选择权交给作者，是因为作者更了解作品的写作动机、背景和投入，也应该有机会表达对作品处理方式的意愿。这也便于我们合理分配有限的审阅时间，投入更多资源完善那些花费较大努力创作的作品。
但是，两种方式没有必然的高下之分。我们建议作者根据作品是否首发、希望何时公开，以及是否愿意配合进一步修改等因素，合理选择提交方式。而根据《审阅规则》，如果编辑部有合理理由认为作者选择的提交方式不符合该提交方式的设置意图，可重新指定有关作品的提交方式（第 4.3 条）。
因应 AI 写作普及的特殊标准
《审阅规则》的另一项改动，是整合并修订了散见于上一版《创作手册》的特殊审阅标准，也就是适用于一部分包含特定内容文章的附加标准。其中，与时下投稿现状最为相关的，自然是关于 AI 生成内容的审阅标准（第 3.2 条）。
旧版《创作手册》已经对于 AI 生成内容的处理标准作了初步规定，编辑部也在之前阐述过我们如何看待「用 AI 写」和「写 AI」的文章。然而，过去一两年中，AI 仍在以极快的速度进化和普及，对我们的审阅工作也提出了新的挑战。在一个常见工作日中，我们收到的新作品可能数倍于以往，但其中至少七成（保守估计）的作品会有明显的 AI 参与痕迹，甚至是 AI「直出」。
因此，我们近来适当收紧了对于滥用 AI 行为的限制。如果投稿文章通篇使用 AI，一般会被直接退回而不予处理。如果新注册用户直接发布 AI 生成的低质量内容，更可能被直接停用账号而不予警告。
不过，我们也承认 AI 对于提高写作效率、鼓励更多人参与创作的有益作用。亦如我们过去阐述，写作的动机和态度，比所用的工具、方法更重要。以尊重读者、保证准确、如实披露为前提，我们并不介意 AI 辅助写作的文章出现在少数派。
修订后的《审阅规则》反映了这一开放态度。例如，考虑到 AI 的普及程度，《审阅规则》现在只禁止用 AI 生成作品的「实质部分」（第 3.2(2)(a) 段），即承载核心观点、论证逻辑、叙事细节及独特表达风格的连续性文本段落。因此，使用 AI 润色语句、完善衔接段落等常见及合理的用例，不在此限。
同时，考虑到现时 AI 产品及与 AI 交互方式的多样性，《审阅规则》现在只要求声明使用 AI 生成技术的名称、方式、目的及范围，不再要求说明提示词、修改过程等不易列举、界定，也难以实际执行的事项（第 3.2(2)(c) 段）。
在审阅文章和与作者互动的过程中，我们也意识到，AI 确实促成了一些写作经验较少的作者参与创作，并且特定题材的文章（例如应用自荐）具有一定的格式化特征，AI 创作对于信息量及表达效果等的损害较小。在这些情况下，仅因 AI 参与了实质创作就直接予以拒绝，也可能是武断的。
因此，修订后的《审阅规则》设置了一些例外情况，允许编辑部就个案放宽标准。具体而言，如果编辑部认为一件 AI 生成的作品的发布动机不是让作者本人或第三方「不诚实地」获益，并且可能让本站一般读者感兴趣，又不至于令人误会是完全原创；那么，即使这篇文章的「AI 味」很浓，或者作者没有准确声明 AI 辅助情况，编辑部也可以允许其保持发布（第 3.2(3) 款）。
其中，在考虑作者的动机是否「不诚实」时，编辑部通常考虑 (1) 作者是否真诚相信自己应该发布一篇文章，即使它是用 AI 生成的，以及 (2) 在明理的一般人看来，作者发布这篇文章的行为是否不诚实。
例如，如果用 AI 生成一篇单纯蹭热点、营销或洗稿的文章，显然作者自己明知该文章是违规的；如果用 AI 生成的文案来批量推广自己的应用，即使作者可能自以为这是正常的宣传推广，多数用户也容易感到这是无价值和打扰的。在此两种情况下，作者的动机都不可谓诚实，其炮制的 AI 作品也不能获得豁免。
相反，设想一名开发者因为顾虑自己表达较为生疏而使用 AI 代笔了一篇应用自荐文章，而从文章看来，该应用确实具有一定的质量和潜力，作者也尽力做了一些手动编辑和配图。那么，根据上述规则，这篇文章不会仅因为 AI 含量高而被退回。
除关乎 AI 内容的标准外，针对宣传内容（第 3.1 条）、专业意见（第 3.3 条）等其他特殊内容的规则也有所更新，作者可以按需参阅。
除《审阅规则》外，此次《创作手册》修订还有如下更新——
- 更新了《少数派风格指南》，使其格式更清楚，并根据少数派新的文章版式，更新题图尺寸要求；
- 更新了作者协议，使其与新增的审阅规则相衔接，并完善了作品使用授权、收益结算等方面的规定1；
- 增加了「更多参与方式」一节，介绍了发布评论、「一派」讨论，或投稿给常设栏目、会员内容等参与到少数派创作社区中的途径和奖励机制；
- 重写了介绍用户组别和权益、提交与审阅流程、稿酬标准与发放等事宜的章节，使其版式更易读、要求更透明；及
- 由于旧版《创作手册》使用的 MkDocs 已不再维护，将站点框架改为 Hugo。
与旧版一样，修订后的《创作手册》仍采用知识共享署名（CC BY）4.0 国际许可协议分发，欢迎自由地共享或演绎，只要在此过程中包含署名、不附加额外限制。

来杭州之后，我周末最常做的事就是和朋友散步。
钱塘江我们不是一天走完的，沿着江一段一段走，走到了富春江，大概有几十公里。湘湖来回走了十几次，西湖、附近的山也慢慢走熟了。走得多了，路上会冒出一个很普通的念头：要是散步的时候有点事情做，是不是会更好？
恰逢今年四月，小红书上忽然出现很多 Color Walk 的分享。出门前选一个颜色，路上只拍它。我跟朋友说，我们也可以这样拍。那时候我还没决定做 app，只是觉得这个 Color Walk 很有趣。
如果只是这一个点子，我未必会做成 app，但那段时间里，我会想起以前见过的散步提示卡：抽到一张，就去拍各种形状的窗子，或者风吹过草的痕迹。此前我也体验过一款在城市里寻宝的产品。这些想法让我觉得：这些都叠加在一个产品里，或许，十分有趣。
所以，我开始做了目前这个散步的 app——Mangata。
一些犹豫
第一版只做 Color Walk：开启散步，选一个颜色，路上拍照，结束散步，再把这次拍到的图分享出去。流程很短，也很快做出来了。
做着做着，我意识到一件事。小红书上的 Color Walk，核心并不在 walk，而在图片分享。大家真正要的，是一张能发的图。在哪里拍的、有没有出门，好像都不重要。好看的照片丢进去，用九宫格、杂志、色卡做成作品，这件事就成立了。
所以我犹豫了很久：Mangata 到底以散步为主，还是以分享为主？
这个问题我与 AI 讨论了一段时间，最后才确认了自己的想法。做分享更接近风口，也更挤。热度在出图这边，竞争也在这边，比的是模板、滤镜、谁更好看、谁更快更新。更危险的是做成中间态：看起来既能蹭到修图热度，又好像还在讲散步，产品会一点点滑成「把任意照片做成分享卡片」的工具。
我想做的是另一件事：颜色作为出门的理由，照片作为路上看见的证据，卡片作为这次散步的纪念。分享可以很好看，也可以借用当时 Color Walk 的传播语言，但 Mangata 必须从一次真实的行走里长出来，不能变成「把相册里任意照片做成作品」。
也是因为这样的想法，从第一个版本开始，Mangata 基本就没有打卡任务、卡路里记录、散步挑战等指标。
Mangata 第一版就按这个判断上线了。时间大概是六月。
迭代还是运营？
作为人生中第一款 app，我对产品是满意的，虽然是一个非常简单的工具产品，但我已经开始畅想后续版本里各种新的功能与体验。
不过，市场打醒了我。Color Walk 的风潮很快过了，Mangata 也没有什么用户量。
我也没有很多精力去花时间在社交媒体上分享我的产品。另外，每次我想分享 Mangata 的时候，我才发现散步路上拍到的照片，也并不总是好看，发到小红书上没有那么强的完成感；真正愿意「专门为了散步而出门」的人，可能本来就不多。
这让我意识到，散步 app 也是很多开发者曾经尝试的赛道，以前有人通过散步获取虚拟币来做增长，才让散步 app 变成了一个火爆的产品。
而海外社区也表明，虽然有人觉得在路上拍各种颜色会有趣，但参与这种讨论的人并不多。真正鼓励人散步的是减肥，是自己走过的步数、消耗的卡路里数。很多人并不是真正享受散步，只是从一个目的地走到另一个目的地而已。
所以，散步需要被倡导成一种生活方式？或者变得更有趣？答案在行动中，我需要继续实现自己对产品的构想。
散步搜打撤
我决定上线第二个功能——玩法卡，也就是引导用户观察自己散步过程中有趣的事物。我准备了一些卡片，大概效果如下：
用户这次出门就多一个很轻的理由——找一个重复出现的形状，找风曾经经过的证据，或者只看离你一米以内的世界。卡可以换，也可以不用。它不是任务，只是让你迈出第一步。
在散步过程中，你参与各种活动，最后以照片的形式记录下来。
这个功能也很简单，但让散步多了一种乐趣。我个人很喜欢，每次散步都会以玩法卡开始，只是偶尔，我并不能找到合适的卡片进行拍照，保存这次散步的旅程。不过，我很期待，我完成这次旅行后得到的天色卡。天色卡是我在今天的光里走过一趟，才长出来的东西。出发前它只是外面的天气、时间和光线；走完，路上的颜色进去了，它才变成我的 Rothko 风格卡片。
另外，做着做着，产品规划也慢慢定下来了。
因为我后续还会添加各种产品功能，但散步的过程是随机的，你可能想要追色，想要拍窗户这个物件，所以我需要有个产品逻辑能涵盖这个想法。
那段时间，我刚好刷到了游戏内容，知道了搜打撤玩法。我觉得散步就像一次搜打撤：进去之前带点东西，局内认真过一遍，出来时把带走的东西带回来。不是把 app 做成游戏，而是把一次散步拆成四个位置，后面加功能都问自己：它落在哪一段？
散步前：你以什么样的理由开启这一趟。颜色是一种，引导卡是一种，以后还可以有别的。理由只负责让你离开家。
散步过程中：你遇见了什么。一张图、一个念头，或者什么都没有，只是走过去了。
散步总结：这一趟到底带走了什么。走完先看总结，而不是先看一张能发的图。
散步分享：如果你觉得这次散步收获不错，那么从这次记录里导出纪念卡。分享是撤离之后的事，不是出发的入口。
也是从这四段开始，我才敢说：Mangata 真正想做的是把每次散步当作一次探索旅行。不管是目前已经上线的 Color Walk、玩法卡，还是未来上线的搭子、主题等其他玩法（可以期待下），都是为了让用户享受这次散步的旅程。
散步变成了工作方式
在做这个产品后，我最大的改变就是有了晚上散步的习惯。一是为了测试产品，二是为了减肥、锻炼身体。
然后在这个过程中，我意识到，散步已经成了我的工作方式。
散步开始后，我们可以拿出手机，使用微信输入法，通过 Cursor、Codex 等工具继续自己的 vibe coding 工作。我的 Mangata 的很多功能和代码修复都是在散步过程中完成的。
另外，我这篇 Mangata 的草稿也是在昨天的散步过程中诞生的。我原本在中秋期间就计划完成这篇内容，但坐在电脑前，我根本不知道我该如何写这篇文章，一直拖延到昨天。而昨天的散步中，我开始有了一些关于 Mangata 分享的想法，我通过微信输入法，将这些想法记录到了 Notion 上。
虽然这些想法都是语音转为文字的内容，可能有很多错误的表达，但那些碎片化的想法变成了上万字的草稿，我非常惊讶和开心。因为这一切都只是在散步旅程里的一小段时间内发生的，我根本没错过我这次散步之旅中的任何东西。
然后想法落到了纸上，后续的写作也有了方向，这才有了大家看到的这篇文章。
显然，散步已经改变了我的工作方式，我想我以后会给自己一个出门的理由去散步吧。
