Troubleshooting: private npm registry .npmrc
If this fails with an E404 for paperclipai (or similar) and you use a private npm registry (for example GitHub Packages) via a global ~/.npmrc, npx may be resolving paperclipai against that private registry instead of the public npm registry.
Diagnostic:
npm config get registry
Workaround (cross-platform; force the public npm registry for this command):
npx --registry https://registry.npmjs.org paperclipai onboard --yes
That quickstart path now defaults to trusted local loopback mode for the fastest first run. To start in authenticated/private mode instead, choose a bind preset explicitly:
paperclipai onboard --yes --bind lan
# or:
paperclipai onboard --yes --bind tailnet
If you already have Paperclip configured, rerunning onboard keeps the existing config in place. Use paperclipai configure to edit settings.

Univer is an open-source SDK for creating office applications inside your own product. It gives you the building blocks for spreadsheet, document, and presentation experiences without forcing you into a hosted app or a fixed UI.
Use Univer when you need to:
- Embed spreadsheet or document editing into a SaaS product, internal tool, BI workflow, or AI application.
- Run workbook/document processing on the server with the same architecture used in the browser.
- Compose only the features you need through plugins or start quickly with presets.
- Extend behavior through custom plugins, commands, services, UI components, and Facade APIs.
Univer is not a spreadsheet file viewer only. It is a framework for building your own productivity surface.
Across the Univer product family, Office tools share a runtime for storage and computation. Content can be composed and embedded across tools, with linked data and references updating together. People and AI agents can work in the same files. See the capability matrix for product coverage and Open Source and Pro for this repository's scope.

OpenBao is a software solution to manage, store, and distribute sensitive data including secrets, certificates, and keys. The OpenBao community intends to provide this software under an OSI-approved open-source license, led by a community run under open-governance principles.
A modern system requires access to a multitude of secrets: database credentials, API keys for external services, credentials for service-oriented architecture communication, etc. Understanding who is accessing what secrets is already very difficult and platform-specific. Adding on key rolling, secure storage, and detailed audit logs is almost impossible without a custom solution. This is where OpenBao steps in.
The key features of OpenBao are:
- 
Secure Secret Storage: Arbitrary key/value secrets can be stored in OpenBao. OpenBao encrypts these secrets prior to writing them to persistent storage, so gaining access to the raw storage isn't enough to access your secrets. OpenBao can write to disk, PostgreSQL, and more.
- 
Dynamic Secrets: OpenBao can generate secrets on-demand for some systems, such as AWS or SQL databases. For example, when an application needs to access an S3 bucket, it asks OpenBao for credentials, and OpenBao will generate an AWS keypair with valid permissions on demand. After creating these dynamic secrets, OpenBao will also automatically revoke them after the lease is up.
- 
Data Encryption: OpenBao can encrypt and decrypt data without storing it. This allows security teams to define encryption parameters and developers to store encrypted data in a location such as a SQL database without having to design their own encryption methods.
- 
Leasing and Renewal: All secrets in OpenBao have a lease associated with them. At the end of the lease, OpenBao will automatically revoke that secret. Clients are able to renew leases via built-in renew APIs.
- 
Revocation: OpenBao has built-in support for secret revocation. OpenBao can revoke not only single secrets, but a tree of secrets, for example, all secrets read by a specific user, or all secrets of a particular type. Revocation assists in key rolling as well as locking down systems in the case of an intrusion.

问答中途，有人问起 Jobs 自己是否使用官方边框保护套 Bumper，台上三位高管随即掏出并高举自己「裸奔」的 iPhone 4 以示回应。
「天线门」是苹果 2010 年遭遇的重大产品危机。iPhone 4 首次采用外露金属边框作为天线，但在发售后不久，大量用户反映用手握住机身左下角缝隙（即所谓的「死亡之握」）时，会导致信号急剧衰减甚至断线；苹果一时面临集体诉讼与巨大的舆论压力。
最终，苹果召开紧急发布会，将信号衰减归因于智能手机行业的共有难题，并声称信号格数计算公式长期存在错误，将通过软件更新修复，同时宣布向所有 iPhone 4 用户免费提供 Bumper 并允许全额退款。
F-Droid 2.0 发布
9 月 24 日，开源 Android 应用商店 F-Droid 发布 2.0 版。官方称其为该项目近十年来规模最大的一次重构迭代，历经 14 个测试版本的打磨，旨在摆脱过往界面陈旧、安装受限等痛点，为用户提供更现代化、更接近官方应用商店的开源软件获取体验。
在底层架构与交互设计上，F-Droid 2.0 采用 Kotlin 与 Jetpack Compose 工具包全面重写，契合现代 Material Design 规范。得益于欧盟《数字市场法案》（DMA）等反垄断举措推动的系统接口开放，新版引入了统一安装程序与预审批 API，无需像以往那样依赖特权扩展组件（FPE），即可在支持的系统上实现后台自动更新与静默安装。
在应用发现与检索方面，F-Droid 2.0 的主导航栏精简为「发现」「搜索」和「我的应用」三大板块，并细化了多级分类体系与多条件过滤选项。针对此前跨语言检索体验不佳的问题，新版重构了搜索内核，提升了对中日韩（CJK）文字的检索支持，允许用户通过应用描述、分类标签及本地化译文直接查找所需软件。
此外，新版本默认启用后台更新检查机制，对代理配置与应用图标伪装等隐私功能进行了规范化调整。因底层技术升级，F-Droid 2.0 正式放弃对 Android 6 的支持，最低系统要求提升至 Android 7。该版本将于未来数周内分批向全球用户推送。

Excel 单元格将支持数组
9 月 24 日，微软发布博客文章，宣布 Excel 的单元格将可以原生保存列表及数组，而不仅限于一个标量值。诸如标签、多选问卷答案、时间序列等数据，都不再需要先作为字符串输入，再用文本函数拆解。
通过列表功能，用户可以在一个单元格里存储多个彼此独立的值。例如 apple, banana, pear 将被视为由三个值构成的列表，而不是整段文本。列表中的项目可以单独增删、编辑和筛选。通过公式引用含列表的单元格，可以将其项目拆分到多个单元格。
进一步地，Excel 将允许数组本身成为一个单元格的值。例如，={{1;2;3}} 会把 [1, 2, 3] 这个数组整体保存在一个单元格中。此外，数组中的元素还可以是数组，例如 ={{1,2,3};{4,5,6}}。与此配套，Excel 增加了 FLATTEN（展开嵌套数组）、HAS（判断数组中是否存在某个值）等函数。
上述功能目前正在 Beta Channel 中测试，尚存在一定的兼容性问题，例如数据透视表、Power Query 和查找替换目前还不能正常理解数组值。嵌套数组功能还需要将 Excel 文件升级到同步推出的兼容性版本 3，这可能改变部分既有公式的计算结果。

鬼武者 剑之道 / 鬼武者 Way of the Sword
《鬼武者》系列的惊艳复活。
- 2026.09.04 / PS5、XS X|S、NS2、PC
Capcom 老牌 IP 二十年来首推新作，系列上一正作已经要追溯到 2006 年的《新 鬼武者 DAWN OF DREAMS》，制作人门胁章人、游戏总监二瓶贤（首次任该职）已在《战国 BASARA》（戦国 BASARA）、《怪物猎人》（モンスターハンター）等社内的动作 IP 下效力多年。在接受 GAME Watch 采访时，门胁解释了系列沉寂至今的原因：公司内部一直想做《鬼武者》新作，但总有更优先的项目、做一部《鬼武者》要的人又太多，随着自研的 RE 引擎逐渐成熟，终于在 2020 年初凑齐了核心开发组成员；本作没有沿用正作的编号、没有直接继承旧作的世界观，主创希望即使不熟悉《鬼武者》系列的玩家也能无负担上手《剑之道》。
本作的故事发生在江户时代初的京都，不是开放世界、也不是类魂游戏，流程以线性关卡为主，但京都城内很多地点都被复刻、供自由探索，实景取材获得了京都市政府的协助。主角宫本武藏，当时还没有「剑豪」的称号、只是个二十多岁的毛头小子，如果没有「幻魔」这种异世界怪物的到来，他的生活可能就是四处找架打、磨砺武艺、与宿敌佐佐木岩流的切磋，但幻魔的袭扰改变了一切，武藏无意中戴上了「鬼之笼手」，开始了与幻魔对抗的冒险旅程。
「鬼之笼手」作为《鬼武者》系列的最核心设定之一，拥有举足轻重的分量：故事方面，它让原处于「人界」的佩戴者能够跨入「幻魔界」，《剑之道》还加入了其中寄宿有灵魂、与武藏聊得火热的桥段；动作机制方面，击败幻魔、吸收从敌人身上被打落的魂魄、回血或积累技能条、施放强大的特殊技能，这些元素都绑定在「鬼之笼手」上。
本作带回了《鬼武者》招牌的「一闪」机制、且获得了现代化改造：「一闪」指玩家在敌人攻击命中前瞬间按键、出刀反杀，本作还新增了一个「精力/平衡」条，玩家的主动进攻、招架都能削减其数值，条被打空就能触发硬直、更容易地使出强力的「崩之一闪」。《剑之道》一周目提供了「剑戟」「活剧」两种难度模式，你可以在免费 Demo 里直观体会差异，笔者感觉「活剧」在连招输入门槛降低的同时、克制了那种难度骤降的泄气感。对此，门胁在 Fami 通 的访谈中也有提及，刻意回避了「简单」这类这种难度称呼，并指示开发团队不要让玩家死得心态崩掉，「让人想摔手柄、发誓再也不玩的死法，对不起买游戏的人」。
二瓶在访谈中透露，本作的出发点是「武士之帅到底为何」，他的答案是——在泥和血里拼命挣扎、为了赢可以使用任何手段，如此也确立了武藏作为主角。特别值得一提的是，Capcom 基于已故演员三船敏郎的形象创建了武藏的面部模型，门胁称三船是本作的「绝对条件」之一，与三船制作公司谈了两年才最终签订合约。三船先后与导演黑泽明合作了《罗生门》（羅生門）、《七武士》（七人の侍）等 16 部电影，1954 年主演了电影《宫本武藏》，堪称日本影史最具代表性的演员之一，塑造了大量影响深远的浪人形象。
笔者是《鬼武者》系列的忠实粉丝，非常着迷于各代作品的美术风格，热爱以「一闪」为核心的动作体验，但「一闪」（以及只在速通视频里见过的「连闪」神技）的爽快、极大的愉悦感，终究建立在炉火纯青的操作技术上，我自己确实是搞不定，所以我一直有一个关于《鬼武者》玩起来十分美好的想象。单就战斗的体验而言，在玩了《剑之道》的 Demo 以后，我觉得它几乎满足了我的想象：「一闪」仍然依赖技巧，但识别、抓住输入窗口的难度没那么高了，成功以后还是那么爽快，开发团队还细致打磨了角色的动、静姿态（电击 Online 的访谈中有提到背后的工作），使整个战斗过程赏心悦目。
当然了，根据 VGC 和 GamesRadar+ 等媒体的分享，他们认为本作的战斗固然出色，但流程中段半开放设计的效果和必要性、Boss 战的重复性等，也是不容忽视的扣分点，但至少对我来说，在《剑之道》里爽玩更多战斗，那是太有吸引力了。
火焰纹章 万缕千丝 / ファイアーエムブレム 万紫千紅
来自任天堂第一方战棋玩法的经典系列，新作延续了《风花雪月》的世界观。
- 2026.09.17 / NS2
《火焰纹章》系列最早由 Intelligent Systems 开发、任天堂发行，1990 年，加贺昭三主导的初代《火焰纹章 暗黑龙与光之剑》（ファイアーエムブレム 暗黒竜と光の剣）登陆 FC，奠定了本系列延用至今的整体框架：宏大的国家战争背景下，玩家招募、指挥、养成一大批鲜活角色，具体到了战局中，玩家将在划为网格的地图上进行回合制战棋作战，发挥不同兵种之间的相互克制关系、角色独特技能的威力；一旦在战斗中倒下，角色就会永久离队（续作大多允许关掉、或者玩家也可以更方便地 S/L）。
本作与 2019 年的《火焰纹章 风花雪月》（ファイアーエムブレム 風花雪月）处在同一个世界，《风花雪月》引入了名为「芙朵拉大陆」的游戏舞台，玩家扮演的主角是士官学校的老师，待到流程中的分叉点时，须在三个学级势力中选一个推进、走向结果完全对立的不同结局。
《万缕千丝》和《风花雪月》的核心掌舵者一致，都是 Intelligent Systems 方的草木原俊行、横田弦纪两位总监。横田在任天堂发布的开发者访谈中提到，《火纹》一直是任天堂、Intelligent Systems 共同开发，《风花雪月》时他提议让开发了《火焰纹章无双》（ファイアーエムブレム無双）的光荣特库摩加入、承担基础开发，《风花雪月》最终斩获了系列最高销量；草木原表示，团队一直在烦恼「怎样才能做出超越《风花雪月》的作品」，但他们最终搞清楚了想要表达的主题，希望没有光荣特库摩参与的《万缕千丝》有不一样的体验。
《万缕千丝》故事的发生地为芙朵拉南方的达古扎大陆，定位为新作而非续篇，不要求先游玩《风花雪月》。本作的故事架构从走向互斥的岔路、变成了「条条大路通罗马」：出身、年龄、境遇不同的角色们心怀梦想、汇聚到达古扎首都，参加一场决斗大会、胜者被允许向神许愿；游戏有四位主角、四条路线，大部分时候可以随时切换，所有路线最后会汇聚到同样的终点，讲述不同的人的理念如何交织、最终推动历史车轮前进的一段史诗。
本作的玩法当然还是万变不离其宗的回合制战棋，笔者还挺喜欢战棋的，说句题外话——我游戏时间最长的《鬼武者》游戏甚至是 GBA 上的《鬼武者 战略版》（鬼武者タクティクス）。本作继承了《风花雪月》很多有意思的设定：角色可以使用战技，武器有耐久度，只要技能等级达标、就能转职成任意兵种。战斗之外，《万缕千丝》的探索自由度更高了，玩家可以在首都和世界地图上自由移动，招募同伴、培养角色、探索迷宫，跳过这些、直接推主线也没问题。

- [宜家 Matter 智能家居终于要来了？在中国市场它将如何破局](https://sspai.com/post/114958) <sub>09-26 14:00</sub>

距离宜家首批 Matter 智能家居产品在海外上市已有大半年的时间，而中国市场则是许久未有消息。直到今年年中，多款宜家智能新品陆续出现在国家 CCC 认证数据库中，我们才得知：这批主打高性价比、支持新一代智能家居协议的宜家产品，距离正式上架中国市场已经为时不远了。
作为全球家居零售巨头，宜家（IKEA）在智能家居领域的动作一直显得独特而克制。它不像传统科技公司那样疯狂堆砌参数或频出概念，而是始终围绕「家居」这一核心场景演进。从早期的 Zigbee 布局到如今全线拥抱 Matter，宜家究竟在打什么算盘？面对生态高度割裂且独特的中国市场，它又将如何落地破局？
在与宜家全球产品线负责人 David Granath 以及产品开发 Stjepan Begic 的对话中，我们找到了答案。
作者注：采访原文为英文，本文内容引用时有翻译和编辑。
从 Zigbee 到 Matter：宜家智能家居的「平民化」演进
很多人可能不知道，宜家其实已经在智能家居领域深耕了多年。在此前很长一段时间里，宜家在售的智能产品大部分都基于 Zigbee 协议——一种通用、低功耗且支持网状组网的无线通信方案。
然而，宜家对待技术的态度与传统科技大厂商大相径庭。后者往往希望把用户死死锁在自己的网关和 App 里。标准的第三方，比如 Philips Hue 的大部分 Zigbee 设备也能顺利接入网关。
而且宜家为了极致的易用性，在大部分设备中都保留了 Touchlink 直连能力。这意味着一位对智能家居一无所知的普通消费者，哪怕完全不购买网关，只要买回一只宜家灯泡和一只无线遥控器，按住遥控器对准灯泡几秒钟，就能实现「遥控器调光」或「人体传感器联动开灯」等高频场景。正如 David Granath 所强调的，宜家始终从家居场景出发，智能不应该以增加用户的理解和购买成本为代价。
当然，如果你想获得更完整的智能体验——比如手机远程控制、定时自动化，或者将设备接入诸如 Apple Home 的生态平台，网关依然是不可或缺的枢纽。为此，宜家先后推出了初代 TRÅDFRI 网关以及新一代的 DIRIGERA 智能网关。 他们不仅承担着集中管理宜家自家产品的重任，还作为 Bridge（桥接器），将宜家的灯具、传感器无缝推送到 Apple Home、Google Home 和 Amazon Alexa 等主流生态中。
但 Zigbee 时代终究存在生态壁垒，不同「风味」的非标准 Zigbee 设备比比皆是。随着跨平台通用标准 Matter 与 Thread 协议的日益成熟，宜家这个收避锋芒的巨头终于放出了大招：正式宣布全面拥抱 Matter 标准，并一口气推出了 21 款极具性价比的 Matter 新品，涵盖了智能灯泡、无线开关、各类传感器和智能插座。近期的新品还包括欧版更新的温控阀与厨房橱柜驱动器。
David Granath 表示，未来宜家将逐步把现有的智能产品线全面迁移到这个通用的智能家居标准上。这不仅意味着产品协议的更换，更意味着宜家智能家居正式迈入了「无缝互联」的新时代。
易用性背后的体验与磨合
如果你体验过宜家的 Matter 新品，就会发现它延续了宜家一贯以来的「平民化设计」与超低的使用门槛。
从包装盒上的第一步指引、内置的纸质图解说明书，到 App 里的引导交互，宜家都尽全力让设备配置变得像组装一套 BILLY 书架一样简单。从 Zigbee 升级到 Matter，最直观的体验提升在于配网过程：用户不再需要像过去那样，按照繁琐的节奏连续开关电源 6 次来重置灯泡，只需拿起手机扫描设备本体或包装上的 QR 码，设备就能瞬间被识别并加入网络。
而在宜家 Home Smart App 的功能设计上，David Granath 解释道，宜家也表现得相当克制。面对「自适应光」或「睡眠唤醒」这类底层逻辑相当复杂的自动化功能，宜家并没有向用户展示密密麻麻的参数调节选项，而是优先呈现一套经过精细调校的默认最佳设定。这种将复杂留给后台、将简单留给前端的设计，极大降低了普通家庭的使用门槛。
不过，作为首批吃螃蟹的巨头，宜家 Matter 产品在刚上市的前几个月里，也经历了一段不折不扣的阵痛期。设备掉线、配网失败、响应延迟等问题在早期用户反馈中屡见不鲜。
David Granath 坦言，这背后的根本原因在于合作模式的剧烈变革。在过去的 Zigbee 时代，宜家拥有「设备 - 网关 - 软件」的端到端全链路掌控力，一旦出现 Bug，自己的工程师团队在内部闭门排查即可解决；但在 Matter 时代，宜家变成了庞大互联生态中的一个节点，设备能否稳定运行，不仅取决于宜家本身的固件，还高度依赖于第三方生态系统、Thread Group 底层网络乃至连接标准联盟（CSA）标准本身。
为了解决这些体验痛点，宜家在今年上半年与各大主流生态厂商开展了频繁的物理联合调试（Joint Debugging）。多方工程师坐在一起，逐行分析日志、抓包定位问题。经过数轮固件迭代与跨厂商协作修复后，如今宜家 Matter 设备在主流生态中的稳定性和响应速度已经达到了非常可观的日常可用水准。
就在这篇文章完稿时，宜家又为旗下的 Matter 产品推送了更新的测试固件，带来新的 Matter 和 Thread 标准版本，问题修复和稳定性提升。
复杂地区背景下，宜家中国的破局之道
在谈到中国市场的落地规划时，David Granath 给出的核心词是「审慎」与「本土相关性」。中国智能家居市场有着极其特殊的地区背景与竞争格局，这使得全球标准的落地变得异常复杂。
国内科技巨头如小米和华为，各自坐拥庞大的封闭或半封闭生态网络，出于商业闭环与生态壁垒的考量，对第三方原生 Matter 设备的支持始终显得克制而保守；手机厂商如 OPPO 和 vivo，虽然拥有庞大的手机终端用户基数，却缺乏像智能音箱、中央网关这样的家庭中枢硬件与 Thread 边界路由器；而原本在全球市场作为 Matter 中流砥柱的三星 SmartThings，则早已退出了中国市场的核心舞台。这一系列复杂的本土现状，使得 Apple Home 几乎成为了当前中国市场上唯一全力支持并扛起 Matter 大旗的主流生态力量。
然而，光靠 Apple 生态，显然难以支撑 Matter 在中国的全面普及。由于 Apple TV 和 HomePod 在国内家庭中的渗透率相对有限，绝大部分中国家庭根本不具备现成的 Thread 组网能力。许多国内的 Apple Home 极客玩家甚至因为国内缺少高性价比原生 Matter 传感器，不惜跨国代购宜家的海外新品。
正因如此，David Granath 强调，如果一股脑地将纯 Thread 协议的产品推向中国市场，消费者买回去很可能面临无网络可连的窘境。
为此，宜家在中国市场选择了稳扎稳打的导入策略。首批通过 CCC 认证并准备引入的产品，优先选择了那些出盒即附带 Touchlink 遥控器的套装设备。这样一来，即便用户的家庭环境中完全没有任何 Thread 组网基础设施，买回家也能直接当作高品质的无线遥控灯具使用，完美避开了网络门槛。
在价格与成本控制上，宜家也展现出了极强的竞争力。许多科技品牌推出的 Matter 设备价格动辄翻倍，而宜家的 Matter 产品却能做到与传统 Zigbee 产品持平甚至更低。David Granath 揭示了这背后的秘诀：宜家庞大的全球出货量能够将研发与认证等固定成本稀释到极低的水平，同时内部专门的成本控制团队会精细审查每一个零部件与生产环节，将省下来的成本转化为低价让利给消费者。
关于未来的本土生态合作，早年宜家在中国曾与小米达成过深度合作，将部分灯具接入米家生态，因为当时小米是中国本土最普及、最相关的智能家居平台。随着 Matter 标准的兴起，David Granath 表示宜家正在重新评估本土标准与生态的发展走向，并继续保持与本地厂商的对话，寻求最契合中国消费者的落地方式。
民主设计与开源贡献：背后的硬件与标准考量
回顾宜家智能家居的发展历程，你会发现它自始至终都在贯彻宜家最核心的「民主设计（Democratic Design）」理念——即在美观、功能、质量、可持续性和低价格这五个维度之间寻找最佳平衡。
对于这一理念在硬件研发上的落地，宜家产品开发工程师 Stjepan Begic 补充了一个极具代表性的例子：宜家新一代智能传感器全面放弃了传统的纽扣电池，转而采用内置可充电电池设计。虽然这在一定程度上牺牲了部分产品的体积，但却换来了更长的续航表现、更出色的电池性能，以及对环境更友好的可持续性——同时它还能完美适配宜家商场里售价极其亲民的 Ladda 镍氢充电电池与充电器。
此外，当谈到与开源社区和行业联盟的关系时，Stjepan Begic 表示，宜家并不是单纯的标准使用者，只要宜家团队研发出了有价值的新功能或新协议规范，他们都会积极推回并贡献给开源社区及 CSA 联盟。例如目前宜家正深度参与联盟内关于 Matter 音响的规范制定，推动整个智能音频行业的标准化发展。
而对于极客群体热衷的改装与捣鼓宜家硬件（IKEA Hacks），David Granath 与 Stjepan Begic 均持非常包容且喜闻乐见的态度。David Granath 表示，只要改造是在安全的前提下进行，团队乐于看到大家发掘出宜家产品的各种创意新玩法。
宜家能在中国交出怎样的成绩单？
从 Zigbee 到 Matter，宜家真正想延续的或许并不是某一种协议，而是它一直以来对智能家居的理解：技术应该藏在产品背后，而不是成为用户需要首先解决的问题。
随着首批低价 Matter 产品进入中国市场，这套思路也将迎来一次更直接的检验。出色的工业设计和家居整合能力、尽可能简单的使用体验，接近米家产品的价格，却又能原生直连 Apple Home，并通过 Matter 接入更开放的生态，这些过去很少同时出现在同一款产品上的特点，如今开始被宜家放到了一起。
但国内智能家居市场从来不只比产品本身。本土的成熟生态已经建立起庞大的设备规模与用户习惯，Matter 的基础设施和本土生态支持也仍在完善。宜家能否把海外已经验证的一套产品逻辑真正复制到中国，又有多少消费者会为了设计、价格和开放生态改变既有选择，都还没有答案。
当这批产品真正摆上宜家中国商场的货架后，一个更有意思的问题才刚刚开始：当宜家的设计和易用性，遇上米家级别的价格、Apple Home 的直连能力，以及 Matter 所代表的开放生态，它最终能在中国智能家居市场交出怎样的一份成绩单？

There's an optical illusion known by names like the "lunar terminator paradox". This has much discussion and descriptions online, but none made sense in my head, so I wrote this program to figure out what was going on. The paradox:
- The moon is illuminated by the sun
- After sunset, the sun is below, so we would expect the illuminated portion of the moon to point down, towards where the sun is
- This isn't what always happens!
I was camping in the mountains with a friend recently. We were looking up at the sky, just after the sun has set. The moon was clearly pointing up.
After playing with this program, I have clarity: we're looking up at the moon from below. The most pathological case is a full moon. Let's say the moon is on the horizon: elevation=0. If we're looking at this low moon, and the moon is full, the sun is directly behind us. The moon is fully illuminated, and we see 100% of the moon disc lit up.
Now, what happens if the moon is not at the horizon, but higher up at the sky? Effectively, the sun is infinitely far away, so the same part of the moon is lit up. But we're now looking at the moon from below, and we would see some of the dark side on the bottom edge. I.e. the moon appears bright at the top, but has a dark slice missing at the bottom: it points up! Even at sunset.
This is the most clearly weird case. A half-moon has no paradoxical behavior, and the more full the moon, the more clearly we can observe the bright moon pointing up despite the sun being down.
I produce two plots. At 3/4-full moon at sunset we look at the moon as it rises from the horizon all the way up to the zenith:
If the moon is at the horizon (elevation = 0), we see the expected 3/4-lit disc. As the moon rises, we see more and more of its bottom, and thus more and more dark areas show up: It clearly points up at sunset!
We can also move the sun around. Let's say the moon is 60deg up; let's move the sun from new-moon to a full-moon:
In the darkest configuration, we can still see a lit crescent on the bottom: the illumination is all on the opposite side, but we can see a slice of the illuminated back side. As the sun swings around, we see more and more of the moon. At azimuth = 90deg, we have a half-lit moon. Past that, more and more of the moon is visible, always pointing up.

Bringing this site to Tor as a hidden service.
This site is now reachable over Tor as a hidden service, at a .onion
address that resolves only inside the Tor network.1 1
Open it in the
Tor Browser. There is no certificate authority, no DNS, and no exposed
IP—the address is derived directly from a public key, and the
connection is end-to-end encrypted by Tor itself. 
Tor relays and
encrypts your traffic as it passes through thousands of volunteer-run
servers, so that no single party can link who you are to what you are
doing; a hidden service extends that anonymity to the server itself.
It’s built by the nonprofit Tor Project, which advances human rights and freedoms through free software and open networks, so that anyone can use the internet free from tracking, surveillance, and censorship. The network only works because people use it, so consider supporting them or running a relay—your contribution helps millions stay safe and private online every day.
The hidden service §
Install Tor and point a hidden service at a local port. Edit
/etc/tor/torrc
HiddenServiceDir /var/lib/tor/blog/
HiddenServicePort 80 127.0.0.1:8080
The directory must be a dedicated, Tor-owned path—not your web
root.2 2
Tor stores the service’s private key and hostname file here
and insists on owning it (chmod 700, user debian-tor). Point it at
your site files and Tor refuses to start. 
Restart Tor and read the
address it generates
$ sudo systemctl restart tor@default
$ sudo cat /var/lib/tor/blog/hostname
dhevt6e4rtgbtr3jh53xrpwmgtilkah6nyjujocsspssrsexc7omxhid.onion
Serving the site §
Tor forwards the onion’s port 80 to 127.0.0.1:8080, so the web server
just needs to listen there. Add an nginx server block for it—no TLS,
no HTTP/2, no QUIC, since Tor speaks plain TCP and provides its own
encryption.
server {
  listen 127.0.0.1:8080;
  server_name dhevt6e4rtgbtr3jh53xrpwmgtilkah6nyjujocsspssrsexc7omxhid.onion;
  root /srv/tor.david.alvarezrosa.com;
  index index.html;
  error_page 404 /404/index.html;
  location / {
    try_files $uri $uri/ =404;
  }
}
Reload nginx and the site is live on Tor.

A static site bakes its base URL into absolute links, so a clearnet build would point visitors back to the clearnet domain even when served over Tor. The fix is to build a second copy with the onion as its base URL
$ hugo --minify --baseURL="http://dhevt6e4rtgbtr3jh53xrpwmgtilkah6nyjujocsspssrsexc7omxhid.onion/"

DSPy makes each call to a model a declared, typed function that you can measure and improve. On the BEAM, an agent is a process: it keeps its own state, receives messages, and runs under a supervisor alongside the rest of your application. Don't couple your Go code to GitHub
Sep 27, 2026
One of the good features of Go is that you namespace your code with the location to fetch the code. This means if you host your Go code at http://github.com/thetrueares/boneclone then you have the line import “github.com/thetrueares/boneclone” and Go will fetch it using git. This makes it super easy to know where to go to report bugs for open source libraries and really easy to fetch and distribute go libraries without a centralised package management system. For many, it’s literally the location of the git hosting, but this has some downsides, and you should use your own custom domain, and I’ll explain why.
Problem
The main problem with using your git hosting location is that your code is now coupled to a hosting provider. That is, if you move your git hosting to GitLab then you have to change your code! Otherwise, you’ll be fetching the old verison. This can result in you being unable to change git hosting provider because the amount of overhead in switching. So you literally end up with your code coupled to GitHub. Which sounds completely nuts, but it’s something that is pretty much defacto in the Go community.
I’ve seen this problem become such a huge issue for a company that were using GitLab, GitHub, and Azure Devops at the sametime because changing the location of the code was such a large task for them and they didn’t “have time” that it was easier for them to operate on three platforms. And is why I built Boneclone to handle skeleton code replication across multiple git hosting platforms at the same time. So this problem literally cost the company money since they had to pay for three hosting services at the same time.
Solution
The solution is to use custom domains such as go.iain.rocks, go.uber.org, go.mongodb.org, etc. This allows you to just change where those domains point to. For example, go.iain.rocks/boneclone points to github.com/thetrueares/boneclone and if I move to GitLab nothing will change for the end users the install command is the same.
In my opinion, every commerical software development team using Go should be using custom domains for namespacing their internal libraries and packages. As it’s an easy way to avoid any pointless coupling.

New studies pour cold water on a prominent rejuvenation idea.
Around this time last year I was attending an aging conference in Manchester, listening to a talk about fly aging, when my phone started pinging. News outlets were reporting that a hot mic had caught Russia’s and China’s leaders discussing the possibility of living forever.
“With the developments of biotechnology, human organs can be continuously transplanted, and people can live younger and younger, and even achieve immortality,” Russia’s Vladimir Putin reportedly told China’s Xi Jinping.
He seems to have been referring to the “replacement” theory of longevity, which has been supported by multiple experiments that involved physically stitching young mice to old ones. Something about the young blood rejuvenated the old mice. Perhaps young organs could rejuvenate world leaders in their 70s, too.
Unfortunately for Putin, new research pours a little cold water on this idea. Studies on transplanted hearts in both mice and humans suggest that new hearts soon adopt the biological age of the recipient, no matter how young they were to begin with. The finding could be important for transplantation, but it also highlights just how complex aging—and rejuvenation—are.
Jesse Poganik at Brigham and Women’s Hospital in Boston is one of the many scientists trying to understand exactly what it is about the bodies of young mice that rejuvenates old ones. Plenty of research has focused on seeking the secrets of youth in young blood. But what if it’s something about young organs instead?
To find out, he and his colleagues performed a set of heart transplants in mice. In humans, heart transplants typically involve removing a damaged or injured heart and replacing it with another from a donor who is usually much younger than the recipient. (When Poganik assessed hospital records, he found that most recipients were about 20 years older than their donors.)
The mouse transplants were different: Mice received a second heart, implanted in the neck—a procedure that’s slightly simpler and allows scientists to compare the new hearts with the existing ones. In some cases, young adult mice were given a heart from a middle-aged donor. In others, middle-aged mice got young hearts.
The team used a trio of “aging clocks”—molecular tools used to estimate the biological ages of tissues and whole organisms—to assess whether the additional hearts affected the mice in any way. These clocks were good at predicting the chronological age of mice that didn’t get new hearts.
Poganik says he was expecting to see a reciprocal effect, and that young hearts might benefit older animals, for example. In previous work by other members of his team, young mice that got old hearts experienced a buildup of senescent cells in their other organs. These cells are thought to contribute to the aging process, suggesting that receiving an old organ might prematurely age an animal.
But that’s not what he found. When he and his colleagues analyzed the transplanted hearts between four and six months after surgery, they found that the hearts seemed to have adopted the biological age of the recipients. Young hearts got older, and old hearts got younger. “The environment of the transplanted organ really dictates how it seems to behave biologically,” he says. The findings were published online at bioRxiv last week.
The team also looked at each mouse’s blood and other organs—including its original heart—and were surprised to find that they seemed to be unaffected by the presence of the new heart, despite the age of its donor.
The finding was backed up by data from human heart transplants. People who receive a donor heart must typically undergo a series of heart biopsies after surgery. The tiny pieces of heart tissue collected from people who had heart transplants at Brigham and Women’s have been stored for decades. And when Poganik and his colleagues tested their biological ages with the aging clocks, they found a similar pattern: No matter the age of the donor, a new heart quickly adopts the biological age of the person who received it.
It’s not clear why this is, but João Pedro de Magalhães, who studies aging at the University of Birmingham in the UK and was not involved in the study, thinks it might have something to do with the recipient’s immune system. Perhaps immune cells circulating in the blood might affect markers of aging in the new organ, he says.
Perhaps the potential rejuvenating effects of a young heart end up being diluted by all the other aged components of an older body, Poganik suggests. Or maybe a single organ just isn’t enough to see an effect.
Poganik hopes his finding will encourage surgeons to consider using hearts from older donors, many of which are discarded on the assumption they won’t function as well. (Machines used to preserve organs before transplantation are changing that already—and Poganik has worked on another study showing that these devices seem to rejuvenate donor livers to some extent.)
But the study also highlights just how complicated aging is. If organs seem to be getting older by one measure but not by another, how can we get a full picture of the biological age of an organ, or a person?
This complexity means that scientists are not likely to discover a true way to completely reverse aging, says Poganik. “That would mean that every aspect of aging has to go back in time,” he says. Reversing DNA damage, structural damage, and all the other degradations that are part of the aging package, across all our various cells and tissues, presents an enormous challenge.
“There are aspects of biological age that are probably reversible, and there are aspects that are probably not,” he says. Sorry, Putin.
