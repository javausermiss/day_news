Browser automation for AI agents: open pages, read them as an accessibility tree, and act on elements from the shell.
agent-browser is a native Rust CLI that gives an AI agent a browser it can drive one command at a time. snapshot returns the page as compact text with a ref such as @e1 for each element. The agent acts on a ref, reads the page again to check the result, and repeats. The browser stays open between commands, so each step is one short shell call.
npm install -g agent-browser
agent-browser install           # download Chrome for Testing (first time only)
- Homebrew: brew install agent-browser, then agent-browser install.
- Linux: agent-browser install --with-deps also installs the browser's system libraries.
- No install: npx agent-browser open example.com.
Project installs, building from source, upgrade, and doctor are covered in Installation.
agent-browser open example.com
agent-browser snapshot -i       # interactive elements, each with a ref
agent-browser click @e1         # act on a ref from that snapshot
agent-browser get url           # check the result
agent-browser close
The snapshot for example.com:
- link "Learn more" [ref=e1]
- Refs describe the page at the time of the snapshot. After navigation or a DOM change, take a new snapshot before using refs again.
- CSS selectors, text, XPath, and semantic locators also work, for example agent-browser find role button click --name "Submit". See Selectors.
- A click fails, instead of reporting success, when the target is hidden, disabled, outside the viewport, or covered by another element such as a consent banner. Dismiss the covering element, take a new snapshot, and retry.
The full walkthrough is in the quick start.
The CLI sends each command to a background daemon that starts on the first command and controls the browser over the Chrome DevTools Protocol. Each --session gets its own daemon and browser. By default, the daemon closes a headless browser and exits after one hour without commands, saving state first when session persistence is configured.
Chrome for Testing is the default browser. You can also attach to a running Chrome with --cdp or --auto-connect (CDP mode), select the Lightpanda or Obscura engine with --engine, drive Mobile Safari in the iOS Simulator, or use a cloud browser provider such as Browserbase, Browserless, Browser Use, Kernel, or AgentCore.
The CLI ships skills that match its version:
agent-browser skills get core                 # the core loop, refs, waiting, and common workflows
agent-browser skills get core --ref commands  # one reference, such as the full command list
agent-browser skills get core --full          # adds the full command reference and templates
agent-browser skills list                     # specialized skills: electron, slack, dogfood, and more
Install the discovery skill into an agent harness from skills.sh:
npx skills add vercel-labs/agent-browser
The installed skill is a thin stub that tells the agent to load agent-browser skills get core, so its instructions always match the installed CLI. Or add this to your AGENTS.md:
Use `agent-browser` for browser automation. Before the first use, run
`agent-browser skills get core` and follow it.
For MCP clients, agent-browser mcp starts an MCP server over stdio. See MCP server.
Run agent-browser --help for the full list, or agent-browser <command> --help for one command.
Flags, environment variables, and agent-browser.json are documented in Configuration.
Native binaries ship for macOS (ARM64, x64), Linux (ARM64, x64, glibc and musl), and Windows (x64). The npm package picks the right binary for the host.
Building from source requires Node.js 24 or later, pnpm 11 or later, and Rust:
pnpm install
pnpm build:source               # builds the dashboard and the native CLI
pnpm link --global
agent-browser install
Run the Rust checks from cli/:
cargo fmt -- --check
cargo clippy
cargo test
cargo test e2e -- --ignored --test-threads=1   # launches real headless Chrome

A coding-agent skill that turns your agent into a security auditor. It orchestrates isolated agents through reconnaissance, coverage-led hunting, candidate validation, structured output, independent record verification, and target-neutral reporting.
This is the skill that seeded Cloudflare's vulnerability discovery harness, described in Build your own vulnerability harness. The harness grew into a multi-stage, fleet-wide system; this skill is the single-repo starting point it evolved from.
The skill runs a structured audit in six phases:
- Reconnaissance -- map architecture, trust boundaries, input surfaces, prior evidence, and deterministic coverage in architecture.md and coverage-ledger.json.
- Coverage-led hunting -- assign isolated hunters from ledger units, record their checks, and use coverage critics to find gaps.
- Candidate validation -- give every unique candidate to a fresh verifier that tries to disprove it.
- Structured output -- write confirmed, needs_validation, and rejected records to findings.json and validate them against report-schema.json.
- Independent record verification -- fresh agents verify final source claims. Material replacements receive another independent verifier.
- Target-neutral reporting -- derive REPORT.md, FINDINGS-DETAIL.md, and NEEDS-VALIDATION.md from the verified records and coverage ledger.
The parent runs validate-coverage-ledger.cjs after creating the ledger and after each later ledger update. It runs validate-findings.cjs in Phase 4 and again after every Phase 5 replacement.
The verdicts are distinct: confirmed has a complete source trace and bounded observed result, needs_validation has an exact unresolved fact and no severity, and rejected records a disproved candidate.
Multiple runs against the same repo are additive. The skill uses prior ledgers and findings to target gaps, revalidate changed source, and carry forward current-source evidence without treating stale or unresolved work as covered.
Install the skill with the Skills CLI:
npx skills add https://github.com/cloudflare/security-audit-skill \
  --skill security-audit
Use --global for a user-level installation:
npx skills add https://github.com/cloudflare/security-audit-skill \
  --skill security-audit \
  --global
Run npx skills --help for agent-selection and non-interactive options.
Start your coding agent in (or pointed at) the codebase you want to audit, then ask it to do a security audit:
security audit this codebase
find security vulnerabilities in ./src
do a security review, output to ~/audits/my-project
The skill activates automatically when the request matches its trigger (security audit, find vulnerabilities, pen-test the code, etc.). A direct codebase audit or pen-test request uses full audit mode. Security questions and focused vulnerability work use guidance mode unless you request report artifacts. In full audit mode, an unspecified output directory defaults to ~/security-audit-skill/<repo-name>/run-<N>. The workflow writes inside the target repository only when you explicitly select a directory that version control ignores.
- A coding agent with a model that supports tool use and parallel sub-agents
- Node.js for the zero-dependency findings and coverage-ledger validators
- An OS-enforced sandbox for target-controlled builds, tests, processes, browsers, emulators, fuzzers, and fixtures. It must disable external networking, use a sanitized allowlisted environment, enforce resource limits, and allow writes only to assigned scratch paths. Without these controls, the workflow keeps the lead as needs_validation instead of executing target code.
- Only confirm established boundary failures. Keep a source-grounded blocked lead as needs_validation with its exact unresolved fact.
- Adversarial validation. The agent that checks a finding is never the agent that found it.
- Severity requires impact. Likelihood x impact, not deviation from a checklist.
- Defense-in-depth gaps are not vulnerabilities. If Layer A prevents the attack, the absence of Layer B is a hardening note.
- Multiple runs improve coverage. In our test runs, a single run found roughly half of the vulnerabilities that repeated runs found in total.
Questions, feedback, or comparing notes on AI-driven security tooling: security-ai-research@cloudflare.com

- It hits ordinary, low-volume senders, not only the bulk senders Microsoft's published rules cover.
- Only some messages bounce, so "my mail is getting through" doesn't mean your domain is safe.

What the bounce looks like
The sender gets a bounce like this one, followed by a bracketed server name and ID that differ per message:
550 5.7.1 Message rejected: Message lacks SPF/DKIM/DMARC Auth Records (AS9031519)
On the first day, the same rejection came back without the (AS9031519) code:
550 5.7.1 Message rejected: Message lacks SPF/DKIM/DMARC Auth Records
The wording suggests something is badly broken. Usually it isn't. The domains we have seen bounced mostly had working SPF, and many had DKIM too. What they were missing was the DMARC record that ties the two to the From address.
What changed
Microsoft does have published sender rules. Since May 2025, domains that send more than 5,000 messages a day to Outlook.com have had to pass SPF, DKIM and DMARC, or get 550 5.7.515 Access denied. - It reaches small senders. A one-line reply from a small office can bounce.
- It wasn't announced. As of November 6, Microsoft has published nothing about it: no postmaster notice, no blog post, no service-health entry.

Microsoft refuses only part of the mail from an affected domain. One message to a Hotmail address goes through, the next one bounces, and a resend may succeed. - [苹果产品那些不够颠覆，却值得被学习的细节](https://sspai.com/post/118114) <sub>11-08 11:18</sub>

Matrix 首页推荐
Matrix 是少数派的写作社区，我们主张分享真实的产品体验，有实用价值的经验与思考。我们会不定期挑选 Matrix 最优质的文章，展示来自用户的最真实的体验和观点。

每次苹果发新品，我都会去官网转一圈，这个习惯保持了很多年，因为无论好坏，他们每次在网站的设计和交互上多少都能玩出些新花样。这在其他品牌很少见。
翻得多了会发现，那些被别的品牌学走的、隔几年就在无数产品上重新出现，或者能明显看到影子的做法，几乎都不是发布会上的重点。
在消费数码领域，所有品牌都在不断探索和学习，苹果这家公司给我的感受是，他们总有一套自己独到的见解和思路，虽没有了 iPod 或 iPhone 4 时代那么现象级的影响，但在库克掌管 Apple 的十几年里，依然存在很多容易被创作者忽视和值得学习思考的问题处理方式。往深讲，这或许有一套方法论在里面，其实我想不明白也说不清楚它们到底是什么，这篇文章也只是抛砖引玉，如果你也对这方面感兴趣，欢迎交流。
把触感融入界面
Taptic Engine 这东西最早出现在 2014 年的 Apple Watch 上，那年它还只需负责提醒你有通知，或者站起来走两步，我想当时应该没多少人能想到它会变成整套交互的一环。
2015 年的 iPhone 6s 换上了 Taptic Engine。当时也没人太在意，宣传语仅仅写的是「更细腻的震动反馈」，为了配合 3D Touch 的卖点。
在这之前，人们对手机震动的认知是只有一种功能，提醒你有事情来了，震动也只是提醒的手段之一。从 Taptic Engine 进入手机之后，震动变成真实的触感：长按图标弹起有一下回弹，滚轮转过一格有一下轻磕，付款确认有一下「咯噔」。它开始不光告诉你发生了什么，还让你确认自己刚刚做了什么。
这个东西感受过一次就很难回去，体验的巅峰时刻我记得是发布 iPhone 7 的时候，它的 home 键你关机后会发现其实是按不下去的，但震感真的就像按动了一样，非常神奇。
之后进入全面屏时代，iPhone 上的震动几乎全都服务于屏幕按钮了，其实我觉得只保留一个电源键，其他所有实体按键全都做成「模拟震动」还是很酷的，极致一点，完全可以做出只有电源键的机身。
随后几年内，其他品牌都陆续开始使用线性马达来获得近似的体验，如今已经是行业标配。
延伸思考：为什么唯独 iPad 没有加入 Taptic Engine 呢？
第二是动画。
2013 年的 iOS 7 给界面加了非线性的弹簧动画。在这之前，动效只靠时长和缓动曲线控制，东西要么匀速走，要么简单加减速，到位就停。iOS 7 之后，位移可以带质量和阻尼，你推它一下，它过冲一点会再弹回来。
这一层改动当时并不全是好评。弹簧的参数不按物理直觉来，开发者调起来得全凭手感，不少 App 早期都弹得过头。但我觉得快慢并不是重点，重点是他们在大刀阔斧把 UI 做成扁平化之后，利用动画让轻飘飘的界面元素具备了重量感，这种处理方式其实和 Taptic Engine 是同一个思路：让玻璃下的数字内容显得真实可信。
2022 年 iPhone 14 Pro 的灵动岛是在这个方向上的继续推进，把那块挖孔镜头变成一片会按内容伸缩、有边界、能呼吸的区域，只是这次的动画是为了让那个闹心的刘海不再「碍眼」。
这三件事看起来并不相关：震动、动画、灵动岛。其实它们都在处理同一个问题，如何让人相信虚拟的屏幕上面那些东西是真实可信的。
一条曲线贯彻到底
2017 年 iPhone X 之后，媒体普遍开始赞赏 iOS 软硬件的圆角处理。
机身、屏幕、图标四角，用的不是几何意义上的正圆角，是曲率连续的超椭圆。我之前也在 《跟着 Apple Watch 初识产品工业设计》 里单独介绍过。
圆角矩形的接缝，在低分辨率屏幕上是糊的，看不出来。iPhone 4 之后屏幕密到 326 ppi，那条缝就藏不住了。我最初以为这是为了修掉某个显示瑕疵，但在 AI 的帮助下发现 2013 年 那份专利 里，理由写的是美学，一个字没提屏幕。
单看不难，难在它必须整台机器一起做。屏幕圆角得跟机身对齐，图标圆角得跟屏幕的手感对齐，连 San Francisco 这套新字体一笔的收尾弧度都得跟它们用同一套曲线。只要有一处圆角没用这个曲线，这个理念就不成立了。
后面所有做手机的品牌都不约而同开始强调自家也做了多好看的圆角。macOS 26 也把图标圆角又调圆了一轮，我在第 6 期里整理过这三十年图标的变化。
把别人的发明整合为规范
比如小组件和深色模式。
桌面小组件不是苹果发明的，Android 很早就有，Windows Vista 的侧边栏比它更早。2020 年 iOS 14 上做的时候，很多人第一反应是「这不早就有了」。
而苹果给了一套尺寸网格、统一的圆角、统一的刷新机制。做完之后，小组件从「能放东西的方块」变成了一个可以被设计的东西，第三方开始按这套规矩做，用户也慢慢觉得它值得摆出来。有关小组件的详细介绍，可以看看优设这篇 全新的 iOS 14 小组件要如何设计？来看官方设计指南。
深色模式同理。2019 年 iOS 13 上线时，Windows Phone 早在 2010 年就把深色做成了默认。iOS 显然做了更多的思考，把哪些层级用什么灰，图片怎么处理，OLED 上黑色怎么用，全部定成了内置的规则，大幅度减少了第三方设计开发的摩擦。
苹果在这些地方的动作都是「整合与收编」。
其实这些纯粹软件上的细节，只要其他品牌愿意多想一步，肯定是能做到且做好的。以我粗浅的理解，可能原因是既然有人愿意吃螃蟹，我们再等等，让他先吃，不中毒我们再吃。Google 大概算那个愿意多想一步的，他们的设计理念我在第 11 期里专门聊过。
让设备边界消失
比如 2013 年的 AirDrop，2014 年的 Handoff，以及 2016 年的通用剪贴板。
这三个工具单独看都是不痛不痒的功能：传文件，跨设备复制粘贴，继续干活。但合起来之后，至少在我的使用经验里，我开始不太在意文件在哪台设备上了。
在这之前，多设备协同是个需要被管理的问题。你得知道照片存在手机还是电脑，得记得哪台机器上是最新版。AirDrop 之后，传输这个动作变成选一个身份，不再是选一个存储位置。Handoff 之后，你在手机上读的网页，电脑上直接就能接着看。
其实还有更多这样的协同，例如，跨设备投屏，使用一套键鼠横跨多个设备，耳机音响多设备无感切换，很多很多……
这些无缝无感但稳定可靠的功能体验，慢慢会改变用户的心智，人们会从「哇原来还可以这样」变成「本来就该这样」。
最近的新变化
如果说手机的全面屏时代，怎样处理屏幕刘海或前置摄像头是 S 级问题，那么折叠屏设备设计的 S 级问题就是看内屏折叠展开的操作体验。这里的「 S 级 」意为无法回避的设计问题。
iPhone Duo 我觉得有意思的地方是折叠和展开的时候，被翻过去的屏幕内容会随着切换的过程变模糊，同时面向用户这一面的屏幕越来越清晰。
这种处理方式我觉得非常有意思，会让人在心理上感到：我其实折叠的是外面的框和玻璃，屏幕里的内容还挺留在那个一整块的平面上。表面看软硬件在视觉上短暂「分离」了，但其实背后结合得十分紧密。
三星 Galaxy Z Fold 8 是 2026 年 7 月发布的，比 iPhone Duo 早两个月，但它根本没有开合动画：内容只是等手机展开到大约一半时，直接从外屏切到内屏。
钛媒体的评价更直接：
折叠屏早就能在内外屏之间接续内容，但画面怎么随着开合动作过渡，过去确实没有几家会去仔细研究。苹果这次把机身的动作和画面的变化连了起来……第一次把折叠屏“折叠”这个动作，做成一种视觉享受。
从 2019 年三星首款折叠屏算起整整七年，行业一直在改进铰链耐久度、折痕和厚度，没有人处理「开合本身」这个交互。
对我的帮助
我并不算果粉，在用的设备只是标准三件套：Mac、iPad 和 iPhone，而且最新的也都是 5 年前发布的型号了。
从第一台 iPhone 4 开始，十几年用下来我感觉到，苹果非常擅长把一个已经存在的功能或体验，改造成别的品牌再想换个做法就得解释一遍的默认值，这是值得所有设计师学习的。
这为我做设计，写文章，乃至从事任何创作活动，都带来了极大的帮助。判断一个设计理念值不值得学，我的启发是看它有没有替后面所有人省掉解释成本——不仅仅是用户，是接触到这个设计的所有人。
这条标准也是通用的，例如我很早就把它用在 文件管理和命名规范 上，给我和同事都节约了大量不必要的沟通时间。它和 设计里的通杀概念 是同一类东西：能跨场景用，才算真正的好工具。
反过来用在自己身上，我会尽量在给出任何交付之前都问问自己：这个东西，需要我再解释一遍吗？

上小学之后，我会在周末到少年宫去上古诗词和科普英语的课，慢慢地我爸还是觉得有个手机方便联系接我，就给我买了台诺基亚 106。这是个功能机，除了用来打电话，我只能一遍又一遍玩自带的贪吃蛇。
直到小学四五年级，我才终于获得了一台下放的小米 4，某种程度上它成为了我的数字世界的启蒙。我花了无穷无尽的时间在上面折腾各种乱七八糟的事情，比如用 BoardWalk 在手机上运行 Java 版的 Minecraft，但是只能在超平坦流畅运行，如果想进「末地」看一眼就只有每秒四帧了；因为当时 Pokemon Go 大火，所以尝试在手机上玩了 Pokemon Go，虽然能成功运行但死活搞定不了虚拟定位；因为一篇电脑报的文章我知道了 xash3D 引擎可以在手机上运行 CS1.6；我还尝试了各种 ROOT 大师，但到最后都没能独立搞定自己手机的 ROOT。
电子书
Kindle 是对我而言最为重要的设备。
虽然我今天已经不怎么看书了，Kindle 都甚至退出了中国市场，真是无限唏嘘。小时候的寒暑假我爸在法院工作，因为没人带我就把我丢在法院的图书馆，然后中午下来和他吃饭。他知道我会无所事事就把他的 Kindle 给了我，还给我开了一个 Kindle Unlimited 的会员。
那个时候 Kindle 背面的 logo 写的还是 Kindle 而不是 Amazon。
Kindle Unlimited 的好处是东野圭吾的小说根本看不完，坏处是没有金庸的小说可以看，我初中的时候看了东野圭吾的全部作品，最喜欢神探伽利略系列和加贺恭一郎系列。我还看了不少知乎周刊，这主要是因为它们是免费的。早年的知乎周刊真的质量奇高，我在知乎周刊上读到了朱利安阿桑奇的故事，也在上知道了硅谷有人在用 Soylent 来代替吃饭。

即使是流行畅销书，读罢一本，也会或多或少在脑海中留下深刻的印记。是的，我想说，对我来说就是 Kindle 培养了我的阅读习惯，以一种方便的、唾手可得的方式给我种下了种子。高中之后我开始逐渐从流行文学读更多东西，读波拉尼奥、读福克纳，但 Kindle 就是一个起点。
给我震动最大的电子设备——没有之一——是索尼 DPT-RP1。我爸在它一发售就花了大几千块钱从日本海淘回来。这台设备至今在我见过的所有电子产品中，优雅程度排第一位。纯黑的薄如蝉翼的外观，宛若用铅笔在纸上的触感，开箱的一瞬间我仿佛在开一个来自外星球的产物。
我把这玩意带去英语课补习，别人都写在纸上，就我写在电子纸上，无敌吸引眼球。2020 年疫情来了，这台设备更是派上了大用场，我可以不打印作业，直接在 DPT-RP1 上写，在把 PDF 直接发给老师，感觉自己优雅得不行。
高中之后，一开始它只是屏幕上有一块坏死的区域没法写字，我只能用它看看书；后来设备的边角开始裂开，我才知道「薄如蝉翼」也有代价。再后来触控屏失灵，它只能躺在我书桌最底下的抽屉里，成为我少年时代的纪念品。
我与苹果
被 Windows Mobile 伤透了心之后，我爸投入了苹果的怀抱。在我上高中之前，每年的九月的某一天我起床吃早饭的时候，如果发现饭桌上我爸架着 iPad 在看昨晚的苹果发布会回放，我就知道苹果又出新品了。
iPhone 6 的金色配色被很多人称之为「土豪金」，我爸买了 iPhone 6 Plus 送给我妈，我记得我和我妈一起拆箱。我爸则买了一个黑色的小屏 iPhone 6，直到今天我都认为 iPhone 6 有着所有苹果手机中最优雅的外观。后来虽然我爸有淘汰下来 iPhone 6，但我却一点不想用它，苹果设备没法自由安装安装包，你不得不折腾各种各样的手机助手，我这种体会了安卓自由滋味的人永远不会满意。
我不喜欢苹果的封闭生态，但没有人会否认苹果的产品就是走在最前沿的，它在乎细节，有质感和格调。
虽然我爸用苹果手机比较晚，但我家很早就有了一台第三代 iPad，主要用来看美剧，当时搜狐还有很多美剧，我跟着我爸一块看，印象最深的就是《越狱》；初中的时候去闵行上学而思培优，它有一个 iPad APP，所以也需要用到 iPad。
iPad 上让我印象最深的游戏除了人尽皆知的《水果忍者》，还有《我的世界》故事模式，和《三国杀 烈》，一个剧情模式的《三国杀》更是我心里最好的《三国杀》电子游戏。《我的世界》故事模式由于制作商倒闭了彻底绝版，而《三国杀 烈》也是除了 iPad 没有上架过任何平台，并且由于只支持 32 位，今天的 iPad 也无法运行了。
2022 年我不得不在家上网课，听说当时的 MacBook 换了 M 系列芯片，我颇感好奇。我爸想着 MacBook 又不能打游戏就给我买了一个。
macOS 还是可以自由安装软件的，因此这是唯一一台让我爱不释手的苹果设备。我很快就发现苹果电脑的屏幕素质实在是太好了，上网课的时候天天挂着 OBS 虚拟摄像头，然后窝在房间里看电影。
不知道什么原因，B 站当时开始大买版权，首页又一次给我推荐了戈达尔的《精疲力尽》，我人生中第一次看到和小时候在家里 IPTV 点播好莱坞电影截然不同的作品，就是在高二下和高三上这两个学期在家的时间。我就这么在上网课的日子里看了大概有一百部文艺片，从戈达尔到伯格曼，从费里尼到塔可夫斯基。结果当然是我的春考一塌糊涂。
我与微软
我是 Surface 系列的忠实粉丝，这主要是受我老爸的感染，他是微软 Lumia 坚守到最后一批的用户，初中给我买的第一台电脑是 Surface Book2（但是没有独显）。上了大学之后，我选择了 Surface Laptop Studio 作为我的笔记本电脑。
只是我越来越受不了 Windows，我把它的系统换成了 Linux。说真的，抛开性价比不谈，微软的整体外观就是 PC 阵营里最有高级感的。银色 logo 帅到爆炸。
Surface Duo 刚出的时候毫无疑问成为了我的白月光，大一的时候我终于在生活费里东抠西抠以三千多的价格搞来了一部 Surface Duo2，圆了自己高中的梦想。
我为了想要更好地使用，甚至把自己的笔记流程转移到了 OneNote。最后发现 OneNote 是一个被低估的好软件，但 Surface Duo 绝对是微软出过最失败的硬件之一。Surface Book 系列和 Surface Laptop Studio 都至少让我能够在看剧和电影的时候忽视键盘——Surface Duo 除了概念什么也没剩下。
微软试图以生产力工具的方式定义 Surface Duo，但是手机根本不是生产力工具。在绝大多数的情况下根本不需要同时双屏，所以并非折叠屏的它，就不得不面对那个雷霆大裂缝，更别说它又宽又厚，单手使用体验差得要命。
大一升大二的那个暑假，我和朋友去安吉漂流的时候把这个手机掉进了水里，它死得非常彻底。无论如何，我还是为 Panos Panay 时代的落幕而感到感伤。我自知他治下的每一款产品都难以称得上成功，但是我就是喜欢那些产品的 fanciness 本身，那种与众不同的个性，那种科技超脱工具本身的感觉。
今天的设备
大学之后有了些闲钱，我可以尝试各种各样的手机。除了 Surface Duo2，我用过一段时间的索尼 Xperia Pro-I，觉得它是带屏幕的黑卡，却发现自己根本不怎么拍照。
我后来尝试用过 Fairphone5，在解 BL 锁的时候出了一些问题然后发了邮件，过了 3 个月才收到第一封模板邮件回复，对于这样的神人客服我真的不知道说什么。更离谱的是不知道为什么我用着用着这个手机的 NFC 坏了。有趣的是尽管 Fairphone 的优点在于可维修性，NFC 坏了只需要换一个电池，但我当时在 UCB 交流，美国根本找不到 Fairphone 5 的备件。
我现在的手机是一台 Minimal Phone，大三在伯克利交流的时候刚好它开始预售发货，而好巧不巧我的 Fairphone 5 当时坏了。所以 Minimal Phone 一跃从玩具变成了主力机。
Minimal Phone 作为一款墨水屏手机其实完全足以日用，虽然我根本不会想用它去浏览任何需要滑动的社交媒体，但它也确实无论是用微信小程序点餐拿外卖，还是用来回微信和 QQ 消息都没毛病。有 NFC 可以 Google Pay 也可以支付宝碰一碰。它完美地卡在了你可以使用但又不想主动使用的区间。在地铁上的时候我会发呆，吃饭的时候我就只能吃饭，我觉得其实也挺好的。我根本没有想到，我手里的这部 Minimal Phone 我已经用了一年了，对我的 Doomscrolling 还真是给彻底根治了。
不过由于它的相机真的特别特别差——是真的连扫码都费劲，距离一远就别想企业微信签到了，而且缺少彩光有一些人脸识别的问题。所以最好有一部备机使用，比如我就有一个 root 了的小米 9。
科技应该是什么样
面对在 Reddit 这个广为传播并引起广泛共鸣的帖子，我不知道该作何感想。因为我永远也没法想象一个科技停止在这里的时间线。我没有办法想象自己没经历过的事物。
出生于 2005 年，我是移动互联网的原住民，我的整个青少年时期就是移动互联网在中国的普及史，我见证了我的小姑给我妈推荐微信这个软件，然后我妈买了一台小米 2S 作为智能机；我见证了家族里的亲戚们开始拥有拉起微信群，在过年玩抢红包和集五福；见证了我的完全不识字的奶奶居然学会了使用抖音，并且热衷于在上面看各种儿孙不孝剧情。
但某种程度上它的确写出了我们的心声，科技并不意味着让我们的生活变好。对我来说，电脑肯定是好的设备，电纸书肯定是好的设备，而智能手机或许不是。AI 呢？我说不准。
2021 年的时候我高二，看了奈飞的纪录片 The Social dilemma，我非常受触动，发了 QQ 空间转发给我的很多朋友。当初我的一些同学也同样深受感触的评论我说想要研究怎么拒绝手机和社交媒体。大家还是拥抱了社交媒体。
我的好哥们 Andy，初中的时候用最爆的语言批评抖音，跟大家说点一个赞刷一分钟，然后在帖子下面说自己刷不下去。每次和他出门吃饭的时候他都在看抖音。
我曾经是一个数码爱好者，天天刷 IT 之家、订电脑报、听李如一的《一天世界》播客，甚至还充了一天世界的会员计划。今天李如一早就淡出了中国互联网，看今天他的部落格里那种对于科技的冷感，你根本无法想象他是那个做《IT 公论》的李如一。我自高中之后再也没有看过电脑报或者 IT 之家。
我在 B 站还能刷到极客湾、TESTV，但我很多时候甚至连懒得点开；极客湾转型面向了手机评测，TESTV 和佼佼流口水分家。我曾经受何同学的影响想一边上大学一边做数码博主，最后我没有这么做，但我并不为此感到遗憾。对于今天的互联网来说为人所知或许并不是一件好事，何同学从数码博主转型做 DIY 之后我再也没有看过他的一期视频。
跋
今年大四，面临人生十字路口的我，选择在一个深夜一口气写下这些文字，或许是因为作为一名计算机专业的学生我有着极大的概率会进入互联网行业，而我只是想思考清楚科技对于我意味着什么。
事实上，高考之后我选择计算机专业不是因为乔布斯和马斯克的故事，更不是因为看过《社交网络》的电影，恰恰相反，是因为 Tim Berners-Lee，是因为读过 RMS 的传记《若为自由故》，是因为 Alan Swartz 的纪录片《互联网之子》。
无论今天的互联网让我感受如何，我都仍然有互联网的乌托邦情结。大概是在我初次邂逅互联网的少年年代，在贴吧、在 QQ 群，大家用网盘和群文件来分享资源，有一批人手把手不厌其烦的教授安装和使用软件：我知道了手机上要用 ZAchiver 来解压 7z，学会了在手机上如何安装谷歌框架，学会了在贴吧靠与佛论禅和与熊论道获取链接。
我在各种奇怪的地方获取影视资源，看到人们说 1024，好人一生平安。
在那个移动互联网方兴未艾的时代，它给了我一个可以钻进去的地下室，其间的感受不足为外人道也，但却使得那些孤独时光并不难捱。我知道那些新奇感并不完全属于那个时代，我想并不叙述某种什么过往黄金时代的陈词滥调。
我只想回应自己的感受，自己的记忆，只是因为那时候我满腔少年心气，对一切都充满好奇，对未来充满憧憬。

I watched a humanoid robot clean my apartment. It felt like a taste of the future.
The startup Tau Robotics is sending humanoid robots to clean San Francisco homes. They still need lots of human guidance, but they’re learning.
I’m not the sort of person who typically pays for a house cleaner. I’m too frugal, and I kind of enjoy putting on a podcast and going to town on my tub with a Magic Eraser. But when I saw an X post about a new humanoid-robot cleaning service in San Francisco, I immediately signed up for the waitlist. I wanted my apartment to feel like The Jetsons, even if just for an hour.
I was also motivated by journalistic interest. In order to ensure an authentic experience, I didn’t tell Tau Robotics, the startup behind the X post, that I was a journalist—though I did use my real name, so it’s possible someone looked me up. Tau’s long-term goal is to make autonomous cleaning robots a reality, but they’re not quite there yet: For now, the robots are piloted remotely by humans, who watch what’s going on via cameras mounted in the robots’ heads and wrists. As the robots clean, they collect data that Tau will use to train up their more independent descendants. Every counter successfully wiped and T-shirt successfully folded will help the models that power the robots learn to do better on the next go-round.
Because this data is so valuable to Tau, the company charges less for cleaning than one might expect for such a cutting-edge product. At the time I booked, Tau was offering $30 for an hourlong cleaning with a single robot; now the charge is $60 per weekly cleaning with two robots, or $100 for a one-time visit. But even at the cheaper rate of $30 per hour, Tau’s robots aren’t a great bargain. They are thorough but slow, so if you, like me, are tempted to stand around watching them for their entire visit, it would probably be a better use of your time to just take care of the cleaning yourself.
But the robots are physically capable of cleaning, and they’re undeniably cute. Tau has armed each four-and-a-half-foot-tall robot with a 3D-printed “head” with antennae that allow it to communicate with Tau’s headquarters, as well as two 3D-printed claw “hands” (the more humanlike alternatives apparently aren’t durable enough, and claws do surprisingly well for most cleaning tasks). Mine was wearing a Tau Robotics shirt, and grippy socks so that it didn’t scratch hardwood floors.
With all the human support they need, the robots are closer to radio-controlled cars than Waymos. Many tasks, such as making the bed and folding laundry, require what’s called kinematic guidance: The human pilot performs the necessary motions, and sensors transmit those movements to the robot, which copies them. These kinematically guided tasks produce especially valuable training data. Tau’s AI models might not have solved laundry folding yet, but learning from the examples of robots that have completed the task in the real world is how they’ll get there.
But according to Tau cofounder Cornelia Weinzierl, to whom I came clean as a journalist a few weeks after the cleaning, the robot can already complete some other tasks—such as vacuuming and mopping—without any human help. If Tau succeeds in using all the data it is collecting to train truly autonomous cleaning robots, they could even become San Francisco’s newest tech tourist attraction as Waymos become more commonplace countrywide.
The cleaning robot that came to my building last month was already a bit of a spectacle. It arrived in a blue minivan, out of which it was helped by Weinzierl and another Tau employee. That’s when the robot encountered its first obstacle: the eight stairs leading up to the building’s front door. I’d come down to greet Weinzierl and the robot, so I had a front-row seat to its struggles with my steps. It climbed as if it were drunk. Each successful step was as likely as not to be followed by a stumbling backward stagger that erased all its progress—though, impressively, it never entirely lost its footing.
When I later discussed my experience with Weinzierl, she explained that the robot sometimes walks strangely because it is operated remotely from Tau’s headquarters, and the short signal transmission delay can affect its coordination. “The amount of work and time that we spend just optimizing, for example, timings and connectivity is crazy,” she said.
Inside, the carpeted staircase leading up to my apartment defeated the robot entirely, and Weinzierl had to lug it up the last few steps. This, it turned out, was not typical. As the robot cleaned, it repeatedly stalled out, something Weinzierl attributed to it overheating in the unseasonably hot weather—until she heard from one of her colleagues that the heat had shut down not the robot but the equipment that its human controller was using to watch its progress through my apartment. Without remote assistance, the robot couldn’t clean, and so it, and Weinzierl, departed before my booked hour was up. (Back in September, Weinzierl or another Tau representative remained with the robot throughout its visit, but she says that’s no longer necessary.)
You can’t fault Tau on customer service, though. Weinzierl quickly emailed me to apologize, comp the visit, and offer me another on the house (minus whatever price I assign to my data privacy)—and that was all before I told her I was a journalist. I scheduled the next cleaning for about a month later, after a couple of trips out of town, and it went much more smoothly—the robot got up my stairs without much assistance, though still with the drunken stagger.
In the hour it was there, it did a creditable job of cleaning my kitchen (though it didn’t brave the stove) and even saved me my most dreaded cleaning task, the toilet. That was its most impressive performance: Three times the head fell off its toilet cleaning wand, and three times it managed to reattach it by poking around with the handle until it made contact at just the right angle.
