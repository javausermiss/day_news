God's Eye View brings public signals into one explorable globe. Track the world live. Talk to it. Break it. Extend it.
Flight transponders, ship beacons, orbital elements, seismographs, and public cameras already tell us a lot about the world. God's Eye View puts them in the same place, so you can move between a global picture and an individual aircraft, ship, or street. It runs locally in your browser, with source code you can inspect and extend.
Half the magic is that it looks like a forbidden cockpit. The other half is that every line of code is inspectable.
Most feeds are live or regularly refreshed. Traffic is simulated along real roads using aggregate location data. CCTV camera poses and rocket launch trajectories are coarse estimates.
Start with the included data sources, then add your own. Each layer is a separate module.

How Libraries Run Rust Inside Python (with PyO3)
Every time you validate data with Pydantic v2, the data-validation library most Python apps reach for, a Rust extension does the work. Its core, pydantic-core, is built with PyO3, the same toolchain we'll use here.
This post builds that same kind of bridge, small enough to read in one sitting: a JSON parser written in Rust, exposed to Python, so you can import it like any other package. The last step, turning the Rust result into Python objects, is the one to understand before you port anything: for a parser like this, it can cost more than the parsing itself.
The four steps from Rust to import
Getting Rust code into Python takes four steps:
- Write a normal Rust module.
- Annotate it with PyO3 macros.
- Let maturin compile and install it.
- Import the result.
#[pyfunction] and #[pymodule] are the two Rust macros that do the wiring. A Rust attribute macro is close to a Python decorator: it rewrites the function it sits on, here adding the glue that lets Python call it and handles the type conversions and reference counting at the boundary.
Maturin then compiles the crate to a shared library (.so, .dylib, .dll) and drops it into your virtual environment, so import just works. I walk through this whole setup, from cargo new to the first import, in How to run Rust in Python with PyO3 and Maturin.
That first tutorial returns a single number. This one picks up where it left off, because the interesting part starts once you return a structure instead of a scalar.
The parser produces a Rust value first
The structure this parser returns is a JSON tree, and it's the running example for the rest of this post. In our Python to Rust cohort, students spend six weeks writing a JSON parser from scratch in Rust, a hand-rolled tokenizer and recursive-descent parser with no serde, then expose it to Python through PyO3. Josh's version beat CPython's C json module on real-world fixtures; Jochen's ran up to 3.5x faster than the Python version.
The public reference implementation, the clean version students start from, is the code I'll walk through here.
The parser produces a plain Rust enum. A Rust enum holds one of several shapes, and each variant can carry data, so it maps a JSON tree cleanly:
pub enum JsonValue {
    Null,
    Boolean(bool),
    Number(f64),
    String(String),
    Array(Vec<JsonValue>),
    Object(HashMap<String, JsonValue>),
}
That tree lives entirely in Rust. Python never sees it. The PyO3 layer is a thin adapter on top.
Exposing one function
Exposing a function to Python takes two lines:
#[pyfunction]
fn parse_json<'py>(py: Python<'py>, input: &str) -> PyResult<Bound<'py, PyAny>> {
    parse(input)?.into_pyobject(py)
}
For a Python reader, the signature is the most interesting part:
- py: Python<'py> is a token representing access to the Python interpreter and is what you pass to PyO3 APIs that need access to Python objects. On traditional Python builds, this access is associated with holding the GIL. PyO3 hands it to you and you pass it along wherever you touch a Python object.
- Bound<'py, PyAny> is a handle to a Python object of any type, the Rust side of what you'd think of as a PyObject.
- PyResult<T> is Result<T, PyErr>: return the value, or an error PyO3 raises as a Python exception.
- ? propagates that error. If parse fails, the function returns early and Python sees an exception; otherwise it unwraps the JsonValue and moves on.
So parse(input)? does the real work, and .into_pyobject(py) builds the Python objects the caller asked for. That last call is where the cost lives: it has to create Python objects for the nodes in the tree, and on a large document that can add up to more work than the parse itself.
The return trip is the expensive part
Here is why that conversion is not free. .into_pyobject walks the entire JsonValue tree and rebuilds it as native Python objects: a dict per object, a list per array, a float or str per leaf. You provide that translation by implementing the IntoPyObject trait, which PyO3 calls to convert a Rust value into a Python one:
impl<'py> IntoPyObject<'py> for JsonValue {
    fn into_pyobject(self, py: Python<'py>) -> Result<Self::Output, Self::Error> {
        match self {
            JsonValue::Null => Ok(py.None().into_bound(py)),
            JsonValue::Number(n) => Ok(n.into_pyobject(py)?.to_owned().into_any()),
            JsonValue::Object(obj) => {
                let py_dict = PyDict::new(py);
                for (k, v) in obj {
                    py_dict.set_item(k, v.into_pyobject(py)?)?;  // recurses
                }
                Ok(py_dict.into_any())
            }
            // ...arrays, strings, booleans
        }
    }
}
A document with 100,000 values means on the order of 100,000 Python objects being created at the boundary, all after parsing is completely done. On a large document this materialization loop, not the parsing, can dominate the end-to-end time.
Errors cross the boundary the same way
The return value is not the only thing that has to translate. A parse failure is a typed Rust error, and Python wants an exception. One From impl, the trait Rust uses to convert one type into another, lets ? do the work:
impl From<JsonError> for PyErr {
    fn from(err: JsonError) -> PyErr {
        match err {
            JsonError::UnterminatedString { position } => PyValueError::new_err(
                format!("Unterminated string starting at position {position}")
            ),
            // ...one arm per error variant, position preserved
        }
    }
}
Now malformed input raises a ValueError carrying the offset where parsing broke. The file-reading path gets the same treatment for free: std::io::Error already converts to the matching Python exception, so a missing path raises FileNotFoundError.
The caller gets Python semantics without the Rust layer leaking through.

中年男人的三大爱好：充电头、NAS、软路由。这里要讲的是后两样。
作为一个软件开发者，我一直想有一台自己的服务器，NAS 和软路由就是我通往这个梦想的起点。2019 年入手第一台 NAS（Network Attached Storage，网络附加存储），算是为我打开了一扇新世界的大门，折腾蓝光电影、备份家庭照片和视频、共享文件等，完全不需要依赖别人给的网盘和 OSS。
加上电信和联通的 2 个公网 IP，我开始痴迷于玩儿网络设备，后面几年陆陆续续添置软路由、小主机、服务器和交换机，慢慢就攒齐了现在这套东西。

作为系列的第一篇，这里想把三件事讲清楚：什么是 HomeLab、我为什么愿意折腾它、以及这套东西需要哪些硬件、它们大概又要花多少钱。系列其他文章的目录放在文末。
什么是 HomeLab
HomeLab，顾名思义就是家庭实验室，可以理解成家庭版的云服务器，用来跑各种自建服务，比如个人网盘、影音服务、开发环境、智能家居、私有云等等。
拆开看，一台 HomeLab 无非是四件事：
- 算力：物理服务器或虚拟机，用来跑各类服务；
- 存储：NAS 和硬盘，用来管理和存储数据；
- 网络：软路由和硬路由，用来管流量；
- 外设：摄像头、传感器、开发板之类的，用来折腾点新东西。
门槛没有想象中那么高。一台成品 NAS，或者一台能装 Docker 的小主机，实在不行一台就笔记本就足够开始，不需要一上来就配齐四类。我现在的这套也不是一次买齐的，而是踩一步看一步折腾出来的，具体清单放在了后面的硬件章节。
为什么我要自建 HomeLab
对我来说，搭 HomeLab 是一种浪漫的「折腾」。理由有三个，按重要性排是：数据、隐私、以及折腾本身。
数据得握在自己手里
我对数据安全比较在意，所以重要的数据都存在自己的服务器上，而不是交给云存储。早些年用七牛云 OSS 存博客的配图，后来搞忘续费，全部图片直接访问不了了，连抢救的机会都不给，加上大批量的云存储服务商跑路，现在我对这类云存储服务商没有任何信任感。
家人的照片不该由第三方保管
家人的照片、儿子的成长记录这类东西，放在本地私有化存储我会更放心。这类数据不需要分享给任何人，也不需要经过任何第三方。
有一个随时能用的实验室
我本身喜欢尝试新技术，有一套自己的环境，就能快速验证一个新方案行不行，而不用等公司排期。这大概也是很多同行入坑 HomeLab 的真实动机。
我的原则：够用就好，别搞 All in Boom
首先是 KISS 原则：Keep It Simple, Stupid。
HomeLab 搭建是一件费时费力的事，为了避免占用大量个人时间，我尽量选简单易用的方案，避开复杂的配置和操作。本着够用的原则也不会上太复杂的软件架构。
硬件：重要的数据买成品 NAS，其余去咸鱼捡垃圾
对重要的数据，我会直接选择成品 NAS，避免数据丢失；其他没那么重要的服务，用 Docker 跑就行，管理灵活、成本也好控制。所以整套 HomeLab 是围绕 NAS 展开的，剩下那些不太重要的服务，直接去咸鱼捡垃圾。
软件：Docker 够用，先不上 K8S
对 HomeLab 来说，最大的投入是硬件成本和时间。为了压住时间成本，我直接用 Docker，不搭 K8S 这类比较折腾的东西：目前的服务数量和质量还不至于用上它（也许下次升级会考虑）。
因为大部分服务都跑在 Docker 里，是否支持虚拟化就成为了选设备时的一条硬指标。
挑硬件的四条标准
具体到选哪台机器，我会按四条标准排优先级：
- 稳定性：优先选可靠性高的产品，避免频繁处理硬件故障，这既影响效率，也可能丢数据
- 性价比：在满足需求的前提下找最划算的选项，钱是有限资源，得合理分配
- 可扩展性：为了以后升级，尽量选容易扩展的方案
- 兼容性：选市场上被广泛认可、兼容性好的组件，避免后期不兼容
不选 All in One，也就是 All in Boom
稳定性是我最看重的一条，我不想频繁处理各种硬件故障，所以排除了把所有功能塞进一台机器的「全功能一体机」（All In One，也叫 All in Boom）。这类产品看着很吸引人，但往往牺牲了性能和升级空间。
我的做法是把服务拆到多台独立机器上。一台出问题不影响其他服务，可靠性和数据的连续性都更有保障。
当然，每个人玩儿 HomeLab 的思路不一样，硬件设备也不一样，适合自己当下的条件才最重要。不想折腾，买个成品服务器最省心；愿意折腾，去收二手硬件自己组装，性价比是真的高。
我的做法算是折中。数据这种最要紧的东西直接上成品 NAS，配上冗余和冷备。只要数据保住了，其他的随便折腾。
成本：钱花在哪了
HomeLab 最大的投入是硬件和时间，软件基本不花钱。我的分配原则是先把钱花在数据上，其余能省则省：
- 成品 NAS 和硬盘：这是唯一不太能省的部分，它承载的是不能丢的数据
- 服务器和显卡：大部分是二手，2080Ti 是咸鱼 1800 收的，Tesla P40 也是二手
- 网络设备：交换机、软路由基本都是咸鱼捡垃圾。DS923+ 的官方万兆网卡差不多抵得上五分之一台机器的价格，所以我一直等到兼容网卡出来才买，400 多块拿下
- 云服务器：99 元一年，一口气买了 2 年，主要用来放博客和做异地组网的中转
也有买贵的时候。早年买的 Mac mini 2018 的内存条，第一条 32G 花了接近 3000，三个月后买第二条只要 1000 出头，只能用「早买早享受」安慰自己。另外，二手货最大的隐性成本是时间和运气：要花时间刷、要花时间验、偶尔也会买到不合用的东西。
电费也是一笔账
这是书房的总耗电量，大约 80% 的设备在运行，这导致我经常做噩梦，梦到我媳妇儿每次交完电费都要去书房拔电源插头。

裁员：山雨终究还是来了
五月份的时候，公司里就开始盛传「人员优化」的八卦，而且还传的有鼻子有眼。鉴于公司在年初确实做了一些非常烧钱但效果差强人意的项目，用人员优化这种方式来挽救财报也不算稀奇。
事实上，这次裁员采用的是「倒序名单」的做法。每个团队需要将团队当中的所有人进行倒序排列，排在最前的人有最高风险被裁，而后依次类推。每个团队 leader 并不负责标注名单中的被裁人员是谁，而是将名单统一上交公司，由公司的「专业团队」根据人力和 token 成本综合计算。
这个「专业团队」，实际上是一个计算人力成本与 token 成本的组织，他们的工作就是基于总体目标，为各个团队计算出一个动态平衡点，根据这个平衡点来决定是否减员或者增补（当然增补的可能性微乎其微）。如此操作的结果就是，每个团队 leader 只有在收到回发名单以后才知道自己团队的准确裁员范围到底有多大。我所在的团队，算是这次裁员中影响范围较大的一个，裁员比例达到了 40% 以上。有些团队影响较小，可能 10% 左右。
除了比例不透明，这次裁员还有一个显著的特点，就是迅速。周一早上各团队 leader 收到确切名单，周一下午由 HR 负责与所有人进行沟通，告知赔偿方案，没异议立刻签字，然后还设备走人。HR 要求的切割速度很快，甚至与团队 leader 收到的节奏不完全同步。例如，我的 leader 在周一早上被告知我的 last day 应该是周五，但实际上周一下午的沟通结束后 HR 就催促我立刻签字交电脑，不用考虑交接问题，周二开始就可以不用来上班了。并且，在到达了下班时间的那一刻，我的账号被准时删除，工作软件被强制登出，所有的事情在四个小时内完结。
显然，市面上在裁员的公司并不只是我们一家。整个六月，我满耳朵听到的都是各家公司的「630」从传言到落实的新闻，人和 AI 在职场的竞争像是被按了加速器一般迅速推进到了白热化阶段。然而不幸的是，这一切似乎都还只是刚刚开始。
重启：又要从一份简历开始
我是一个非常讨厌写简历的人，一方面可能是因为上学的时候错过了很多写简历培训，怎么写都感觉不是那么回事；另一方面可能是因为我从本质上认为一张纸几行字完全不足以反映一个人。可是没办法，现阶段进入职场的第一步除了一份简历再无其他，我只能硬着头皮重新开始。
幸好，如今有了 AI 这个全能选手，终于不用自己写了，而且我认为 AI 还就真的适合干这个活儿。有了 AI 以后，写简历这件事情可以简化为以下三步。
Step 1：对 AI 念叨自己做的所有事情
这一步是我最擅长的事情。我的建议是，把每份工作中做的事情事无巨细的说给 AI 听，大到项目成果，小到解决问题的方法和细节，都可以事无巨细地全部列出来。这个步骤有两个好处：一是为 AI 准备充分的素材，俗称完善知识库；二是帮助我们在脑海中再重新梳理一遍自己做过的事，将来面试的时候也知道说什么。
你可能要说了，有把这些字都打出来的功夫，我自己可能都写完一份简历了。别忘了，有语音输入这个好东西。如果担心 AI 软件自带的语音识别准确度不高的话，也可以在微信中和自己聊天，利用微信自身的语音转文字来完成这个步骤。
Step 2：让 AI 提炼总结你的故事
以前的简历培训班，一般就教两个东西：简历模板、以及如何总结提炼自己的经历。包括我在内的很多人，之所以写不好简历，是因为提炼总结能力较差，不知道应该如何把自己做的事情用一套清晰简洁的语言表达出来。有了 AI 以后，把这种复杂的事情交给它做就可以了。假设你本来已经有一套自己的表达方法论（例如：背景—执行—结果），你也可以告诉 AI 用你习惯的表达方式来总结。如果没有也没关系，直接告诉 AI 提炼总结就行。毕竟这个版本还不是我们最终要交出的版本，先浓缩出一个基本可用的版本即可。
Step 3：找到几个心仪职位的 JD，让 AI 将提炼好的版本综合这些 JD 修改定稿
简历最终是要发出去给用人单位看的，而用人单位看简历就是为了确定你的经历是否和岗位需求匹配，因此匹配这个环节我们要尽量做好。当 AI 学习了你选择的目标 JD 的共同性之后，它就会很清楚地知道你和这个职位的匹配点在哪里，它应该朝着哪个方向来帮你优化。这样不仅会帮助我们在简历筛选中更快脱颖而出，而且能瞄准真正适合自己且有希望的岗位，而不是拿着一份放之四海而皆准的简历冲入招聘市场去大海捞针。
Tips：让 AI 展示每一步分析和结果供你把关
在 AI 还不算非常了解的情况下直接全流程托管，简历写出来有文不对题的风险，把写简历的过程全部外包出去很难完全放心。我建议你把分析和写作两个环节分开，要求 AI 在每一步分析结束，都返回给你它的分析思路和分析结果，你确认无误之后再进行写作。在查看分析过程的时候，还要注意防止 AI 对原始语料的某些词过度解读或发散思考，出现这样的问题时要及时介入进行纠正。
下海：陷入招聘的漩涡
准备好了简历，下一步自然就是把简历投出去了。招聘软件、企业官网，甚至小某书都被我用了起来，一边旅行一边在各个平台上搜索合适的岗位。在我把招聘软件的附件简历和在线简历都更新以后，事情就开始变得有意思了起来。
形形色色的猎头
招聘软件上的个人信息更新完成后，很多猎头就自动找上门了。整个求职期间，我加了不少于 50 个猎头的微信，每个猎头所说的主攻招聘方向都不一样。根据我的接触经验，现在的猎头大概可以分为以下几类。
打电话充数型
所谓打电话充数，就是指猎头只是为了完成其每天打电话的数量指标。举个例子，我的简历中清晰地写出了我所做的 AI 项目仅涉及功能应用，不涉及数据标注、算法优化等技术性工作。然而，很多 AI 方向的猎头在电话中上来就询问我的技术经验如何，似乎根本没有看过我的简历。在简单问了几个无关痛痒的问题之后就匆匆表示不合适然后挂断电话。这类猎头往往只看你的简历中是否有他们想要的关键词，而后就会把你作为他的「曝光池」，打完电话就完事儿。当你在求职过程中遇到这样不负责任的猎头，大可不必跟他客气，直接挂电话走人。
颐指气使型
你可能会觉得我的用词有些激烈，可没办法，这就是我接完这种猎头电话当下最真切的感受。这类猎头一般会直接进入主题，根据简历开始询问具体的工作和项目经历。聊着聊着，一切就开始变味儿了。猎头先是会对一些项目经历表示不屑，认为做得不够细致不应该拿出来讲（其实我也没有把这些项目写在简历上，倒是猎头很执着于问），再后来直接表示这样的简历和工作经验也就他还勉强愿意接触，直接推到 HR 那里肯定是浪费时间的，最后在问了一些个人情况之后直接甩了一句：你看起来根本没有路径规划呀，这样是不可能有公司要你的呀，你晓得伐。我斗胆猜测这些猎头是本来给予了我过高的期望然后失望了，不然我实在想不出第二个可以让他如此高傲的理由。
模拟面试型
也许是脱离求职市场比较久的缘故，我居然完全不知道现在和某些猎头的前置沟通已经变成了一轮面试。模拟面试型猎头大多一上来就会对简历展开详细追问，包括但不限于每份工作的细节和每次换工作的原因。他们还会在我讲述项目经历的过程中，临时根据某个关键词打断并细问。一来二去，一次电话沟通的时间竟然也到了一小时，并且挂电话时还会表示了解下来觉得匹配度不高，下次再见。到目前为止，我还没听说过猎头骗取候选人项目经历的事情，可是这些经历令我不得不怀疑我是不是第一个碰上这种事情的倒霉蛋。
真正靠谱型
如今任何工作中靠谱的人都越来越少了，猎头也不例外。然而真正靠谱的猎头，对求职者找工作来说是有很大助力作用的。我在整个求职过程中，也碰到了几位非常认真负责的猎头。他们大多首先确认简历中的关键词是否属实；然后简单精炼地描述目前岗位的需求，以及他判定的匹配程度；最后，还会跟你明确他的推荐理由大概会集中在哪几点，向你确认是否合理以及是否需要调整或补充；整个沟通过程十分钟左右就可以结束，简单高效。如此一套流程走下来，即使岗位最终没有推荐，我们这些求职者也在这个过程中又梳理了一遍自己的求职思路和方向。可惜讽刺的是，这样的猎头在我遇见的几十个猎头中屈指可数。
不可否认的是，对于已经有一定求职经验的求职者来说，猎头推荐是找到工作的一个很有效的路径。可是市面上的猎头已是鱼龙混杂，对求职者来说甄别难度也越来越大。大家要留好心眼，无需在错误的人身上浪费时间。
奇奇怪怪的职位
正所谓前有狼后有虎，除了要解决筛选合适猎头的问题，还要解决筛选合适职位的问题。而这一步，对广大求职者来说也是困难重重。
招聘平台：被 AI 包办的职位推荐
与三年前找工作时明显不同的是，如今各大招聘平台对算法推荐的应用非常普遍，每天几乎能根据简历邀请你投递 8-10 个不同公司的岗位。每个岗位的套路也都是一样的：先由系统发送给你一个职位邀请，而后你可以选择是否感兴趣，如果感兴趣则会由系统帮你自动投递简历。
然而现实情况是，这些系统自动投递的简历在企业 HR 的筛选序列中整体还属于低优先级，HR 会花更多的时间按照条件主动搜索发现简历，而不是完全相信系统推荐投递。因此，假设你和我一样正在找工作，我奉劝你一定要把时间用在有效的地方，不要被系统推荐算法耽误太多时间。
躲过了系统算法的推荐还不算完，我还遭遇了 AI 直接打电话的窘境。某平台在多次邀请我投递简历无果以后，直接触发了电话投递的方案。一天下午，我意外接到了已经神似人类但依然是机器人的电话，电话中机器人并没有直接告诉我邀请投递某岗位，而是先模仿人类进行了简单寒暄以后（甚至还会发出机械又礼貌的笑声），才开始说明有一个某快销公司的岗位很合适，并且开始询问我的个人基本信息。令我感到意外的是，在询问个人信息时，对话当中开始出现了明显不正确的停顿与断句。到这里，我才完全证实了这是一个 AI 电话的猜想。但贼船已上，说话间简历就已经投过去了。结果当然也是可预知的没有结果，不了了之。
我不能笼统地说这些 AI 推荐的职位都不合适，但我真的没有遇到任何一个推进到面试的职位是以系统推荐为起点的。更重要的是，不合时宜的推荐或电话还会让求职者感到不适。招聘软件上的推荐信息几乎是泥沙俱下，大家还是要尽力减少这些信息损耗，别让这些东西消耗你的精力。
职位要求：与 AI 强绑定
今年的求职市场相比于往年，一个最大的变化就是大多数职位都开始要求有「AI 相关经验」。无论你是做什么的，也无论你想找什么方向，AI 都成了一个绕不开的关键词。根据我的观察，求职市场对 AI 经验的要求有三个特点。
第一，越是容易被 AI 替代的岗位，对求职者的 AI 应用经验要求越高。以我为例，我的投递方向之一是数据产品经理，这个职位平时做的指标梳理、查 SQL 等工作，AI 目前的完成度其实是不错的。投递过程中，各家公司的数据产品经理职位几乎都问到了我过往是否有在工作中使用过对应的 skill 和 agent，并且有些还强调他们很看重候选人独立搭建 AI 工作流的能力，甚至会追问很多建设细节。这种现象在未来只会越来越普遍，我的建议是，每个人都可以用 AI 尝试一些独立制作的项目，将来这些东西可能会和设计师的作品集一样，成为找工作的敲门砖。
第二，从业年限和 AI 经验并不挂钩。虽然 AI 真正在很多工作的应用层面大火也就是近半年到一年的事情，可用人单位对 AI 经验的要求可并不是这么久。举一个最离谱的例子，在和某橙色短视频公司进行职位沟通时，它们明确表示目前只招聘工作经验一两年的低级别员工，并且严卡 AI 应用，要至少有完整一年的 AI 应用经验，否则无法进入招聘流程。我不认为市面上符合这个要求的人会很多，也许他们确实只招聘「顶尖人才」和太子爷。
第三，很多公司和职位无法清晰地界定并描述出其所要求的 AI 经验。如果你多问一句用人单位对 AI 的经验要求到什么程度，他们往往就会开始跟你打马虎眼，表示具体的要求需要问面试官。再进一步，如果你在面试过程中跟面试官多聊一些 AI 前沿的东西，他们反而可能跟不上你的节奏。为了 AI 而 AI 的乱象，已经从工作中延伸到了找工作中。
现在的求职市场基本上是不折不扣的卖方市场，招聘需求可能会随着 AI 的渗透而变得越来越离谱。作为一个求职者，大家做好相关准备的同时，也要勇于和不合理的职位需求说不，默默吃亏对自己并没有好处。
「诈骗」职位遍地开花
我真诚地提醒你，现在招聘软件上的「诈骗」职位越来越多，对求职者的甄别能力提出了更高的要求。
最典型的一类诈骗职位，就是要求先国内入职，等待海外工签下发后再启程去海外的工作（非常见海外大厂，以不知名小公司为主）。这样的公司，很可能在国外从事的是灰色产业（最典型的就是博彩），干的活儿可能是正经活儿，只是行业游走在法律的底线附近。这样的职位，一般有判断力的人和所谓的 HR 聊两句就能分辨出来，及时撤退就不会有什么风险。
还有一类职位，我之所以称之为诈骗职位，是因为它们实在太过不公开透明，那就是保险公司的储备干部。在我开始求职不久，就有不止一位保险公司的 HR 来接触我，像我推荐他们的储备干部职位。他们的 JD 和话术千篇一律，都是说职位定位为未来的储备干部，日常负责做区域人员培训和规划，并且一直都是进行跨行业招聘，没有保险从业经验完全没有问题。当你问到是否是销售岗位时，他们也都会表示自己有资源更好，没有也不重要，这不是他们的考核标准。我师父（实习时候的老板，现在自己做香港保险）知道之后严肃警告我：看到这种职位，想都别想，立刻拒绝。牢记，任何保险公司的模糊职位最终目的都是让你去卖保险。小某书上有很多相关的经验帖子，大家一看便知。
游向岸边：面试推进
虽然前面的路走得磕磕绊绊，但是也有一些看起来还不错的机会得到了有效地推进。在游向岸边的过程中，我遭遇了很多风浪也习得了很多技能。

- [iPhone 18 和 Duo 发布会上，Apple 没告诉你的那些事](https://sspai.com/post/114449) <sub>09-11 16:30</sub>

又是 9 月，又是一年一度熬夜看发布会的日子。然而今年的开场却有「亿点」不一样：当视频的灯光打向我们熟悉的 Tim Cook 的时候，他摆了摆手说「不是我，是这位」，然后镜头往前一推，John Ternus 走上台，说出了他作为新 CEO 主持发布会的第一句问候：「Hello」。
这场名为「Surprise and Shine」的发布会，看点相比往年也要密集许多。
其中，这次的主角毫无疑问是 Apple 的第一台折叠屏手机 iPhone Duo，其它产品如 iPhone 18 Pro、Apple Watch 和 AirPods 5 也有不小的升级。但仅仅只有一个半小时的 Keynote，总还是让人觉得意犹未尽。因此和往年一样，我们在发布会后火速把各个渠道的内容又翻了一遍，整理了 Apple 在发布会上没有告诉你的那些事。
关于 iPhone Duo 的那些事
Apple 推出的第一款折叠屏设备得名 iPhone Duo 而不是传言很久的 iPhone Ultra，说明 Apple 对它的定位其实并不是「比 Pro 更高」。相反，它的定位或许更像 iPhone Air，即算是一个新的系列，保留 iPhone 和折叠屏幕的核心体验，并在某些地方做到极致，而影像、峰值性能等一些地方相比 Pro 则有所妥协甚至缩水。
下面让我们看看如果今年打算买 iPhone Duo 的话，会比 iPhone 18 Pro 少了哪些功能。
延时摄影视频没缩水
在官网规格页上，iPhone Duo 的视频拍摄里写着「延时摄影视频，支持防抖功能（最高可达 4K 杜比视界）」。这是 iPhone Duo 唯一一个与 Pro 影像功能平起平坐的地方了。
Duo 了个屏幕，少了些功能
除了上面一条之外，Apple 对 iPhone Duo 的影像系统直接来了个大砍刀，刘华强看了都觉得残忍那种。我们把 iPhone 18 Pro、iPhone Duo 和 iPhone 17 的对比放一块，你就知道它和谁坐一桌了。
换句话说，iPhone Duo 是一台价位接近旗舰，不过影像规格接近标准版、iPhone Air 的设备。
噢，差点忘了。iPhone Duo 也没有操作按钮，但我觉得 Apple 下一代会给 iPhone Duo 加上，并当一个新的卖点。
史上最薄也最重的 iPhone
iPhone Duo 在展开状态下的厚度为 5.2 毫米，相比 iPhone Air 的 5.64 毫米还要再薄 0.4 毫米，是 Apple 有史以来最薄的 iPhone。但这台最薄的 iPhone，也是有史以来 Apple 最重的 iPhone：254 克，超过了半斤，比 iPhone 18 Pro Max 还要重 5 克。
或许 5 克对很多人来说不算大，但对我这种 iPhone Air 用户来说就很夸张了：iPhone Duo 比 iPhone Air 重了 89 克，差不多是 4 节半 5 号电池。
展开之后，充电口在左边
目前市售的大部分折叠屏手机，充电口普遍放在展开后的右侧，但 iPhone Duo 则反过来，把接口在左侧。或许是 Apple 考虑到 Dock、按钮和扬声器放在了右边，再放一个充电口就很拥挤了。
当然这也带来一个好处和坏处。好处是折叠起来之后，USB-C 接口位于上方，比较厚的 USB-C 充电线也能怼得进去；坏处是每次你展开屏幕，线就得跟着跑个半圆。
顺带一提，iPhone Duo 的接口和 Pro 又是一样的 USB 3 10Gb/s，还支持 DisplayPort 输出 4K HDR。
营业厅应该从没有这么 Duo 人来办过 eSIM 卡
由于 iPhone Duo 过于轻薄，因此它和 iPhone Air 一样也只支持 eSIM。
所以不管是一年一换闭眼就买的发烧友，还是为了第一时间尝鲜新形态的追新族，又或者是各类为了评测、体验入手的数码博主，只要是国行 iPhone Duo 用户，大家都会在当地的运营商营业厅里相遇。
很难讲这次的 iPhone Duo 会不会是国内一次 eSIM 的普及风暴。
Duo 了块电池，但充电功率和 18 Pro 略有不同
iPhone 18 Pro 的充电功率再次得到提升，最高很可能可以跑到 60W，15 分钟就能充 50% 的电量，基本赶上了如今国产 Android 设备的入门水平。但翻看下面的小字发现，想要达到这个速度，必须得用支持可调电压供电（AVS）的 60 瓦或更大功率充电头，所以又找到一个买新充电头的理由啦。
相比之下，iPhone Duo 大概是 iPhone 17 系列的水平，20 分钟能充 50% 左右的电量。但与 17 系列只要 40W 以上充电头不同的是，iPhone Duo 也得要 60W 以上的充电头才行，但不用支持 AVS。不过换个角度看，iPhone Duo 里面装着两块电池，充电时两块电池一起充电，20 分钟能充到 50%，其实速度不算差了。
至少比起 iPhone Air 这个 30 分钟只能充 50% 的弟中弟来说，已经算是飞跃了。
没为 Duo 更新的 App，会怎么显示
Android 设备做折叠屏这么多年来，应用适配的情况一直不容乐观。因此你或许也会好奇，那些没给 iPhone Duo 适配的 App 会怎么显示？
Apple 在发布会后更新给开发者的技术讲座视频里给出了答案：没有为 iPhone Duo 更新的 App，Apple 设计了三种兼容模式来过渡。一部分使用旧 SDK，还没适配 iOS 27 的 App，会被限制在一块安全区域内、周围留着黑边。而适配了 iOS 27 的 App，会自动适配大部分的屏幕面积，但右侧的状态栏边缘仍会留白。
只有使用了 iOS 27.1 SDK 开发的 App，才能真正铺满内屏。
今年 4 月，Apple 就已经要求所有提交的新应用必须使用 iOS 26 SDK 构建。相信不用再过很久，Apple 就会把这个要求提升到 iOS 27.1 来适配新的屏幕形态。不得不说，在应用开发和适配这一块，Apple 仍然是旧 App 最严厉的父亲。
那么这时候我就比较想知道，某个绿色软件的适配速度了......
全球官网翻译人员最轻松的一次
这次 iPhone Duo 全球通用的 Slogan 是「Hello, hello。」，且没有任何翻译，日文用也是直接用的 Hello 片假名。唯一有变化的是英语宣传页用了英文标点，而中文宣传页用用了中文标点。
这个 Slogan 或许是来自 2007 年初代 iPhone 那条「Hello」的广告。那时候的 iPhone 只有一个屏幕，因此 Hello 一次就够了。而这次 iPhone Duo 有两块屏幕，所以可以 Hello 两次。
关于 iPhone 18 Pro 系列的那些事
A20 Pro 是 2nm 制程
A20 Pro 也是 Apple 2 纳米制程的处理器。
剩下的信息则在发布会上都有提及，我们也可以简单回顾下。
按照官网的说法，A20 Pro 配备了 6 核 CPU，内存带宽相比 A19 Pro 提升 50%；而全新的 7 核 GPU，图形性能比 A19 Pro 提升最多 40%。神经网络引擎数量也翻倍了，达到了两簇 16 核；散热方面，A20 Pro 借鉴了 M 芯片的封装，内存放在 CPU 旁边，并且直接贴合新一代面积暴涨的均热板。
美版 iPhone 18 Pro 和 18 Pro Max 的基带不是同一颗
国行 iPhone 18 Pro 系列全系使用了 Apple 自研的 C2 基带，并做到了和此前高通基带一样的频段支持。但在美国，iPhone 18 Pro 用的是 Apple 自研的 C2，而 iPhone 18 Pro Max 用的却是依旧是高通。
纯 eSIM 机型的电池还是更大一点
「底大一级压死人」这句话其实也适用于电池容量。上一代 iPhone 17 Pro Max 设计大改后，用了更大的电池，续航明显变好了不少。这次 iPhone 18 Pro Max 的续航又增加了，视频播放时长从 iPhone 17 Pro Max 的 37 小时涨到了如今的 43 小时，再加上快充的加持，这代 iPhone 18 Pro 系列应该基本不会有续航焦虑了。
但由于国行这次依旧还有 SIM 卡槽，也因此续航还是比美版这种纯 eSIM 机型略有缩水。美版 iPhone 18 Pro Max 的视频播放时长比国行还长 2 小时，达到了 45 小时，接近两天的时间。
最丰富的 SIM 卡支持
而说到 SIM 卡槽，在发布会前就有传言称，这次的 iPhone 18 Pro 系列会缩减一个实体 SIM 卡的位置，转而用一张实体 SIM 卡 + 一张 eSIM 来实现双卡双待。但在实际发布后，国行版本的 iPhone 18 Pro 给大家带来了有史以来最丰富的 SIM 卡支持，你可以选择：
- 两张实体 SIM 卡
- 一张实体 SIM 卡 + 一张 eSIM 卡
- 两张 eSIM 卡
这对于经常国际出差或海外留学的朋友来说，确实方便了很多。
关于 Apple Watch 的那些事
S11 的 CPU、GPU、NPU 都衍生自 A20 Pro
Apple Watch 上的那颗 S11 芯片也很值得说道说道。
原因也不难猜，因为 Apple Watch 也支持了 Siri AI（Apple 智能再次最有用的一集），需要运行 Live Rewind、Siri 回顾、实时音乐识别（Pixel：谁叫我）等音频智能新功能。从发布会的原图上看，S11 的 CPU、GPU 和 NPU 设计均衍生自 A20 Pro —— 如果 A20 Pro 是 2nm，那 S11 大概率也是 2nm，世界上第一块戴在手腕上的 2nm 芯片。
而且 MacRumors 发现，S11 搭配的内存也翻倍了，从原来的 2GB 直接跳到了 4GB。考虑到上一代 S10 被普遍认为是 S9 的套壳马甲，某种意义上来说，S10 最多只能算 S9 Pro，而真正的 S10 应该是这次的 S11。
音频智能是这样工作的
针对音频智能的相关功能，Apple 专门发了一份隐私白皮书，里面介绍了一些技术信息和它的工作原理。
首先是 Live Rewind，它只有在双击数码表冠的时候才会激活，并把过去 15 秒的语音内容以文字片段显示在屏幕上。它不会在后台持续转写，默认也不会保存这些文字，同时也不会把语音归属到具体的说话人。而且，它启动时还会向周围的人发出提示音，即使手表处于静音模式或者连着耳机，这个提示音也依然会从 Apple Watch 的扬声器响起，同时屏幕上还会出现全屏动画和麦克风指示器。
而 Siri Recap 则是一个真正能让 Apple Watch 变身为随身 AI 设备的重大更新。它相当于一个全天陪着你的 AI 助理，在你允许的时间和地点里，持续理解日常对话，并生成一些高层次的摘要，方便之后回顾今天聊过什么。
这类 AI 功能也很容易带来隐私方面的问题。对此，Apple 的做法是，在 S11 芯片里提供一个名为 Secure Exclave 的硬件隔离区域。
Apple Watch 采集到的原始音频会直接进入 S11 芯片内部的安全缓冲区，并经过加密发送到配对 iPhone 的 Secure Exclave。数据来到 iPhone 上以后，会先进行语音转写和语义压缩。如果需要最终总结，才会发送到云端 Private Cloud Compute 处理。
Apple 认为，这个功能不是录音，因为在 Apple Watch 上采集并处理后的音频会被立即删除；而且用户也可以随时控制这个功能在什么情况下才打开。至于 Siri Recap 生成的摘要，如果用户没有保存或导出，会在 7 天后自动删除；Live Rewind 的文字片段则会在屏幕熄灭约 30 秒后消失。
不过，这些功能都要等到「今年稍晚」才会以 Beta 形式上线，而且首发只有英文。当然，欧盟和国内用户就接着等吧。
其实有新表盘
这次的发布会其实还给 Apple Watch 带来了一个新表盘，叫 Siri Modular，它以 Siri 为设计中心，最上方是可以调节高度的时间，下方分别是 Siri 建议卡片和三个复杂功能。
你可以选择「时间 + Siri 建议卡片 + 复杂功能」三个一起显示，也可以选择「时间 + Siri 建议卡片 / 复杂功能」两排显示。同时，时间和可以调整字体，其中我个人就很喜欢那个拉长的衬线体时间，很有 Eva 风格的感觉。
如果你是 Apple Watch Ultra 用户，那么新表盘上还有两个独家功能：专属的「Ultra」时间字体和边框选项。
还在预备的 Apple 智能与不知何时来的 Siri AI
Siri AI 本月先上英文，10 月再加五种语言
Siri AI 会随 9 月 14 日的 iOS 27 正式版一起上线，但目前只支持英文。尽管 Apple 表示 10 月会新增语言支持，但也只有法语、日语、韩语、葡萄牙语和西班牙语，没有中文。
而国行 Apple 智能的本地模型虽然已经获得了审批，但目前依然在等待。
Siri AI 有额度，用完了要充钱
Apple 在发布会当天，还发布了一份新的支持文档，进一步解释了 Apple 智能的使用条款、额度和限制。
其中，Siri AI、智能修图工具（包括消除、扩展和空间构图）、图乐园、快捷指令里的 AFM 3 Cloud 与 AFM 3 Cloud Pro 模型，以及在专用云计算中使用 Apple 基础模型的第三方 App，都属于依赖服务器端模型、未来会受到使用额度限制的功能。
但具体限制是多少，Apple 目前还没有公布，只表示额度可能因功能、请求复杂度、系统需求和系统策略等因素而异。达到某项功能的使用上限后，需要等待一段时间才能再次使用。
未来，Apple 智能很可能也会像其它 AI 公司一样，采用「基础额度免费、更多算力付费」的模式。考虑到如今海量的 Apple 设备，这个收入也是不容小觑的。

最终进入决赛圈的是小米 YU7 标准版、特斯拉 Model Y 后驱版，以及理想 i6。
小米 YU7 最大的优势无疑是外观设计。抛开网络上各种「阴阳怪气」不谈，25 万元左右能买到这样一台有着强烈跑车气质的车型，确实很难不让人心动——「25 万的法拉利」谁会不喜欢呢？除此之外，电动前备箱、遍布车内的接口设计以及丰富的磁吸生态配件，也体现了巧妙的小心思。
不过它的后排和后备箱空间相对有限，而当时标准版为了控制成本，在舒适性配置上的取舍比较明显。更重要的是，标准版与 Max 版在驾驶体验上的差异大到让我觉得几乎像两台车。那段时间过热的营销节奏也让我产生了一些顾虑。
特斯拉 Model Y 则拥有我试驾过车型中最出色的驾驶体验。转向、底盘和动力响应都非常成熟，整车有一种「开起来就知道为什么卖得好」的感觉。外观设计我也比较喜欢，尤其是夜晚点亮后的漫反射尾灯，辨识度和高级感都很强。
遗憾的是 Model Y 的舒适性配置相对克制，电池容量和充电速度在当时也不算突出。更现实的问题是，由于工作单位的管理要求，特斯拉无法进入地下车库，这意味着我无法使用单位地下车库里价格优惠且方便的慢充桩，这一点对纯电车型来说体验将大打折扣。
相比之下，理想 i6 反而成为了最大的「意外之喜」。在试驾之前，我原本并没有对它抱有太高期待，但实际体验后我发现它的驾驶质感远远超出了我的预期。与此同时它在舒适性配置上的表现几乎又称得上同价位的越级存在，无论是座椅、静谧性还是乘坐体验，都给人一种明显高于价格的感觉。再加上相对完善的 5C 超充网络，补能体验也让我比较放心。
当然理想 i6 并非没有缺点：它的外观设计一直存在不小的争议，而且当时还面临着较长的交付等待周期。在反复权衡之后我才做出选择。
这也很符合我的性格。作为一个「顾家」的巨蟹座，相比于更张扬、更吸引目光的选择，我最终还是放弃了所谓的「面子」，选择了那个更符合自己实际需求的答案——理想 i6。正如网上那句评价所说：它或许不是把肉摆在最上面的那碗饭，但一定是那个默默把肉埋在饭里的选择。

外观
理想 i6 的外观的确是争议最大的地方。以当下主流审美来看，它多少显得有些超前。流线型的车身设计让它与传统意义上的 SUV 拉开了不小的差距，这也是我选择整体感更强的「黑武士」配色的原因。
就我个人而言，我一直是旅行车的忠实爱好者，因此当 i6 将悬架调至较低状态时，呈现出的车身姿态非常对我的胃口。此外，理想 i6 与 992 代保时捷 911 出自同一位设计师之手，夜晚看到它的尾灯时，我总能感受到一丝独特的德系韵味。
空间表现
得益于四轮四角的设计，相较于传统燃油车，纯电车型少了发动机这一体积庞大的部件，电机所占用的空间也远小于发动机。因此作为一台诞生于纯电平台成熟发展阶段的车型，理想 i6 几乎拥有了传统意义上所有能够提供的增量储物空间：前备箱、后备箱，以及后备箱下方的下沉式储物空间。
后排空间也是它的一大卖点。在不足 5 米的车身尺寸下，后排乘客依然能够在前排调整到正常驾驶坐姿的情况下轻松翘起二郎腿。配合车内大屏，能够获得一个相当舒适的观影环境。
在午休场景下，理想提供了便捷的的主副驾单人床模式，跟随车机指引，将副驾驶头枕拆卸下来后，按照屏幕中的操作指引调整座椅，便能够快速组成一张便捷的单人床。再搭配商城售卖的小憩套装，一次舒适的午休便顺理成章地完成了。也正因如此，拖鞋和眼罩逐渐成了我车上的常驻物品。
NVH
除了底盘质感外，我觉得车辆的隔音能力也是体现高级感的重要因素。就个人体验而言，理想的整体隔音表现可以说是同级别中的第一梯队。双层夹胶玻璃配合车内主动降噪系统能够显著隔绝道路噪音和环境噪音，有时候车内过于安静，不知不觉车速就已经来到了 80 km/h——好吧，有可能是坐了小鹏的我见识短浅了，最新的理想 L8 Livis 的噪音控制还要更上一层楼。
此外，电吸门也让上下车的关门过程变得安静和优雅了许多。最打动我的其实是理想对于各种电机噪音的控制。试驾极氪时，我能比较明显地听到座椅按摩电机工作的声音；在一些其他车型上，按摩气袋充放气时产生的噪音也较为明显。
相比之下，理想 i6 对这类细节的处理更加克制，无论是座椅按摩、后排屏幕的开合，还是座椅调节过程中的电机运转，都尽可能做到了静音，进一步强化了整车的高级感。
行驶质感
此前我也试驾过理想的增程系列车型，整体舒适性确实不错，但依然能够感受到车身尺寸带来的那种「船感」。而理想 i6 的驾驶体验则要运动得多，大车感被削弱了不少。
日常驾驶时我通常会将悬架调低，并把转向和空气悬架都调整到运动模式，试图获得一种接近「瓦罐」旅行车的驾驶质感。在这种设定下，车辆在过弯和变道时对车身侧倾的抑制表现不错。虽然达不到 Model Y 那种极致偏运动的驾驶感受，但偶尔激烈驾驶时依然能给我一些信心。
当然它终究还是一辆理想，当副驾或者后排坐了人，我还是会把所有设置切回舒适模式。即便油门踩到底，加速过程也不会给人突兀的感觉；同时空气悬架对于路面颠簸的过滤也很到位，底盘有一种德国车常见的一体感，经过减速带时没有多余的晃动，和我之前开过的小鹏相比差距还是比较明显的。
舒适性配置
理想 i6 最打动我的还是内部这些舒适性配置。在 25 万元左右的价位，大部分厂商拿出的都是 7 系车型，而理想却选择用 6 系列来参与竞争。横向对比来看，这款车型的舒适性配置的确处于同级领先水平。
下面聊几个让我印象比较深刻的点。
首先是方向盘电动调节。虽然大部分时间车辆的驾驶员相对固定，但电动调节依然能够提升日常体验，例如方便驾驶员上下车时进出座舱。此外它还能与零重力座椅联动，在主驾休息时获得更好的横向空间。
其次是各种五金件的质感。无论是前排门拉手、后排座椅调节按键，还是后备箱内的座椅调节机构，以及空气悬架车身高度调节时的反馈，都能够感受到不错的品质感。
再就是内饰用料。上手能够触碰到的区域基本都有软质材料包裹，座椅标配 Nappa 真皮，同时也配备了舒适性不错的头枕，这些细节都能明显提升车内的豪华感。
后排娱乐屏的屏幕素质也值得一提。窄边框设计配合简洁的 UI 界面，观感非常不错。更重要的是，每块屏幕都可以独立登录不同的音视频账号，这意味着每位乘客都能按照自己的喜好观看内容，互不干扰。
不过不得不说，相关配置依然存在一些提升空间。例如后排中央扶手没有下落阻尼，而我实测最新款理想 L8、L9 都已经具备缓降特性，因此这并非技术上做不到的问题，更像是产品定位带来的取舍。另一个被不少车主诟病的点是前备箱没有配备电吸功能，大部分时候车头区域都比较脏，每次关闭前备箱都需要手动再按压一下，长期使用下来确实会带来一些困扰。
补能与电耗
以 8 月为例，日常我的高速与城区比例大抵相当，动能回收开到低，作为一辆整备质量 2.3 吨的中大型 SUV，有下面这个能耗表现实属不易，这也与相对保守的动力调教与流线型的外观不无关系。
当然，驱动电耗仅仅是参考，对于一款舒适性配置相对较多的车而言，冰箱、哨兵模式、娱乐屏等开关都会影响到实际续航，就个人实际体验而言，充满电显示的续航 525km 基本是可以达到的。
最令我感到体验提升显著的是理想官方的 5C 补能体系。就个人体验而言，在城市环境下，各家品牌的充电桩布局都已经比较完善；但在高速场景下，理想的充电桩数量应该与蔚来并列处于第一梯队。实测在 5C 超充桩的加持下，从 5% 充至 80% 仅需约 10 分钟，峰值功率可达到 500kW 以上，平均功率也能维持在 380kW 左右，这确实是我之前使用小鹏时无法获得的体验。另外即使在 4C 的场站，从 12% 充电到 98% 用时也仅有 22 分钟，峰值功率 273 千瓦，平均功率 218 千瓦，仍旧属于比较优秀的水平。
这样的补能速度刚好适合在服务区短暂休整时完成充电，甚至很多时候，开车前往充电桩所花费的时间都比实际充电时间更长。当充电速度已经卷到这个程度时，我觉得大多数场景下的续航焦虑其实已经得到了解决。
同时理想也在持续扩充自己的超充网络，并逐步将部分 2C 充电桩升级为 5C。个人认为，这种补能网络就像传统燃油车时代的 4S 店体系一样，是新能源汽车品牌不可或缺的重要配套服务，也是用户长期体验的重要组成部分。
辅助驾驶
虽然 L3 的消息目前满天飞，但在现行法律法规下，我国消费者个人能够购买到的车辆，其辅助驾驶能力本质上仍然需要在人类驾驶员监督下使用。
对于采用 Thor-U 芯片的理想 i6 而言，目前已经可以实现车位到车位的辅助驾驶。从「能否实现」的角度来看，这项能力确实已经达到了较高水平，但从实际使用体验来看，其效率与经验丰富的人类驾驶员相比仍有不小差距。
对于封闭道路场景，尤其是高速公路，我已经比较放心地将大部分驾驶工作交给它完成；但在城市道路中，由于存在大量不确定因素，其能力仍有较大的提升空间。我也认为，仅依靠车辆当前的算力和算法能力，许多边界场景在短时间内依然难以被彻底解决。例如不规范驾驶的社会车辆、穿梭车流的外卖骑手、突然横穿马路的工人或老人，以及与导航信息不同步的临时信号灯变化等情况，都会给辅助驾驶系统带来挑战。
这些偶发时间对于驾驶员的惊吓会导致后续使用的信心大大降低。在这些场景下，智驾系统的反应时间和应对能力都是有限的，驾驶员仍然需要随时做好接管准备。
此外，我还发现理想辅助驾驶对于驾驶员是否持续接触方向盘的检测相对较弱。销售人员也提到，即使长时间不扶方向盘，系统往往也不会主动退出，我的实际测试结果基本一致。不过无论系统是否允许这样做，从安全角度出发，你都不应该把自己和他人的生命安全当成儿戏。

Meet the under-35s shaping the future of biotech
They’re designing viruses, reversing the aging process, and saving lives.
Every year, MIT Technology Review puts together a list of some of the brightest and best young minds working across science and technology. Our 35 Innovators Under 35 are the ones to watch—people whose research and technical work stands to shape the future of their fields.
This year, the list includes nine people who are transforming biotech. And this week, I’m going to give you a taste of some of the very cool stuff five of them are working on, which includes lifesaving innovations and groundbreaking “age reversal” tech.
1. Preventing maternal deaths
Let’s start with Paschal Kija, a 28-year-old who has developed a device to treat postpartum hemorrhage—a dangerous birth complication that contributes to around 29% of maternal deaths in his home country, Tanzania. The Mkanda Salama (“Safe Wrap” in Swahili) is easy to use and costs just $70. A study found that it stopped postpartum bleeding in 73% of women within 20 minutes.
2. Making brain electrodes inspired by Japanese art
For decades, scientists have been developing, testing, and implanting brain electrodes. These devices are literally inserted into people’s brains, so while they can help us understand brain activity and treat various neurological disorders, it’s not totally surprising that they can also cause a bit of damage. Xiao Yang, 34, is working on ultra-small electrodes, which she hopes will have less of an impact on surrounding brain tissue. Her electrodes are flexible, too—in fact, they look a lot like actual neurons.
Yang is also creating sheets of electrodes to study brain cells in the lab. Inspired by kirigami—the traditional Japanese art of cutting paper to form three-dimensional shapes—she’s created a sheet of electrodes with a honeycombed structure shaped like a spiral basket. And she’s already using it to study brain cells.
3. Developing an all-new treatment for baby KJ
In 2024, Kyle “KJ” Muldoon Jr. was born with a rare and potentially fatal genetic disorder. Sarah Grandinette was a member of a team that developed an entirely new, personalized treatment for him—a gene-editing therapy essentially designed to correct a genetic misspelling.
Grandinette, who is now 26, created cells with KJ’s genetic variant and used them to screen gene-editing approaches; then she tested potential medicines in mice and monkeys. KJ ultimately got his first dose of the resulting treatment when he was about seven months old. He responded well and was eventually discharged from hospital. He’s “doing pretty great,” she says.
4. Reversing the aging process to treat eye disease
The buzziest tech in longevity right now centers on reprogramming—attempts to rewind the age of cells by resetting them to a more embryonic-like state. In a study published in 2020, Yuancheng (Ryan) Lu (now 34) and his colleagues showed that a reprogramming therapy reversed vision loss in aged, blind mice. Now an almost identical version of that therapy is being tested in people with eye disease. Life Biosciences, the company developing the drug, dosed its first volunteer in June.
5. Using AI to design new viruses
Last year, Samuel King used a generative AI model to come up with new genetic blueprints for bacteriophages—teeny viruses that can infect bacteria. Once he had those blueprints, he printed them out as strands of DNA. In experiments, he found that those AI-designed viruses could create new copies of themselves, burst out of bacterial cells, and infect other nearby bacteria. Viruses aren’t alive, but King, 27, hopes that AI-designed life forms might one day be used to make drugs or soak up pollution.

NSF moves to overhaul funding approach in line with White House priorities
The major funder of basic science has not said how its new initiatives will be funded — but staff worry streamlined approach will further squeeze cash for core sciences.
The US National Science Foundation (NSF) is changing how it funds research grants — and how it decides which ones to fund — to better align with White House priorities, according to a letter released on 10 September.
“NSF is taking decisive action to meet this moment, introducing new and ambitious ideas that capitalize on the changes in the scientific ecosystem to advance our core mission,” says the letter. It is signed by Brian Stone, who is standing in as the NSF’s director.
Since its inception in 1950, the NSF, a major funder of basic research, has solicited proposals on topics informed heavily by the scientific community. The letter describes a shift to a “portfolio-based” approach to making grants that combines traditional “investigator-driven inquiry” with “NSF-directed opportunities”. The letter does not say what the opportunities will be, but states that the NSF will specify objectives but “never the method scientists must use” to achieve them.
Staff members at the agency, who spoke on the condition of anonymity out of fear of retaliation, are concerned that the changes will lead to further cuts for work that has long been core to the agency’s mission: discovery-focused research, led by the curiosity of scientists.
When asked for comment on criticisms of the changes, an NSF spokesperson directed Nature to Stone’s letter.
The letter says that solicitations for grant proposals will be “consolidated” and “simplified”. Calls for proposals will also be designed with a greater focus on advancing “a specific aspect of NSF’s mission”, the letter adds.
Central to the NSF’s portfolio-based approach are four research topics that will receive funding from across the agency’s directorates and will also require “cooperation across disciplines and directorates” the letter says. It names four “Frontier Initiatives”: the Future of Intelligence, Frontier of Quantum Phenomena, Advanced Materials and Matter, and Foundations of Biological Design.
These initiatives are a brainchild of the White House Office of Science and Technology Policy (OSTP), according to earlier reporting by Nature. The letter does not specify how much will be spent on the frontier initiatives, or how they will be funded, but it says that they will “make full use of the agency’s funding mechanisms … including prizes and challenges”. NSF staff have told Nature that some of the money is likely to come out of the US$1 billion in funding that the agency has been holding in a central account instead of allocating it to grants.
Staff members say that the move to fund the frontier initiatives will probably shrink the agency’s core-science funding and divert large sums to White House priorities. “Ordinarily, there would be optimism that these initiatives could further strengthen the agency’s mission,” one staff member says. “The current administration, however, seems intent on undermining science, so naturally there is scepticism about all of this.”

At a time when misinformation is rife and many seem to be questioning scientific evidence, do people really trust scientists? In the United Kingdom, the answer is mostly yes, finds a study led by the Policy Institute at King’s College London and Sense about Science, a charity based in London.
Nearly two-thirds (63%) of 4,262 UK adults surveyed said they trust scientists, giving a score of 7 or higher on a zero to ten scale. Only 5% rated their trust at three or below.
To explore what drives trust and distrust of scientists, the researchers used regression modelling to identify factors most strongly associated with trust. The most influential factors were whether respondents felt that scientists are "on the side of people like them" and whether they thought of scientists as open and transparent. Both outweighed perceptions of scientific expertise.
Previous research has shown that benevolence — the idea that researchers care about society and want to do good — is a core pillar of public trust in science1. Now Bobby Duffy, director of the Policy Institute at King’s College London and one of the authors of the UK study, says that the work reveals that trust in scientists was less associated with scientists being eager to work for the good of society in general (12%) and had more to do with whether they are on the side of people like the respondent (21%).
“In a politically divided society, people become much more interested in, ‘What’s in it for me?’” says Duffy.
Where trust falters
When the researchers delved into specific fields, they found that trust declined for scientists working on vaccines, space and climate (see ‘Pockets of trust’). And more people had more confidence in academics (12%) rather than in scientists working in government (42%) and in private companies (34%). Perhaps unsurprisingly, people with little trust in scientists are more likely to think conspiracy theories about climate change, vaccines and the effects of 5G phone towers are true, says the report.
