Computer use for AI agents: see and operate desktop apps on macOS, Windows, and Linux through the OS accessibility tree.
agent-desktop gives an AI agent computer use without screenshots or pixel matching. It reads the accessibility tree of a desktop app and returns it as JSON, with a ref for every element the agent can act on. The agent clicks or types on a ref, reads the UI again to check the result, and repeats. The loop lives in your agent; agent-desktop has no model inside. It ships as a CLI and a C library.
Snapshots, clipboard reads, screenshots, command output, and debug artifacts can contain private desktop content. Keep them out of public logs and uploads.
npm install -g agent-desktop
agent-desktop status                # platform, permissions, supported surfaces
agent-desktop permissions --guide   # macOS: walks you through the Accessibility grant
Bun, Yarn and pnpm can install the same package. It includes native binaries and platform helpers for x64 and ARM64. For direct execution without a JavaScript launcher, download the matching native archive from GitHub Releases and keep its helper beside the executable.
On macOS and Linux, Homebrew also works: brew install agent-desktop. There is no official Scoop package yet.
The repository no longer maintains a custom Homebrew tap or Scoop bucket.
Release archives and building from source are covered in Installation.
agent-desktop snapshot --app Finder -i      # interactive elements, each with a ref
agent-desktop click @s8f3k2p9:e8            # act on a ref from that snapshot
agent-desktop snapshot --app Finder -i      # observe again to verify
Each command prints one JSON envelope. A trimmed snapshot:
{
  "version": "2.6",
  "ok": true,
  "command": "snapshot",
  "data": {
    "app": "Finder",
    "snapshot_id": "s8f3k2p9",
    "ref_count": 59,
    "complete": true,
    "tree": {
      "role": "window",
      "name": "Downloads",
      "children": [
        { "role": "treeitem", "name": "Documents", "ref_id": "@s8f3k2p9:e8", "available_actions": ["Click"] }
      ]
    }
  }
}
- Refs carry their snapshot id. A bare @e8 fails with INVALID_ARGS.
- If the UI changed, an action returns STALE_REF or AMBIGUOUS_TARGET. Take a new snapshot and use its refs.
- Actions are headless by default: no pointer movement, no focus change. Pass --headed for physical input.
- In PowerShell, quote every ref ('@s8f3k2p9:e8'), because a bare @token is the splatting operator.
The full walkthrough is in the quick start.
Your agent calls the CLI, or the C library in process. Both run the same core, which reaches the OS only through PlatformAdapter. Each binary is built for one OS and talks to that OS's accessibility API.
The binary carries guides that match its version:
agent-desktop skills get desktop      # the loop, refs, verification and retry rules
agent-desktop skills get platform     # what differs on the OS you run on
agent-desktop <command> --help        # flags for one command
Install the skill into an agent harness from skills.sh:
npx skills add https://github.com/vercel-labs/agent-desktop --skill agent-desktop
Or add this to your AGENTS.md:
Use `agent-desktop` to see and operate desktop apps. Before the first use, run
`agent-desktop skills get desktop` and `agent-desktop skills get platform`, and follow them.
Retry a failed command only when error.disposition.retry is safe. See JSON output for the envelope, error codes, and exit codes.
agent-desktop mcp serves every command as an MCP tool over stdio. A tool is named after its command (desktop_snapshot, desktop_click, desktop_session_start), takes that command's arguments, and returns its JSON envelope:
{ "mcpServers": { "agent-desktop": { "command": "agent-desktop", "args": ["mcp"] } } }
Global flags given to mcp, such as --session, --headed or --trace, apply to every call.
agent-desktop has 60 command names, 56 operational commands. The other four (key-down, key-up, mouse-down, mouse-up) refuse to run until a daemon can release a held key or button. Commands documents each one.
Each platform page lists what works headless, what needs --headed, and what refuses.
Each release ships libagent_desktop_ffi, so a program can call agent-desktop in process. See the C library docs.
import ctypes
lib = ctypes.CDLL("./lib/libagent_desktop_ffi.dylib")
lib.ad_adapter_create.restype = ctypes.c_void_p
lib.ad_adapter_destroy.argtypes = [ctypes.c_void_p]
assert lib.ad_init(7) == 0  # AD_RESULT_OK when the header's AD_ABI_VERSION_MAJOR matches the library
adapter = lib.ad_adapter_create()
lib.ad_adapter_destroy(adapter)
Each platform adapter builds only on its own OS, so scope cargo to the host's packages. On macOS:
HOST_PKGS=(-p agent-desktop-core -p agent-desktop-macos -p agent-desktop -p agent-desktop-ffi)
cargo test "${HOST_PKGS[@]}"
cargo clippy "${HOST_PKGS[@]}" --all-targets -- -D warnings
On Windows, use agent-desktop-windows instead of agent-desktop-macos; on Linux, agent-desktop-linux. CONTRIBUTING.md lists every gate.

Kronos is a family of decoder-only foundation models, pre-trained specifically for the "language" of financial markets—K-line sequences. Unlike general-purpose TSFMs, Kronos is designed to handle the unique, high-noise characteristics of financial data. It leverages a novel two-stage framework:
- A specialized tokenizer first quantizes continuous, multi-dimensional K-line data (OHLCV) into hierarchical discrete tokens.
- A large, autoregressive Transformer is then pre-trained on these tokens, enabling it to serve as a unified model for diverse quantitative tasks.

How does Adaptive Dark Mode work?
At the core of Adaptive Dark Mode is the transformation of color. Sometimes colors are simply decorative, while other times they have semantic meaning. Adaptive Dark Mode determines when to invert colors so elements remain visible or when to leave colors unchanged.

- [一眼的熟悉，满眼的惊喜：新款 iPad mini 首发体验](https://sspai.com/post/118263) <sub>11-03 22:00</sub>

<details>
<summary>📄 展开阅读全文（4716 字）</summary>

在 Apple 的产品中，名字里带有「mini」的产品似乎总有些特别。
方方正正的 Mac mini 别看小，但很能装：高性能芯片、丰富的接口，还能时刻在线，它总能安静并可靠地完成各种任务。纤薄小巧的 iPad mini 别看轻，桌面级的性能加上随手可用的便携性，它既是能打发碎片时间的随身屏幕，也是能随时投入专业创作的趁手工具。
也正是这种尺寸与能力之间的反差，让两款产品始终能在各自的产品线中占有一席之地。只是并不稳定的更新节奏，总让偏爱它们的用户格外惦记。好在今年，继全新的 Mac mini 之后，iPad mini 也终于迎来了久违的更新。
一眼的熟悉
新款 iPad mini 的整体轮廓没有发生太大变化，几乎一致的宽高参数，依然是一块可以单手拿住的小尺寸平板电脑，顶部按键继续集成触控 ID，侧边也保留了用于吸附和充电 Apple Pencil Pro 的磁力接点。
虽然宽度和高度的毫厘之差无法令人感知，但在厚度方面可就不一样了。新款 iPad mini 的厚度从 6.3 毫米降到了 5.4 毫米，重量甚至减轻了最高有几乎 40 克之多。
不夸张地说，拿起新旧两代产品的一瞬间，就能感受到这样的尺寸和重量变化带来的差别。
另一个比较明显的变化，是新款产品的屏幕边框收窄了 24%，在机身尺寸基本不变的情况下，屏幕从 8.3 英寸增大到了 8.5 英寸。虽然新款 iPad mini 的边框依然不能算窄，但变化也是一眼就能感知；对于一台经常需要手持的设备来说，我认为保留一定的握持空间不是坏事，单手拿住这台 iPad mini，拇指依然可以自然地落在边框部分，并不会遮挡任何显示内容。
最后是前置镜头，iPad mini 的前置镜头终于在这一代被移到了的机身的长边，与其它 iPad 产品保持一致。对于 iPad 这类形态的产品而言，这样的设计无疑是更合理的，通过智能双面夹等配件将 iPad 横放在桌面，参加视频会议或通话时的画面角度会更加自然，视线也不会明显偏向屏幕一侧。
对了，新款 iPad mini 的智能双面夹在设计和材质方面都有调整。过去的保护盖通过两条折痕被分成三段，折叠后组成一个三角形支架；新款则改用双重面板结构，只在中间保留一条折痕，将保护盖一分为二。虽然折叠结构有了调整，但实际用法没有太大区别，过去支持的各种支架方式，新款基本都能实现。
新的智能双面夹表面也从过去相对光滑的材质换成了与 iPhone 保护壳一样的科技织物，纹理更加明显，手感也多了一点细密的摩擦感。以我使用 iPhone 科技织物保护壳的经验来说，iPad mini 的新款双面夹应该也会更加耐脏，打理起来会省心不少。
你可能会好奇这款双面夹能不能适配旧款 iPad mini，答案是不建议：由于两代机身尺寸存在细微差别，旧款 iPad mini 装上新双面夹后，机身边缘与保护壳会有轻微错位，后置摄像头也无法完全对准开孔。除此之外，从实际吸力来看，新款双面夹正面的磁铁位置似乎也有所调整，用在旧款设备上时吸附会明显偏弱。
满眼的惊喜
如果要选一项最能改变这代 iPad mini 体验的升级，我会毫不犹豫地选择这块 8.5 英寸的 OLED 屏幕。
新款 iPad mini 的屏幕分辨率为 2316 × 1512，依然维持 326 ppi；SDR 最高亮度从上一代的 500 尼特提高到 600 尼特，这样的区别在日常使用中其实不会让你有明显感知，真正拉开差距的还是这款 OLED 屏幕带来的 HDR 显示能力。
上一代 iPad mini 虽然已经能够播放杜比视界、HDR10 和 HLG 等 HDR 内容，但受限于 LCD 面板和最高 500 尼特的亮度，画面仍要经过色调映射，无法完整呈现 HDR 原本的亮度范围。新款 iPad mini 借助全新的超视网膜 XDR 显示屏，显示 HDR 内容时的峰值亮度可以达到 1200 尼特；再加上 OLED 的像素级控光和出色对比度，画面中的灯光、阳光与反射等高光区域能够以更高亮度呈现，黑色背景、电影暗场和照片阴影也终于不再泛着一层灰。
虽然有不少人诟病新款 iPad mini 的屏幕刷新率依然固定在 60Hz，没有支持最高 120Hz 的 ProMotion 自适应刷新率，但刷新率并不是影响动态画面观感的唯一因素。
OLED 的像素响应速度比 LCD 快了一个数量级以上，像素可以更快完成颜色变化，从而显著减少画面移动时产生的拖影。因此，即使刷新率没有变化，在同样的 60Hz 下，新款 iPad mini 在滚动页面和播放动态内容时，画面依然比上一代更加干净、利落，看起来也会更流畅一些。
关于新款 iPad mini 为什么没有支持高刷新率，目前也有一些未经证实的说法。有传闻称，这块面板本身具备 120Hz 的显示能力，只是被 Apple 限制在了 60Hz；另有消息称，新款 iPad mini 使用的是 LTPS OLED，而不是 iPad Pro 上的 LTPO OLED。前者同样可以实现 120Hz，但通常无法像 LTPO 一样，在较大的范围内高效地动态调节刷新率。
如果沿着后一种说法猜测，Apple 或许是不希望用固定的 120Hz 换取更高的功耗，又没有为 iPad mini 配备能够大范围动态调节刷新率的 LTPO 面板。毕竟 iPad Pro 在换用 OLED 时，也同时采用了 LTPO 与双层串联 OLED，在保留 ProMotion 的同时兼顾亮度、功耗和续航。从这个角度看，如果传闻属实，Apple 为 iPad mini 保留 60Hz 的固定刷新率，并不是完全不能理解。
不过，这些说法目前都没有确凿的证据。无论背后的原因是功耗、成本还是产品定位，对于一款起始价格已经突破 5000 档位、又往往要陪伴用户数年的 iPad mini，高刷新率的缺席确实是一个不小的遗憾。
此外，新款 iPad mini 还首次为 256GB 和 512GB 机型提供了纳米纹理玻璃选项。相比减少屏幕反光，我个人更看重标准玻璃通透的观感。iPad mini 虽然是一台经常被带出门的设备，但对我来说，使用场景大多还是高铁、飞机或咖啡店等光线相对可控的环境，真正需要长时间应对户外强光的场景并不多。当然，对于有相关需求的用户而言，多一个选择总是好的。
上手的变化
看完外观和屏幕，接下来再聊聊新款 iPad mini 用起来有哪些不同。
上一代搭载 A17 Pro 的 iPad mini 放到现在依然够用，日常使用时很少会让人觉得力不从心，芯片代际的差异主要还是体现在持续的高负载场景下，比如游戏。
实际使用下来，新款 iPad mini 在高画质游戏中的表现更加稳定。即使将画质、帧率和画面特效全部调至最高，整个游玩过程中也只会偶尔出现短暂掉帧；上一代则会在游玩一段时间后难以始终保持稳定帧率，快速转动视角时，画面的拖动感也更加明显。两代产品在发热方面的差别同样容易感知：上一代产品连续游玩十多分钟后便已经明显发热，新款 iPad mini 游玩二十分钟后仍然只是稍微温热。
与此同时，新款 iPad mini 的统一内存也从上一代的 8GB 增加到了 12GB，内存带宽提升至两倍以上，为游戏、多任务处理和本地 AI 运算留出了更多余量。
我在之前提过，用 iPad mini 玩游戏时手掌很容易盖住两侧的扬声器开孔，这一问题在这一代产品上算是得到了解决：Apple 为 iPad mini 带来了全新的 Acoustic Display 发声结构。
Acoustic Display 将低音单元布置在显示屏两端，高音单元则隐藏在玻璃面板与铝金属机身之间，机身外侧已经完全看不到扬声器开孔。横向玩游戏时，无论朝哪个方向握持，双手都不会再直接挡住声音，也不用为了扬声器刻意调整握姿。
面对这样的新设计，你可能会担心它是否会牺牲原有的音量和音质。经过音乐与游戏场景下的实际对比，我认为上一代 iPad mini 的声音更加明亮、直接，高频轮廓也更加突出，第一耳听起来会稍微更响；新款则加强了中低频，人声和乐器听起来更加厚实，高频也少了一点尖锐感。
在游戏场景中，新款 iPad mini 更加饱满的中低频能让爆炸、碰撞和引擎声多一点分量；上一代突出的高频，则会让脚步、换弹和界面提示音显得更加清晰。从实际听感来看，两者很难简单分出高下。至少可以确定，隐藏式 Acoustic Display 并没有带来明显的音量或音质退步，这一点可以放心。
得益于 Acoustic Display 的隐藏式设计，新款 iPad mini 有了更加密封的机身，防尘与抗水能力也达到了 IP67 级别；取消外露的扬声器开孔之后，机身整体看起来也更加简洁、完整。我也期待 Apple 未来能在更多 iPad，甚至 iPhone 型号上采用这一设计，毕竟在不牺牲音质的前提下减少机身开孔，同时提高防护能力与外观完整性，本身就是一件好事。
最后再说说续航。机身变得更薄之后，新款 iPad mini 的电池容量也从上一代的 19.3 瓦时略微减少到 18.9 瓦时，降低了 2% 左右。
OLED 屏幕理论上能够减少部分场景下的功耗：由于每个像素都能独立发光，显示黑色和暗色内容时，相应像素可以降低亮度甚至完全关闭，因此在深色模式、电影暗场等画面中会比需要常亮背光的 LCD 更加省电。
从结果来看，Apple 给出的标称续航时间与上一代相同。实际使用下来，以阅读、浏览网页和观看视频为主，中间穿插一段时间的游戏，两代产品的续航差距也不算明显。在电池容量略有缩小的情况下，新款依然能够维持相近的续航表现，可以认为 A20 Pro、OLED 屏幕等软硬件变化带来的能效提升，基本弥补了这部分容量差异。
虽然续航表现没有明显变化，但这一代 iPad mini 终于支持了快速充电：搭配 35W 或更高功率的 USB-C 电源适配器，大约 30 分钟最多可以充至 50% 的电量，出门前临时充上一会儿就能换来数小时的使用时间。不过，包装内附带的依然是 20W 电源适配器，想用上这项功能，还是需要另外准备一枚功率更高的充电器。
更好的，也是更贵的
最后说说购买建议。
新款 iPad mini 提供 128GB、256GB 和 512GB 三种容量，无线局域网机型起售价 5499 元，蜂窝网络机型则从 6799 元起。与 2024 年发布的 A17 Pro 版本相比，起售价足足提高了 1500 元。
更微妙的是，目前 11 英寸 iPad Air (M4) 的起售价为 5999 元，只比 iPad mini 贵了 500 元。当然，两款产品的尺寸和使用方式并不相同，不能简单放在一起比较；但如此接近的价格依然意味着，选择 iPad mini 的理由虽然没有改变，但为这份便携性和 OLED 屏幕升级需要付出的预算，已经比以往高出不少。
在过去几年里，我一直把 iPad mini 称作一台「纯粹」的 iPad。对于这一台 iPad mini，也是一样。
对于大部分人而言，iPad mini 依然不是一台必需的设备，它能做的大部分事情，其它设备同样能够完成。因此，我不会仅仅因为更轻更薄，或者更好「看」，就推荐你去购买这台 iPad。但如果你本来就有购买 iPad 的打算，我依然认为 iPad mini 是值得考虑的选择，只要你清楚自己需要一台这样的 iPad。

需要注意的是，卡片＋软磁铁会比较难压，需要使一点力气，裁剪一些冰箱贴后，没有看出对压花器的影响。

Matrix 首页推荐
Matrix 是少数派的写作社区，我们主张分享真实的产品体验，有实用价值的经验与思考。我们会不定期挑选 Matrix 最优质的文章，展示来自用户的最真实的体验和观点。
文章代表作者个人观点，少数派仅对标题和排版略作修改。
前段时间出于某些契机，在GitHub上认识了这样一个有趣的项目，它支持你利用任何刻录光驱与任何光盘在数据区刻录出肉眼可见的图案。
老资历应该一瞬间就能想起来，在光盘上「画图」的技术其实挺早就有了：
- 2002 年雅马哈的 DiscT@2 技术允许在 CD-R 的数据面烧图，但必须使用专用刻录机。
- 2004 年惠普的光雕（LightScribe）和 2005 年雅马哈与富士胶片的闪雕（LabelFlash），允许把图案刻到标签面；老实说挺好看的，但必须使用专用刻录机配专用涂层盘，巨贵，还得手动把盘翻面再刻一次，多花很多时间。
这三个技术很快就寄了，专用盘和光驱陆续停产，现在这些设备都挺贵的。
但这个开源项目 Disc Image Studio 极其炫酷：只需要普通刻录机 + 普通空白 CD、DVD 或单层 BD-R，通过一些算法把图像信息转为数据，再把它写进数据区。放在台灯下看数据面就能看到图案了。
太高雅了，特写此文，同各位分享刻一张图的流程。
大概的原理
为方便大家理解后面的刻录与标定流程，先简单介绍下项目的原理。
光驱在光盘上烧录数据时，激光在盘片上留下微小的坑点（或变色点），两者的反光不同，光驱读到亮暗变化就是 0 和 1。很明显，宏观上，这些坑也可以呈现出光学性质。这就是在数据区刻图的原理。
刻录时，光驱头从中心向外沿一条螺旋轨道走。以 DVD 为例，数据区在内半径 24 mm 到外半径 58 mm 之间。
光驱处理数据时，数据将被切成固定长度的扇区：一个 DVD 扇区约 5.16 mm，全盘固定 2,297,888 个，所以整条轨道的总长度也是固定的。每个扇区在盘面上的位置——半径加角度——由内外半径和轨距（相邻两圈之间的距离）共同决定，这就是地址表。
基于如图演示的这套流程，Disc Image Studio 将最终生成一段数据，刻录上去即呈现出图案。
所以在这套方法里，图像是「一圈一圈印上去」，沿螺旋一路采样铺开的。只要地址表里的内外半径和盘片真实尺寸一致，每个像素就会落在该在的位置。
但这实际上成了最难的一步：光盘尺寸虽有国际标准，但光盘毕竟本不是用来画画的，每个厂家每个型号光盘的真实内外半径与扇区数都是有细微差别的！
差了会怎么样
写这篇文章的主要目的就是教大家如何计算标定每个型号光盘的真实物理参数，所以让我们先看看当参数不准确时，会发生什么。
地址表是按软件以为的半径算的。盘片的真实内外半径只要差一点，同一个扇区实际落下的角度，就会和软件预期差一点；偏差不断累积，越靠外错得越多。
沿用第一节我们展示的标准图案，这套数据生成时采用的参数是内半径 24 mm、外半径 58 mm。现在我们分别模拟一张内半径实际情况为 24.002 mm 和 24.05 mm的光盘，看看印上去会呈现怎样的图案：
按 DVD 的螺旋几何估算，内半径差 0.002 mm 时，外圈累计的角度偏差约为 1.1 圈；差 0.05 mm 时约为 28 圈。
所以接下来就进入我们正式的印刷教学了。
最省事的办法
实话实说，没有经验，初次标定需要花上几天，报废 10 ~ 30 张盘。
所以如果你不打算在标定上花时间，只是想刻几张玩玩或者送朋友，最简单的做法是买作者已经标定过的型号。软件内置了几个实测过的预设参数，新建工程时直接选就行了：
- DVD：Verbatim DVD-R AZO（43533）
- CD：铼德医疗水蓝盘、Verbatim CD-R AZO（43438）
- 蓝光：铼德 BD-R 10x、Verbatim BD-R（64099）
买盘时务必认准型号、产品编号！同一个品牌的不同型号、不同批次，参数不一定相同。就算你确保买对了，也建议先刻一张测试图看看效果。
手工标定-粗调
如果你下定决心想自己标定自己手上的盘，那就开始吧！
做第一张标定图案并刻录
这张图只用来观察，好不好看无所谓，主要是要方便辨认。
- 贴近外缘：图案放在靠外的位置。偏差从内圈开始积累，到外圈最大，放在外面容易看出来；
- 径向要长：每条黑线从靠外处向里延伸一段，以方便看出被拧弯的弧度；
- 在圆周方向铺开一部分：一组线沿盘面外缘排开，才能容易看出螺纹是顺时针还是逆时针，判断该往哪边调；
- 黑白分明、间距固定：边缘要清楚，方便看。
前文的示例用了一组从靠外处向里伸的黑色短横条，建议你就用它。把这张图放进工程，用当前参数刻一张。
刻录速度选一个固定值，比如「自动（最低速率，推荐）」，之后尽量每次都用这一个速度不要变。理论上速度不影响结果，但还是不要引入新的变量为好了。
看盘面上是什么状态
放到台灯下观察最方便。
- 看不出任何东西：参数差得太多了，把现有参数 ±0.5 碰运气吧。但这种情况理论上还是不会发生的。
- 能看到很密的螺纹，类似上文的相差 0.05mm 的演示：往下看。
- 图案基本可以辨认，只有轻微弯曲，类似上文的相差 0.002mm 的演示：跳到第五节，用智能辅助标定。
差得远时：先蒙方向
螺纹密到看不出图案的时候，相当无力。这时我们只有一个目标：让螺纹变松。
- 在工程设置里把内半径往一个方向改一个明显的量，比如 0.1 或 0.05 mm，保存后重新生成镜像、再刻一张；
- 盘面比上一张疏一点、开始能看出图案，说明方向对了；
- 如果更密，说明方向反了，往另一边走。
方向确定之后，每次把改动量减半：0.025 → 0.01 → 0.005 → 0.002 → 0.001。到小数点后三四位就够了，跳转第五节。
说白了就是二分法！
全程只改一个参数就行，后续的精细标定要等到第五节。我个人的习惯是只修改内半径。
经验之谈：
- 改完参数记得保存，要不然刻录用的是旧参数。
- 得把每次的参数和盘面表现拍照记下来，因为等你刻到七八张的时候，就分不清哪张是哪张了。
等到螺纹不算太密，能看出大约只绕了八九圈的时候，就可以进下一步了。
在预览页把螺旋「拟合」上去
打开左侧的预览页，确认上方选的是「设计投影」（预览用的就是设计页的合成图），然后展开左边面板里的实测参数与预览精度（高级）。
这里的「内半径、外半径」，填的是你猜测的盘片真实尺寸。右边的预览会按这个猜测重新投影，显示「如果盘片真的是这样，刻出来会是什么样」。
所以我们现在需要反向拟合，反复改半径，直到预览里的原本方正的形状与实际上的螺旋形状、方向和疏密基本一致。
（DVD的三次轨距参数不用理会，这是第五节的内容）
对得差不多以后，继续按「减半」的节奏微调，直到预览和盘面基本重合。
把数字抄回工程
同上文一样，这一步容易忘。预览里的实测参数只影响预览，不会改变刻录。 刻录用的始终是工程自己的参数。
所以对上了以后：
- 点预览页里的当前工程参数 → 编辑…；
- 把半径改成刚刚对上的数值；
- Ctrl-S 保存工程，重新生成镜像或重新刻录。
这次盘的螺纹应该会明显变疏。
要有心理准备
第一次不熟，刻掉二十多张盘是正常的。理解了「预览对应盘面」这一层关系以后，一般 5 到 10 张就行。
辅助标定-精调
当图案已经呈现出来，但是「略有扭曲」，自己对参数也很难对了。这时就可以用软件自带的辅助标定，你只需要拍一张照，它可以利用高雅的算法来算。
这个流程分成 3 步，如图，软件里已经分好了。
第 1 步：生成标定盘
点从当前参数新建标靶，得到一个由九个同心圆和十字线组成的图案。然后进行刻录。
第 2 步：透视与镜头畸变矫正
在台灯下拍一张照。
- 点导入盘片照片，选择盘型；
- 把两组控制点分别拖到盘片实体外缘和实体内缘，就是说你手摸的到的那个边界；
3. 点计算矫正，软件将通过计算矫正透视与镜头畸变。
4.确认没问题就点确认矫正，开始描线。
第 3 步：描曲线并反推
- 沿着一条清楚的径向线，由内向外均匀打点，建议打16个以上；
- 点反推参数，程序会给出几个候选；
- 选候选，看照片上叠出来的橙色预测线：它应该和你描的整条线比较吻合。特别要检查两个点之间有没有多绕一圈；
4.勾选「已对照整条曲线，形状与绕圈一致」，再点应用标定参数。
随后，这套新的参数将会被自动保存到工程上，软件界面左上角工程头部会出现「参数已更新」的提示以及一个炫酷的特效。记得保存工程，然后重新反复进行上面的三步，大概一两次就大功告成了。
常见问题
Q1: 辅助标定，只有一圈圈同心圆，一条线都看不到：
A1: 参数差得太多，导致十字线被扭曲太多，看不清了。回到第四节粗调吧。
Q2: 刻出来盘面完全一样：
A2: 多半没保存，或者用的还是旧镜像。确认工程参数、导出时间和文件路径。
Q3: 能用 ImgBurn、cdrecord 这些软件刻吗？
A3: 可以。导出的 ISO、WAV＋CUE、RAW 都是通用格式。个别软件处理方式不同，盘面可能出现重影，但标定的参数仍然是准的。最好还是用软件内自带的即时刻录。
Q4:「抖动强度」是什么？
A4: 设计页右侧「影调」里的一个参数，可以理解成黑白点的分布强度，类似对比度。
Q5: DVD-R 和 DVD+R 有区别吗？
A5: 和标定无关。软件里内置的威宝43533 是 DVD-R。
Q6: 必须用某种特定的光驱吗？
A6: 不用。只要是能刻录的光驱都可以，标定和盘片有关，和光驱型号无关。
Q7: 8 cm 小盘能用吗？
A7: 能。辅助标定时记得选「小光盘 · 8 cm」。
Q8: 即时刻录失败：
A8: 如果是已经等待半天，数据已经写入，在最终清理缓存的阶段报错，那不用理会，这是已知bug。如果是一开始就报错，检查光驱连接，盘片是否为空等问题。

Borrowing from disciplines like economics could help AI safety researchers control AI models, even if they don’t understand them.
A new approach known as “reverse game theory” aims to control powerful AI models by designing systems that incentivize them to stick to the rules.
As AI models become more capable, safety researchers are scrambling to ensure they are “aligned” with human desires—to make sure, in other words, that rogue agents don’t break the law, hack into unauthorized servers, or release poison gas into major cities and kill us all.
Until now, this work has mostly focused on trying to peer into an AI’s “brain” to understand what it is “thinking,” or training models to hew to values that we hold dear. Claude, for instance, has its constitution—a sort of moral code.
The trouble is, these techniques don’t seem to work particularly well: Models have been shown to deliberately underperform on tests, hide their intentions, and mislead their evaluators.
Now some alignment researchers believe that reverse game theory, also known as mechanism design, might get better results. Where game theory tries to predict how rational actors will behave when given a particular set of rules, reverse game theory attempts to design rules that will elicit the kinds of behavior we want to encourage.
An example of mechanism design in the real world might be the classic strategy for splitting a piece of cake in two: One person cuts the cake and the other gets the first choice of pieces. This incentivizes the cutter to make the pieces as even as possible. Other examples include surge pricing in ride-hailing apps, which encourages drivers to be available at busy times, and second-price auctions, where the winning bidder pays the price of the second-highest bid instead of the highest. Platforms use these auctions to sell online advertising because they encourage buyers to bid close to the maximum they are willing to pay.
In AI, mechanism design starts from the premise that we may never be able to understand enough about the internal workings of frontier models to make sure they are aligned. This means we should design mechanisms that incentivize agents to behave in ways that we want, regardless of what’s actually going on under the hood.
A recent preprint paper by Stephen Morris, an economist at MIT, along with colleagues from Yale and Columbia suggested some potential mechanisms that could stop agents from “sandbagging” tests (pretending to be worse than they actually are—for example, to avoid triggering safety mechanisms).
Instead of being rewarded only for how well it does on a test, a model could be rewarded for how well its answers predict what a second model will say. Deliberately playing dumb becomes a losing bet. “AI agents have a very good understanding of what other AI agents can achieve,” Morris says. “So it does seem like a context where this cross-checking could work more practically.
The paper also suggests pitting agents against each other, creating a competitive dynamic that incentivizes them to perform their best, or pairing agents that are known to be biased in opposite directions and rewarding them depending on how closely their outputs match, thus incentivizing them to reach an optimal answer.
A second approach, as envisioned by Elad Hazan, a professor of computer science at Princeton, is to design mechanisms that take inspiration from the ways human society keeps people “aligned”: social norms, the justice system, the monetary incentives of free-market capitalism. “We want to align superintelligent AI,” he says. “Why don’t we first talk about humans? How do we align humans?”
Hazan’s suggested mechanism involves having AI models take turns as either “solvers” that tackle problems or “auditors” that check the others’ work. “One agent acts like law enforcement; the other agent acts like the citizen,” he says.
During training, the models are rewarded depending on outcomes: Solvers that get caught cheating are punished, but so are auditors that fail to catch the cheaters. In situations where there’s a disagreement between auditors and solvers, the case can be sent to “trial”—perhaps a human expert will decide who is right.
There is, Hazan admits, a risk that agents will collude with each other—as auditors have colluded with the businesses they’re meant to be auditing, or corrupt police officers have colluded with criminals. But that problem can be solved by rewarding the auditors well enough, so that being caught isn’t worth the risk (a lot easier in the world of AI training than the real one, where money for police salaries is tight), and by auditing the auditors using techniques akin to employing mystery shoppers.
Hazan points to Nobel Prize–winning work by the economist Gary Becker, who introduced the idea of the “rational offender” in the 1960s. Criminals don’t break the law because they’re inherently bad people, he said. Instead, they do it when it’s the most rational choice given the incentives on offer. Crime makes sense only when the proceeds outweigh the potential punishment.
Alignment shouldn’t be thought of as a property of a model, he argues, but as a descriptor of its behavior at a particular moment. “You are, like, a nice person,” he says. “Are you aligned? I don’t know. Probably you are aligned most of the time, but there could be a situation where you’re not.”
