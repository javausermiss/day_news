The rule was never "fewest tokens." It is: write only what the task needs, and never cut validation, error handling, security, or accessibility. Lower cost and latency are a side effect on the models that follow the ladder; a terse reasoning model that spends thinking tokens deliberating the rungs can go the other way (on GPT-5.5 it does).
Before writing code, the agent stops at the first rung that holds:
1. Does this need to exist?   → no: skip it (YAGNI)
2. Already in this codebase?  → reuse it, don't rewrite
3. Stdlib does it?            → use it
4. Native platform feature?   → use it
5. Installed dependency?      → use it
6. One line?                  → one line
7. Only then: the minimum that works
The ladder runs after it understands the problem, not instead of it: it reads the code the change touches and traces the real flow before picking a rung. Lazy about the solution, never about reading.

This will be a quick tutorial on how to configure an Exit Node for the Tor Network. Doing this comes with some inherent risks for the operator but exit nodes are essential for bridging Tor with the ‘clear net’. Without exit nodes, anyone suffering from ISP filtering or those not wishing to have their Internet activity logged (BBC Article) couldn’t utilise Tor to access the Internet.
Unlike bridges, exit nodes (and normal relays) are publicly known devices, for which their IP address and configuration is available for anyone to see. They effectively make the final connection to the destination on behalf of the originating (anonymous) client. The Tor network is drastically short of exit nodes, but for good reason. Because they are the final hop in the chain, they will be making hundreds of outbound connections to whatever website or service Tor users request. It is therefore easy for the powers who be to blame an exit node operator for ‘doing bad things’ when in fact their node is merely participating in a network, much like a traditional router would in any network. Anyway, assuming you have balls of steel and willing to run an exit node I’ll take a look at how to do this with least hassle as possible.
Before we begin, let me make it clear running this from home is possibly dangerous, due to harassment from ISPs and the powers that be. Although you are not breaking any law by doing this you are acting as the exit point for Tor traffic and you have no control over what any of the 2.5 million Tor users across the world are going to be doing. If you do experience harassment, stay calm and know you have done nothing wrong. There is lots of information out there to help you if required.
Another issue you may face is one of reputation. Some websites block exit nodes and others make Captcha a requirement (such as cloudflare CDN & Google if it sees lots of traffic).
First up lets assume you have a working Linux machine, I’ll go with Ubuntu 14.04 (Trusty). Secondly lets assume you are NAT’ed behind a bog standard router.
We need to install tor and tor-arm. To do we need to add the Tor repos:
echo 'deb http://deb.torproject.org/torproject.org trusty main' >> /etc/apt/sources.list
echo 'deb-src http://deb.torproject.org/torproject.org trusty main' >> /etc/apt/sources.list
Next, install the GPG keys for the repo:
gpg --keyserver keys.gnupg.net --recv 886DDD89
gpg --export A3C4F0F979CAA22CDBA8F512EE8CBC9E886DDD89 | sudo apt-key add -
Now install tor, tor-arm, curl, vnstat, nginx and socat:
apt-get update
apt-get install tor tor-arm vnstat vnstati nginx curl socat
Weyhey, Tor is installed. By default it acts as a client so we need to make it into an exit node.
Replace the contents of /etc/tor/torrc with a basic relay configuration.
curl -o /etc/tor/torrc https://madpsy.uk/wp-content/uploads/2015/11/torrc.txt
The sample configuration looks like this:
ORPort 127.0.0.1:9001 NoAdvertise
ORPort 443 NoListen
DirPort 9030
Nickname TorExit
RelayBandwidthRate 100 KB
RelayBandwidthBurst 100 KB
ContactInfo [email protected]
DisableDebuggerAttachment 0
ExitPolicy accept *:20-23     # FTP, SSH, telnet
...
...
ExitPolicy reject *:*
Edit /etc/tor/torrc and set your email address next to ‘ContactInfo’.
You may also wish to set ‘RelayBandwidthRate’ and ‘RelayBandwidthBurst’ to something else, depending on your Internet connection speed. The example value is 100 KB (Kilobytes Per Second) which is fine for a typical ADSL broadband connection. You will notice ‘DirPort’ is also set, enabling this node as a Directory Server – remove the line if you don’t want that.
Next, we need to run socat to redirect port 443 traffic to localhost port 9001. This is because a useful Entry Guard (the relay will accept incoming connections as well as being an exit node) needs to run on a port which is likely to be available for every Tor user. Port 443 is HTTPS so a sensible choice. The problem is Tor doesn’t run as root and will be denied permission when trying to bind to port 443. For this reason it’s bound to 9001 locally and we will redirect traffic using ‘socat’.
To run socat:

Can AI design circuit boards yet?
OpenAI showed GPT-6 Astra working in KiCad. We have been building a way to measure whether the circuits that come out of these models are any good.
We got pretty excited yesterday when OpenAI put a demo of GPT-6 Astra working on a circuit board in KiCad on the front page of its launch post. It is cool to see electronics show up in a major model release like this.
We are obviously still some distance from asking an AI to build an entire phone in one prompt. The demo does raise a question we have been thinking about for a while, though: how do we measure whether the electronics an AI produces are actually any good?
The models know a surprising amount about electronics
Our experience has been that current models know much more about electronics than their output in conventional design tools tends to show. They have read textbooks, datasheets, application notes and a lot of code.
You can have an agent operate a graphical CAD tool, but it spends a lot of time clicking around and keeping track of what is on screen. A lot of its context consists of coordinates, menus and application state.
EEBench uses atopile instead. The circuit lives in declarative code, so the agent can work directly on components, connections and electrical constraints. It can change the design, build it, run a simulation and inspect what failed without leaving the project.
This has worked much better for us than asking a model to draw lines in a GUI. It also means the benchmark can spend less time testing computer use and more time testing electronics.
The real world is messy
One of the public tasks is based on a residential energy meter. When its 5 V supply disappears, the circuit has to keep the processor alive for another 20 ms so it can save the accumulated reading. The protected rail must stay above the processor's 3.0 V brownout threshold during that window.
Most models intuitively jump to the right base conclusion: add a capacitor.
A real capacitor makes the task more interesting. A ceramic part may provide much less than its advertised capacitance once it has voltage across it. Parts have tolerances. Adding more capacitance costs more, takes up space and makes the rail slower to recharge when the power returns. A design that works with nominal values can fail with the parts that arrive.
EEBench cuts the input power in simulation and measures what happens. It checks the voltage throughout the outage, the effective capacitance at the operating point, the recovery after power returns and the limits on package, dielectric, voltage rating and cost.
The meter is one of the easier tasks. In a harder analog task, the agent may have to synthesize a multiple-feedback low-pass filter around an op-amp, solve the resistor and capacitor ratios for the required poles, and keep its gain, cutoff frequency and Q inside their limits after every component is pushed to a worst-case tolerance corner. The harness rebuilds the SPICE deck for those corners, runs the AC and transient captures, binds measurements to named probes, and records each result against its lower and upper specification limits.
But getting the equations right is only part of electronics engineering. EEBench uses real manufacturer parts, with specifications extracted from their datasheets and carried into the SPICE model. The agent has to find a combination that works across those tolerance corners while also choosing parts that exist, can be ordered and are reasonably priced for the product. That trade-off between electrical performance, cost and supply is much closer to designing real hardware than picking ideal values from a textbook.
This is the part we find most interesting, because it is what electrical engineering eventually boils down to, just like every other engineering discipline: trade-offs.
How the grading works
EEBench checks are fully deterministic. It builds the submitted design, constructs the circuit graph and bill of materials, and runs a set of SPICE simulations and design checks. Each requirement produces a measurement with a limit.
For the energy-meter task, the harness measures the protected rail while the input drops out and returns. Other tasks measure gain, thresholds, ripple, transient response and behavior at component-tolerance corners. The technical score is combined with cost efficiency against a reference bill of materials. Cost only helps once the circuit works.
This is similar to giving a coding agent a compiler and tests, except the tests are measuring voltages and component behavior..
EEBench V1 covers analog and digital design through simulation. It does not yet tell us whether a model can lay out, manufacture and bring up a complete product. We want to add those parts later. The current benchmark concentrates on the requirements, design and verification loop because that is where we can already grade useful engineering work objectively. The full methodology and sample result explorer are public.
What we are seeing on the leaderboard
The September 1 results are encouraging. Claude Opus 5 scored 61.6% across the 13 tasks in EEBench V1. Grok 4.6 came second at 57.1%, just ahead of Claude Fable 5.1 at 56.4%. A few months ago we would not have expected models to do this well.
There was another result we were especially happy to see: xAI included EEBench in the Grok 4.6 model card. It appears in the section on âengineering acceleration,â alongside evaluations for 3D modeling and parametric CAD. Their published run put Grok 4.6 at 60.0% with xhigh reasoning effort. Seeing a frontier lab use EEBench to describe a new model's engineering ability makes us think this is becoming a category people care about.
Anthropic's models have consistently done well in this environment. Grok's rise is also interesting. In its Grok 4.6 launch post, xAI says the model received high-quality engineering data and RL training in domain-specific environments including computer-aided design. The front line is being turned into a place to train AI models, and right now it’s effectively a regulation-free zone.
Battlefields in Ukraine are littered with the remnants of drones, which are now firmly established as a critical weapon of modern warfare. But behind all that wreckage, there’s a new gold mine for the defense sector. The data drones generate will far outlast the wars in which they are used to fight, increasingly becoming part of the AI architecture that shapes even civilian life.
For every flight, unmanned systems collect thousands of points of data, from images and video to controller inputs. Together, those records show how a machine and a person responded to constantly shifting circumstances.
Ukraine has now begun converting that experience into a resource. Its Ministry of Defense announced in January that it would make millions of data points gathered during tens of thousands of drone flights available to both military contractors and commercial companies, and since then more than 100 companies and the UK government have gained access.
For a country at war, it’s a quick way to attract funding and partnerships. But this step turns the front line into an active site of model training, taking advantage of how the chaos of war creates conditions that AI companies struggle to reproduce on their own.
Other countries and battlefields are likely to follow Ukraine’s lead, but the responsibility for governing this new industry cannot fall solely on a country fighting for its survival. That legal vacuum has to be filled together by the countries and companies involved in this industry’s development.
Explosive growth
Ukraine’s battlefields are not the first to produce records used to train and develop models: American drones over Syria and Yemen collected data that informed the first generation of semiautonomous military hardware in the late 2010s.
The difference now is that access to that data is being used to develop a wider ecosystem. And the financial value to defense firms is immense: Battlefield data offers large volumes of machine experience gathered under conditions that no laboratory can produce.
That’s because the data that’s most valuable for training AI models comes from exceptions: the moment visibility disappears, a signal jams, or a human operator improvises. AI companies spend years and enormous sums trying to capture enough of these moments to make their models more robust. But war produces them at a frequency controlled testing cannot match.
This constantly changing terrain is what makes drone data valuable far beyond the battlefield. A commercial drone used for delivery or remote sensing may never encounter artillery fire, but it must still operate with incomplete information in a world where people behave unpredictably. The same problem is compressed by war into a much shorter timeline.
Processed and matched against records of what its operator was doing, that data turns operational records into training sets. Combat becomes a commercial asset.
Many conflicts have already seen this training loop happen as drone footage feeds subsequent generations of military technology, and the market is set to grow. Enabled Intelligence, an American company that specializes in processing data to become usable in AI training, says it has already made more than half a million hours of Ukrainian drone footage available to feed into the next round of models, advertising possible uses in both military and commercial systems.
Closing the data loop
Many of the drones that now define our modern age of warfare began as civilian technology. But they’ve recently been turbocharged by new, commercially available AI systems, which allow cheap machines to operate autonomously—either individually or as a flock—as the environment changes around them. Each flight then creates a record of what the system encountered.
The resulting data is critical. The controlled lab environments usually developed to train these autonomous systems can approximate failure but are no match for the live conditions of a battlefield with very real risks. Military intelligence programs have held data generated by sensor-heavy systems like Predator and Reaper drones for nearly a decade through programs like Project Maven, but access remained entirely within the defense world. The data generated was available only through restricted, classified channels for the sole purpose of developing new weapons systems that would feed back into the same military that produced the data in the first place. That experience is now being shared to a much broader development network.
The loop now closes. Commercial technologies adapted for the battlefield are generating data that can flow back into the industries from which they came, becoming part of the data infrastructure relied on by governments and the private sector alike.

开学季
少数派的读者中有不少学生朋友，而对这个暑假之后即将进入大学的读者来说，接下来摆在眼前的可能是新的城市、新的生活环境和新朋友，以及更多可以自由安排的时间用来学习、探索。
因此和往年一样，少数派也将整理一系列围绕开学季这个话题的内容与资源，不管你是打算为自己挑选一台好设备、好工具，还是投身知识与书本、发展一门新爱好、充实自己的大学生活，这些文章都能为你提供一些参考和帮助。
新学期开始，除了调整作息、适应课程表，还有一些每天都会遇到的小麻烦，叫自己起床、确认今天上第几周的课、自动收作业、统计谁没交，这些看起来琐碎的事情本身并不难，麻烦的是经常要重复的做，而这恰好是快捷指令最适合解决的问题。
01｜动起来才能关闭的闹钟
刚开学最难的事情之一，大概就是把已经放飞的作息重新调整回来。
快捷指令里有一个比较有意思的操作 —— 获取体能活动。
它可以获取设备当前检测到的活动状态，例如静止、步行、跑步、骑车、在静止或移动的车内。还有与已知模式不匹配的移动中。
这个功能非常有用，可以通过当前不同的活动状态判断场景决定下一步要做什么。例如连接蓝牙耳机时等待几秒，判断在步行还是跑步，选择播放舒缓还是激昂的音乐。
虽然 iOS 26 已经把闹钟的关闭方式从按钮改成了滑动，但对于一个睡意缠身的人来说，滑一下依然不是什么困难的事情。
所以可以利用「闹钟」自动化做一个简单的判断：
闹钟被关闭或推迟之后，自动获取当前的体能活动。
如果设备仍然处于静止状态，就认为：
大概率还没真正起床。
这时候快捷指令可以继续生成多个闹钟。
直到某次关闭闹钟后，检测到设备已经开始移动，认为这次起床判断通过，再删除后续所有的标签为「起床」的闹钟。这样就无法简单地躺在床上随手把闹钟全部关掉了。
如果觉得在床上移动身体不方便，也可以通过摇一摇手机。
现在闹钟已经改成滑动关闭，为了避免摇手机时直接把手机甩出去，可以考虑两只手配合，一只手摇手机，另一只手滑动关闭闹钟 ：）
不过实际用了几次之后，我还是觉得：
相信科学，相信生物钟。
于是怒删自动化。
如果是在宿舍使用，需要考虑环境问题，关闭闹钟铃声，只保留振动提醒，避免每天早上把整个宿舍的人一起叫醒。
02｜开学第几周？让快捷指令帮你算
刚开学还有一个很容易搞混的问题：
这周到底是第几周？
尤其是学校的课表往往并不是简单地每周重复。
第 1 周和第 2 周可能不同，单双周课程也可能完全不同。如果把整个学期的课程都放进日历，就需要根据当前日期判断现在究竟处于开学第几周。
这个也可以交给快捷指令。
只需要预先设置好开学日期，然后通过「获取日期之间的时长」等操作计算当前日期与开学日期之间相差多少周，就可以得到当前的教学周。
例如：开学日 → 第 1 周
间隔 7 天 → 第 2 周
间隔 14 天 → 第 3 周
这里需要注意一点，不同学校计算教学周的方式不同，可以根据具体情况进行修改。
03｜自动收作业
不管作为老师还是学生，收作业看起来很简单，真正做起来却非常琐碎：
收到一个人的作业 → 保存附件 → 再收到一个 → 继续保存 → 统计人数 → 找出没交的人 → 催交 → 最后把全部作业整理、压缩，再发给老师。
如果一个班有几十个人，这些操作重复几十次之后，工作量还是相当可观的。而且作业这种事情还有一个特点，它并不是一次性完成的，而是在一段时间内陆续收到。不光是保存一份文件的事，而是不断重复同样的动作，并且还要记得最后检查有没有遗漏。
所以可以用快捷指令把整个流程串起来。
自动收集邮件附件
设置一个邮件自动化，筛选主题中符合条件的作业邮件。
每当收到新的作业邮件：
- 获取邮件附件
- 将附件保存到指定的「作业」文件夹
- 重新统计作业文件夹中的文件数量
例如班级有 30 人，当文件数量达到 30 个时，就可以认为：作业已经基本收齐这时候可以自动压缩整个作业文件夹，并发送通知：
作业已经收集完毕。
甚至还可以继续自动把压缩包发送给老师。
不过这里目前自动发送邮件操作存在 bug，只能打开显示编写表单，手动点击一次发送，无法完全做到后台无感发送。
如果设备处于锁屏状态，还会出现邮件发送表单无法正常打开导致指令运行失败。
所以暂时在实际使用过程中，将发送邮件去除，只保留作业收齐的通知，单独编写一个发送邮件的指令，手动运行一次。
自动化运行失败兜底
这里还有一个容易被忽略的问题。快捷指令的自动化不是百分百可靠，网络、系统状态、文件读写，会因为各种各样的原因运行延迟或失败。
假设班级有 30 人，现在作业文件夹里已经有 29 个文件。
这时候不能直接认为：
还有 1 个人没交。
因为也可能是已经收到了 30 封邮件，但其中某一次自动化运行失败，导致某个附件没有成功保存。
所以可以在接近班级人数的时候增加一次校验。
当作业文件夹中的文件数量与班级人数接近时，再次去查找主题符合条件的作业邮件数量。
然后比较作业邮件的附件与作业文件夹中的文件数量（图中使用的「否则如果」是iOS 27新增加的操作，可以在否则中嵌套一个如果替代）。
如果两者数量不一致，就说明可能存在附件没有成功保存的情况。
这时候可以重新获取这些邮件的附件，并再次保存到作业文件夹，同时打开「如果文件存在则覆盖」，避免保存成功的作业文件重复保存。
这里也有一个快捷指令的bug，当压缩包的名称为中文时，重新保存文件会导致压缩包名称乱码，可以获取附件名称，找出谁的作业保存失败，手动操作。
如果两个数量一致，就说明之前的指令流程基本运行正常。
这时候还剩下最后一个问题：
到底是谁还没交？
自动找出没交作业的人
在文本中储存全班的人员名称，或使用文件和iOS 27新增的储存操作。
先将全班人员姓名拆分成列表，然后逐个判断：
这个人的名字，是否出现在作业文件夹中的文件名里？
如果包含：
→ 已交，不处理。
如果不包含：
→ 则为未交作业人员。这时候通过微信逐个提醒。
微信发送操作的收件人，是你给联系人的微信备注。并且不是普通的文本，而需要联系人、电话号码或者电子邮件类型。直接传入文本会提示快捷指令无法将文本转换成联系人、电话号码或电子邮件，所以这里可以采用一个非常规办法：
先把文本强制转换成电话号码类型，再传给发送微信的操作。
这样就可以绕过这个限制。
当然，这个部分也完全可以单独做成一个快捷指令。
后期不需要每收到一份作业邮件就提醒一次，而是设置一个时间自动化：
距离作业截止时间还有一段时间 → 自动检查作业是否交齐 → 找出未交人员 → 发送提醒
这样整体流程会更加合理，也能减少自动化频繁运行。
一个容易踩坑的地方
如果设备版本为 iOS 27 之前的系统，制作这种自动化，还需要注意一个比较特殊的问题。
iOS 27之前的版本自动化和快捷指令本身是分离的。在自动化中直接编写指令步骤非常不方便维护。
所以一般的流程是：
先把完整的快捷指令写好 → 再创建自动化 → 让自动化负责运行这个快捷指令
这样维护起来会方便很多。
但涉及「收到邮件」「收到信息」这种 自动化本身会产生输入内容 的场景，就会遇到一个特殊的问题。
例如自动化收到一封邮件后，需要把邮件的附件传给快捷指令。
快捷指令中的第一步可能是：
获取「输入快捷指令的信息」
然后从这个输入中提取附件。
问题在于，如果先单独创建快捷指令，此时它实际上没有自动化输入。
所以在选择「输入快捷指令的信息」之后，某些类型无法直接修改成所需要的内容。这会导致快捷指令无法正确配置自动化传进来的数据。
解决方式是先新建一个空白快捷指令。
然后新建自动化→ 添加「运行快捷指令」选择空白指令→ 回到空白快捷指令
此时再选择「输入快捷指令的信息」， 就可以根据自动化提供的输出，修改类型，进一步选择对应的详细信息，例如附件，然后继续编写后续流程。
这个问题平时不容易遇到，但一旦开始制作「邮件自动收附件」「收到信息后自动处理」这类有输出的自动化，就会变得明显。
从叫自己起床，到计算教学周，再到自动收作业、检查漏收附件、找出未交名单。
快捷指令真正有意思的地方，其实不只是「做一连串动作」，而是把原本需要自己不断重复的、机械的操作串成一条自动化流程，减少人为干预。所以个人认为最能体现快捷指令哲学的指令是提醒快递取件码：
收到快递短信→ 正则提取取件码→ 添加到提醒事项并设定到达某地提醒→ 经过快递驿站时主动提醒有快递未取
流程走完，只有最后一步需要人来执行。把原本反复的思考、判断、操作变为系统流程，让不重要的重复性决策自动化，减少不必要的认知消耗。
新学期开始，如果你也准备折腾快捷指令，不妨从这些每天都会遇到的小问题入手。

就连一贯坚持 4:3 的 ThinkPad，也从 T60 这一代开始提供 16:10 的版本。
本期《怀旧手记》要聊的不是 ThinkPad 第一款 16:10 笔记本，而是 T 系列最后一款 4:3 机型：T61p。
就如我们所说的，2006 年 11 月 28 日 ThinkPad 正式发布了 16:10 屏幕比例的 T60 系列，但是只有 15.4 英寸的版本，才提供 16:10 的屏幕比例。而在国内，2007 年 1 月 16 日宽屏版正式登陆中国市场。
到了 T61 这一代，2007 年 5 月联想正式公布了 14.1 英寸版本的 T61。在发布前，市场就已经有消息传出 T61 依旧会提供两种屏幕比例的版本。仅仅一个月之后，2007 年 6 月 28 日，联想在国内举行了发布会，正式推出了 14.1 英寸宽屏比例版本的 T61。
从联想的举措可以看出，T61 系列主推的是 16:10 宽屏版，无论是 14.1 英寸还是 15.4 英寸。
但是这并不代表 4:3 屏幕比例的 T61 系列便不存在了，在 T61 标准版中，无论是当年刚发售还是现在的二手市场，你都能时不时见到 16:10 和 4:3 两种版本。
不过当我们把重点放在 T61p 上，情况会更加特殊。在当年你或许能看到部分媒体对外展示的 T61p 是 4:3 比例的正屏，但是到了现在的二手市场，你几乎见不到 4:3 屏幕比例的 T61p。
更常见的还是 15.4 英寸的 16:10 宽屏的版本，这其实并不矛盾，因为虽然都同属于 T61 系列，但是 T61 标准版定位更加偏向于商务办公笔记本，而后缀带「p」的 T61p 则是更偏向于移动工作站。
移动工作站的定位决定了 T61p 上更常见的是大屏幕。16:10 宽屏无论是做设计还是看电影，视野都比 4:3 更宽一些。
ThinkPad T61 系列屏幕比例区别
而回到我手上这一台 T61p，它就是当年为数不多的使用了 4:3 屏幕比例的版本。
虽然存量并不多，但是根据 ThinkPad T61 and T61p (14.1-inch) Hardware Maintenance Manual（硬件维护手册）
我们可以看到，官方是把 14.1 英寸 4:3 屏幕比例的 T61 和 T61p 放在一个硬件维护体系当中的。
而在官方手册里可以看到，T61 标准版的 4:3 版本并不少，T61p 上相对少很多，但也不是完全没有，只不过绝大多数是 CTO 的机型。
而 CTO 则是我们常说的企业按需定制，简言之，如果你想以个人身份购买一台对外零售的 4:3 版 T61p，可能比买 16:10 版难不少。
那 T61p 的 4:3 版和 16:10 版到底有什么不同？通过我这台机器的实测，可以给大家讲讲。
在外观方面，两种版本的 T61p 用料都是一样的，A 面采用大面积的类肤质涂层，同样都是经典的七行键盘。机身内部的镁铝合金框架也并没有因为屏幕比例不同而减配。
不过在机身的尺寸和重量方面还是有明显不同的：
- 4:3 正屏版 (14.1 英寸)：设计更紧凑。重量约 2.4 - 2.5 kg，尺寸约为 333 x 238 x 28-32 mm。
- 16:10 宽屏版 (15.4 英寸)：机身更宽大。重量约 2.7 - 2.8 kg，尺寸约为 358 x 255 x 30 mm。
所以把两种比例的 T61p 放一起对比，像我手上这台 4:3 的，键盘左右两侧并没有明显的空余，键盘上方也没有扬声器开孔。
而 16:10 版本的键盘两侧的空余处更多，并且键盘上方有明显的扬声器开槽。
因为 4:3 版本的 T61p 扬声器并不在键盘上方，自然没有开槽。通过后续的实际拆解我们可以发现正屏的版本扬声器是在笔记本电脑底部的。
本文 T61p 的官方配置
配置方面，整个 T61 系列包含标准版和 T61p，配置各有不同，在此不对每一款详细展开。
但是根据我手上有的这一台 4:3 的 T61p，它对应的配置是：
- 屏幕：14.1 英寸，4:3 比例，1400x1050
- CPU：Intel Core 2 Duo T7500 2.2GHz
- 显卡：NVIDIA Quadro FX 570M（128MB 显存）
- RAM：官方标配 1GB DDR2，官方最大支持双卡槽扩展 4GB
- 硬盘：160GB 5400RPM（制造商为日立）
虽然说 4:3 和 16:10 的 T61p 有多款配置，但是可供查证的是 4:3 比例（14.1 英寸）的 T61p 搭载的 NVIDIA Quadro FX 570M 显存往往是 128MB，而 16:10 比例（15.4 英寸）的 T61p 则是 256MB。
当然，T61p 并非全部搭载 FX 570M，根据中关村在线等渠道的历史参数记录，部分型号如 6457RU1 搭载的是 NVIDIA Quadro NVS 140M。不过 NVS 140M 多见于 T61 标准版，在 T61p 上属于相对少见的配置。
「显卡门」历史
不过，不论是 NVIDIA Quadro FX 570M 还是 NVIDIA Quadro NVS 140M 都是基于英伟达 G84/G86 的独立显卡芯片。
而当年采用英伟达 G84 和 G86 的独立显卡有很大一部分概率会遭遇「显卡门」事件。
具体原因是，英伟达 G84/G86 系列显卡核心的封装材料有缺陷。这种材料的热膨胀系数与 GPU 芯片不匹配，导致芯片在高温下反复热胀冷缩后，与主板焊接点脱焊（空焊）。
遭遇「显卡门」事件的机器，往往会遇到以下几种情况：
- 开机无画面，机器鸣响报错
- 显示异常，出现花屏、黑屏、白屏，甚至同时显示两种或三种画面
- 机器不稳定，频繁死机，蓝屏重启，温度过高。
在当年事情发酵后，厂商层面英伟达承认问题并拨款数亿美元处理，各 PC 厂商通过更新 BIOS 强制风扇全速运转来延缓故障，但治标不治本。
更完善的解决方法则是采用 2008 年后英伟达推出的改善版显卡芯片。
T61p 的 OEM 系统
说回系统，当年的 T61 系列多数搭载的是 Windows Vista Business 和 Ultimate，有部分版本搭载的也是 Vista Home Premium 和 Home Basic。
这些配置运行 Windows Vista 肯定是没有问题的，不至于过分的卡顿，但是在兼容性方面可能没有 Windows XP 更加完善。
所以联想也对应的有提供 T61 系列的 Windows XP 版本的 OEM 系统。
因此我们本次的系统测试以及软件体验均基于搭载联想官方 OEM 版 Windows XP Professional SP3 的版本。
原厂系统的安装并不复杂：准备一张空白光盘，把 ISO 镜像刻录进去，塞进 T61 的光驱，进 BIOS 把第一启动项设为光驱启动，剩下的就交给联想的自动化安装了。
系统安装的过程当中会重启多次，你可以看到系统在逐步的完善，从驱动的安装再到个性化壁纸以及捆绑的第三方应用。
恢复耗时跟机器配置有关，我这台 T61p 大约花了半个小时。
恢复完成之后，所有的驱动原厂软件功能均正常，自带了很多的第三方软件，但是多数还是跟商务办公相关。
这台 T61p 到我手上之后，我又对它进行了硬件升级，内存从官方标配的单条 1GB 升级到了两条 1GB 组成的 2GB 双通道。同时，将原本只有 5400 转的 160GB 机械硬盘换成了 7200 转的 500GB 机械硬盘。
在升级后的配置下，运行 Windows XP Professional 非常流畅。
软件体验
软件方面，我安装了 Office 2007 配合 ACDSee 看图。
因为 XP 最后支持的 IE 版本为 IE9，部分网页已经打不开，另一部分会渲染错误。
但实测 360 极速浏览器 13.5 正常浏览网页没有问题。Firefox 最后支持 XP 的版本是 52.9.0 ESR，相比 360 极速浏览器，Firefox 在部分较新的网页和视频网站上的支持要差一些。
播放 MP3 可以用 XP 自带的 Windows Media Player，也可以用千千静听和 Winamp。个人觉得 Winamp 在冷启动以及系统占用方面优化得更好。
输入法可以使用搜狗的 7.2 历史版本，不过如果想要体验更多新功能和特性，在搜狗输入法官网也可以下载到最后支持 XP 的历史版本。

游戏方面，目前我一共安装了三款：
植物大战僵尸，离线版本体积不大。2009 年的游戏原生支持 XP 和 Win7，对电脑性能的要求更多的是运存以及显卡。

体验完上述游戏和软件可以发现，4:3 屏幕比例的优势在此刻就体现出来了。用 Office 办公、玩千禧年左右的老游戏，配合 Windows XP 系统，4:3 都很舒服。
Office 办公时屏幕上下显示的内容更多，而各种经典老游戏原生支持 4:3 显示，不会因为比例不同而缩放画面。

上述潜在因素依旧存在，所以除了在软件方面尽可能使用轻量软件，在不必要的情况下也尽可能不让显卡有过高负载。

机器拆解
在拆解部分，我们遵循 ThinkPad T61 and T61p (14.1-inch) Hardware Maintenance Manual（硬件维护手册）的官方步骤。
将笔记本翻到背面，取下电池，用螺丝刀把一旁印有键盘图标的螺丝卸下。
将笔记本翻回正面，轻轻掀起掌托，注意掌托部分有一根排线连接。
然后将键盘轻轻向下滑动抬起，注意键盘下方也有对应的排线连接。
之后你就能看到完整的机器内部结构，首先看到的是大量的镁铝合金框架，进一步加强笔记本的结构强度。
我们先将内存取出，放置一旁。如果有条件可以将笔记本上面的主板电池同样更换，型号为 CR2032。
接着卸下对应的螺丝，就可以将左右两侧的边框取下，然后将笔记本散热器上面的四颗螺丝取下。
轻轻掀起散热模块，注意拆下之前先把一旁的排线拔下，不要划伤 CPU 和显卡，然后就能看到 CPU、显卡以及南桥。
你可以先用气吹加刷子把散热模块上的灰尘清理干净，如果非必要请不要将散热风扇内部的扇叶取出。
把 CPU 和显卡芯片上的硅脂擦干净，散热器底部的硅脂也一并擦干净，然后就可以涂新的了，我用的是 7921。
这里分享一下我的做法：确保 CPU 和显卡芯片上的硅脂已经擦干净后，把 7921 点涂在两者中间，大概黄豆大小。
然后把散热模块垂直盖上去，把原来的四颗螺丝按对角线一点一点拧紧。
确保散热模块装回、排线插好后，再把取下的内存金手指擦干净装回，然后把键盘装回。
先不用完全装回去，基础部分连好后可以短暂用电源适配器开机测试，点亮后把电源拔下，再按开机键释放静电，最后把剩余的掌托和螺丝拧回去。
到此 T61p 的机器拆解部分，以及清灰更换硅脂就完成了。
再补充一些历史信息
回到标题，为什么说 T61 系列是 ThinkPad 最后的 4:3 屏幕比例的笔记本电脑？
因为在 T61 之后的 T400，T500，联想并没有提供 4:3 屏幕尺寸的版本。
再加上前文提到的 T61p 4:3 版本比较少见，导致部分人甚至不知道 T61p 还有 4:3 版本。
其实 4:3 的 T61p 本身并不罕见，根据官方硬件维护手册，CTO 占了绝大多数。
只是在消费市场上，能通过正常官方渠道买到的 4:3 版 T61p 确实比较少。
借着这次机会，我们也看到：在 2007 年消费级笔记本 16:10 宽屏逐渐流行之际，依旧有厂商愿意把 4:3 屏幕放在自家高端产品上。

在软件工程和科研领域，OpenAI 称 Astra 是其目前能力最强的软件开发模型。官方测试显示，该模型在系统控制、浏览器交互、数学推理、科学研究和网络安全等多项测试中取得了此前模型的最高成绩。Astra 还可以调用专业软件完成数据处理、测试和验证。

针对潜在的滥用风险，OpenAI 对 Astra 采取了更严格的安全措施，包括隔离训练环境、限制网络访问权限和敏感工具调用、保护模型权重，以及进行持续监控和自动干预。发布初期，高级网络安全功能仅向受邀的安全测试人员开放，后续将通过「Daybreak Blue」等防御性研究计划扩大使用范围。
