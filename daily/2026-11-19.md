Open Code Review is an AI-powered code review CLI tool. It originated as Alibaba Group's internal official AI code review assistant — over the past two years, it has served tens of thousands of developers and identified millions of code defects. After thorough validation at massive scale, we incubated it into an open source project for the community. Simply configure a model endpoint to get started.
It reads Git diffs, sends changed files to a configurable LLM via an agent with tool-use capabilities, and generates structured review comments with line-level precision. The agent can read full file contents, search the codebase, inspect other changed files for context, and produce deep reviews — not just surface-level diff feedback. Beyond diff review, ocr scan reviews entire files for auditing unfamiliar codebases or directories that have no meaningful diff.
Visit the official website for more details.
Compared to general-purpose agents (Claude Code), Open Code Review achieves significantly higher Precision and F1 with the same underlying model, while consuming only ~1/9 of the tokens and completing reviews faster. Note that its Recall is lower than general-purpose agents — a deliberate trade-off favoring precision over noise.
A real-world code review benchmark built from 50 popular open-source repositories, 200 real Pull Requests, and 10 programming languages — cross-validated by 80+ senior engineers (1,505 annotated ground-truth issues).

If you've used general-purpose agents like Claude Code with Skills for code review, you've likely encountered these pain points:
- Incomplete coverage — On larger changesets, agents tend to "cut corners," selectively reviewing only some files and missing others.
- Position drift — Reported issues frequently don't match the actual code location, with line numbers or file references drifting off target.
- Unstable quality — Natural-language-driven Skills are hard to debug, and review quality fluctuates significantly with minor prompt variations.
The root cause: a purely language-driven architecture lacks hard constraints on the review process.
Open Code Review's core philosophy is to combine deterministic engineering with an agent, each handling what it does best.
Deterministic Engineering — Hard Constraints
For review steps that must not go wrong, engineering logic — not the language model — guarantees correctness:
- Precise file selection — Determines exactly which files need review and which should be filtered, ensuring no important change is missed.
- Smart file bundling — Groups related files into a single review unit (e.g., message_en.properties and message_zh.properties are bundled together). Each bundle runs as a sub-agent with isolated context — a divide-and-conquer strategy that stays stable on very large changesets and naturally supports concurrent review.
- Fine-grained rule matching — Matches review rules to each file's characteristics, keeping the model's attention sharply focused and eliminating information noise at the source. Compared to purely language-driven rule guidance, template-engine-based rule matching is more stable and predictable.
- External positioning and reflection modules — Independent comment-positioning and comment-reflection modules systematically improve both the location accuracy and content accuracy of AI feedback.
Agent — Dynamic Decision-Making
The agent's strengths are concentrated where they matter most — dynamic decisions and dynamic context retrieval:
- Scenario-tuned prompts — Prompt templates deeply optimized for code review, improving effectiveness while reducing token consumption.
- Scenario-tuned toolset — Distilled from deep analysis of tool-call traces in large-scale production data — including call frequency distributions, per-tool repetition rates, and the impact of new tools on the overall call chain — resulting in a purpose-built toolset that is more stable and predictable for code review than a generic agent toolkit.
- Git >= 2.41 — Open Code Review relies on Git for diff generation, code search, and repository operations.

View PDF HTML (experimental)
            Abstract:Large language models (LLMs) generate text by auto-regressively sampling the next token. This inherently leads to a many-to-many mapping between prompts and responses, complicating the task of inferring prompts from observed outputs. Prior work on LLM inversion frames prompt recovery as a semantic reconstruction task. They rely on fine-tuning pretrained sequence-to-sequence models on large external datasets--and requiring access to model weights or logits--to generate semantically plausible prompts. In contrast, we present a functional approach to inverting a given LLM in a black-box setting, without auxiliary aids. We train an explicit inverse language model entirely from scratch on data synthetically generated from the target LLM itself. Analogous to forward next-token prediction, our inverse model is trained using previous-token prediction, establishing a generative link between the forward and inverse processes that enables faithful prompt reconstruction. Moreover, it naturally supports diverse prompt reconstructions through sampling, whereby all such prompts induce similar responses under the forward, target LLM. Our approach generalises across datasets and exhibits transferability in reconstructing prompts from responses generated by different LLMs. Further, across the set of token based evaluation metrics for prompt and response reconstructions, our approach outperforms prior work.

Software companies are trying to kill home computing
 If you use a computer or any other device which runs software on it, here's something which you might want to know: Software companies are not your friends, and in fact, they are trying to kill personal and home computing.
The reason for this is simple: Software companies, like any other business, are out to make money, but what's good for computer users is not good for software companies, and the reason for this is that software companies are not selling a physical product.
Hardware companies are different. Hardware companies usually want to make good products, because they can get repeat sales. Hardware wears out, breaks, or simply gets replaced, and so in the hardware business, mostly the same laws of business and economics apply as in any other home-appliance business such as selling refrigerators, ovens, and washing machines. I say "mostly" because computer hardware is still experiencing some minor amount of technological development, particularly in the field of GPUs, but in contrast to the 1980s and 1990s, this development is no longer proceeding so rapidly that it's likely to fuel an upgrade cycle (a person today is not likely to buy a new computer because their old computer is obsolete, for the simple reason that computer hardware no longer advances quickly enough for a still-operating computer to become obsolete within its working lifetime), but people who want to have the absolute latest technology may still buy new hardware for that reason alone; this is a fairly small niche of hardcore technology enthusiasts, but such consumers may provide considerable revenue to companies like Nvidia, which specialize in bleeding-edge hardware. Most other hardware companies, however, are selling commodity hardware in an established market which is not likely to experience much growth or other change, and thus the business model works on the same principle as companies selling refrigerators: You're selling durable goods to people who are making a one-time purchase, but if your products are good, then you'll develop a reputation for quality, and so other people in the situation of making a one-time purchase will also buy your products. There are some hardware companies which take the opposite approach, namely the thinking that if you sell fragile products which break quickly, then you can get more business because people will buy replacements more quickly, but the same principle applies here as in other businesses selling physical products, like the car business: If you develop a reputation for selling cheap junk which breaks quickly, then you'll lose a lot of business long-term, so most hardware companies (at least those with widespread name-brand recognition) want to protect the value of their brand and sell good products which work well and last a long time. Business comes not from customers re-buying stuff to replace cheap junk which breaks quickly, but quite the opposite: From customers who need to replace hardware which worked well for long enough that they feel it's worth buying another product from the same brand. 反返《痛/快》
2026 年 10 月 29 日
冷面热心肠，走啊走啊走
年底各家音乐平台争相推出年度盘点，反返是名单上的大热——Apple Music 2026 年度最佳歌曲（《刺客》）、网易云音乐 Z 世代 30 佳新声……在网易云上，这张《痛/快》发布两个星期收藏量便大破两千次。
反返还是那么酷，上一张自我介绍专辑《反返》封面是负片效果的莲蓬脸（？），诡异风犹记在心，这回新专封面，乍一看以为是藏在石窟里的佛家图腾，堆叠的脸孔迷离忧郁，正如专辑流露的听感色彩。
听她的歌，你高兴不起来，会跟着她一起坠入记忆的深河，听着听着，不知怎的竟流起泪来。
常有人把反返归为电子音乐人，电音元素营造一个清冷而有疏离感的世界。这回，她抱起了吉他，音乐添加许多暖意，虽然制作还是用电脑拼贴，音色的选择却大部分向原声乐器靠拢，展现出民谣摇滚的色泽。
小打鼓点的带动（《Dear Friend》）、竹笛的穿引（《慢慢慢》）、更易共鸣的旋律（《家》《坠河》）、更朴实的演唱叙事（《蓝天》），都升腾出浓浓的人情味，你别看她总用黑色涂抹自己，却也不掩饰那颗温热的心。

反返摆脱了音乐风格的控制，更注重情感的表达，这些理念和行动上的蜕变，在我聆听的过程中都真切地感受得到，即便不听她唱的是什么，依然能被旋律意境和声音表情散发的情绪击中。

连亚喆《And Another Lake》

每天都想逃离
连亚喆所在的乐队心头肉，一直是我的心头肉。

诗意的词曲，伴着深情的男声，不卑不亢，款款歌唱。连亚喆这回的唱腔并不像在乐队里那样张扬，而是走内敛深情，甚至没有精雕细琢，粗粝无修饰的演唱细节更见血肉。

《Mind Palace》是钱润玉的第二张创作专辑。据她说，专辑由童年的碎片、灵性的微光、潮流的奇想组成，还有那些曾为了活下去而遗落的自己，它们共同筑起心灵的宫殿，每首歌都像一扇门，每推开一扇门，都会离真正的自己更近一点。

你的 AirPods，其实一直知道你的头朝哪
空间音频这个功能，用 AirPods 的朋友应该都试过：转头的时候，声音还停在原来的方向，就像音箱摆在你面前一样。
能做到这一点，是因为 AirPods 里装着陀螺仪和加速度计，一直在读你头部的朝向。这些数据本来只给空间音频用，但从 macOS 14 开始，苹果开放了一个叫 CMHeadphoneMotionManager 的接口，第三方 App 也能读到。
我做的 NodLink 则很简单：既然耳机知道你的头朝哪，那就让光标也跟着走。
我希望它能帮到手不方便的朋友，例如有肢体障碍、或者长期卧床的人，用电脑这件事对大多数人来说太自然了，但对他们来说，挪一下鼠标、点一下按钮可能都很难。
为什么不用摄像头
其实苹果系统里自带了「头部追踪」辅助功能，靠前置摄像头看你的脸。但摄像头方案有几个绕不开的问题：要有光、要正对屏幕、脸还得在画面里。专门的头控鼠标价格往往要上千美元，还得额外戴个反光贴片或者传感器。
NodLink 只读 AirPods 里的传感器，全程不开摄像头。所以理论上，躺着、侧着、关了灯都不影响。对卧床的人来说，这一点我感觉挺关键的。
它能做什么
左右转头，光标左右移动；抬头低头，光标上下移动。校准之后，头部角度会直接换算成屏幕上的位置，你看向哪，光标就在哪。
看东西的时候，人很少会歪头，所以歪头特别适合拿来当「按键」，和移动光标不冲突：
- 向左歪头再回正：单击
- 向右歪头再回正：右键
- 向左歪头不回正：按住，可以拖拽，回正就松开
同时这些都能自己改。例如把左歪头改成「按住 Fn 语音输入」，就能直接说话打字；刷视频的时候，左歪头又可以是「下一条」。
如果你觉得歪头不方便，也可以直接说：「点击」「双击」「右键」「上滑」「下滑」「复制」「粘贴」「撤销」「关闭窗口」……中文英文都行，「click」「command tab」这种也认。语音识别用的是系统自带的本地识别。
这里还有个小细节：你一开口，光标就会冻住，等识别完再在冻住的位置执行。不然识别那零点几秒里，头稍微一动，光标就会跑偏。按钮太小、头不好对准的时候，还可以说「标号」：头指的地方附近，能点的按钮会标上 1-9 数字，说个对应的数字就能点中；执行点击的时候，光标也会自动吸到附近能点的按钮上，并画一圈框告诉你选中的是哪个。
对想转头看别处又不想光标乱跑的情况，说一声「暂停」，再说一声「继续」就能再接着用。慢慢地歪头、或者边转头边歪头都不会被当成点击。按一下 Esc，或者碰一下真鼠标、键盘，控制权又会马上回到你手上。
实际用起来是什么样
下面的图都截自我的演示视频，戴着真的 AirPods、手不碰键鼠录的。右下角的小窗是我本人的动作。
控制台左边是歪头的角度，底下是左右转头，右边是上下点头。实际戴上之后你会发现苹果这颗传感器真的很灵敏，数值也很稳，整个头控系统就是基于它的数据来的。
下面这是我自己画的小角色，奶蛙自己不会动，它的每个动作都来自你的头：你点头它就笑，点得越快笑得越快；你一停，它也停；转头的时候，它还会出招。
我也在控制台里做了四个练习场景，都是平时用电脑最常做的事，可以先在这里熟悉操作。
- 关弹窗。头指到按钮上，说「点击」。开口那一刻光标先停住，识别完就在停住的地方点下去。
- 刷短视频。左歪头下一条，说「双击」点赞，右歪头打开评论区。
- 回消息。左歪头不回正，等于按住 Fn，用输入法说话；回正就松开，字就上屏了。最后说一声「点击」发出去。
- 点外卖。把前面几种办法串起来：语音点选菜品、选送达时间，歪头说备注，最后下单。
说实话语音偶尔也会听错，录视频的时候它就把我说的「点击」听成过「天气」，这种时候什么都不会发生，再说一遍就好。
练习场景之外，我也在真实的抖音网页版上试了试：左歪头换下一条，全程不用手。（图里别人的视频已经模糊处理。）
为了调试方便，也为了好看，我给控制台做了一个 3D 场景。第三人称视角下，能看到一个小人戴着耳机，头朝向的延长线落在哪块屏幕上；切到第一人称，就是你自己的桌面视角。
背后的一点原理
如果你对实现感兴趣，这里简单说几个我觉得比较有意思的地方。
- 校准用的是鼻尖，不是眼睛。戴上耳机后，先用鼻尖对准屏幕正中的点，保持 2 秒，定下「正前方」。想更准，可以再做一次 30 秒左右的路径校准：先看中心和四个角，再用鼻尖跟着光标沿四边走两圈。这里一定要用鼻尖，因为 AirPods 测的是头的朝向，不是视线，只转眼珠是没用的。
- 防抖。人的头不可能完全不动，光标直接跟着走会一直抖。NodLink 用了一种叫 One Euro 的滤波：头不动的时候使劲压住抖动，快速转头的时候又尽量不拖慢。
- 漂移校正。AirPods 里没有指南针，左右方向只能靠陀螺仪一点点累加，用久了会慢慢偏，最后可能得把头扭向一边才能看到屏幕中间。好在用电脑的时候，人总体上是正对屏幕的，所以 NodLink 会在后台悄悄地、慢慢地往回拉。真偏多了，说一声「回中」或者按 C 就好。
技术上，Mac 端是一个用 Swift 写的小程序（我叫它「耳机桥」），负责读耳机数据、听语音指令、控制系统鼠标；校准、滤波、手势识别和 3D 场景都在一个网页控制台里，用 Node.js 和 three.js 写成。
怎么装
你需要一台 macOS 14 以上的 Mac，和一副支持头部追踪的 AirPods（第 3 代及以后、Pro、Max）。具体的安装步骤都写在 GitHub 的 README 里，跟着走就行。
装好之后按页面顶部的引导走：连接耳机 → 定正前方 → 开始头控。用到的权限和数据都只在本机处理。没有 AirPods 的话，可以直接打开在线版用鼠标模拟头部，先感受一下。
NodLink 目前只支持 Mac，安装也有点门槛，要开终端、装 Node.js，对不熟悉电脑的朋友不太友好，之后我也想做成双击就能装的 App。另外就是语音偶尔会听错，上面也说了，听错了再说一遍就好。
其实我最想做的是手机。手机屏幕小、按钮密，又是很多人躺着时用得最多的设备。但 iOS 不允许一个 App 去控制别的 App，纯软件做不到。所以我打算加一块很便宜的 ESP32 小板子：iPhone 上的 App 读 AirPods 的头部数据，发给 ESP32，ESP32 再以蓝牙鼠标的身份连回同一部 iPhone，借系统的辅助触控来移动光标、点击。但这都是后话了。

- [How to make AI data centres more sustainable](https://www.nature.com/articles/d41586-026-03708-6) <sub>11-18 08:00</sub>

<details>
<summary>📄 展开阅读全文（5860 字）</summary>

Around the world, people are demanding a halt to the proliferation of data centres — racks of computers, housed in warehouses, that are powering the boom in artificial intelligence. Communities worry that existing infrastructure will not be able to handle the surge in demand for electricity and water, and that data centres’ energy demands will cause environmental and health problems, including increases in air pollution and greenhouse-gas emissions. The question of whether AI is going to stall climate action is explored in the first of a three-part Nature Podcast (Nature https://doi.org/rzqs; 2026).
Is the climate totally cooked? What the data say
People have many concerns about the way AI is being developed, including how it might affect safety, security and jobs. Where energy is concerned, however, any added demand for computing power can, and must, be met in smart, sustainable ways, not by burning more fossil fuels. Achieving this will take some creative thinking, and researchers need to be closely involved. Many argue that there are alternatives to relying on energy-intensive data centres, such as AI models that can run on individual computers or institutional servers, thereby consuming much less power than those run using cloud services. Efforts to develop such options need to be better funded.
Future projections of data centres’ energy demands are hard to make, because they are based on assumptions that could change. If current global trends continue, electricity consumption by data centres will go on rising. Between 2017 and 2024, it grew by around 12% per year. Figures for 2024 from the International Energy Agency (IEA), based in Paris, show most of this demand coming from three regions: the United States (45%), China (25%) and Europe (15%).
The Electric Power Research Institute, a non-profit organization in Palo Alto, California, has projected that the continued growth of US data centres could add up to 94 gigawatts of demand by 2030, equivalent to 17% of the country’s electricity consumption. Data centres currently consume more than 1.5% of the world’s electricity supply, and the IEA’s projections indicate that this figure will more than double in the next few years. By 2030, data centres could consume more electricity than Japan, the agency says.
Why scientists should lead the shift away from AI mega data centres
There are serious concerns that this extra demand will be powered mainly by fossil fuels, when carbon emissions are already at a record high. Research published this week in Nature Sustainability estimates that some 400 data centres in the United States accounted for around 26 megatonnes of carbon dioxide emissions between May 2024 and April 2025, more than those produced by many countries (G. Guidi et al. Nature Sustain. https://doi.org/hcsptc; 2026). And according to a study published last week in Nature Climate Change, data centres’ energy demands could prolong the lifespan of coal-fired power stations (C. Li et al. Nature Clim. Change https://doi.org/rzqr; 2026).
But none of this is inevitable. Governments could mandate that new energy demand be met with renewable sources. And regulators could look at alternative ways to manage existing electric supplies.
Many nations’ electric grid systems are designed to accommodate surges in demand, whether to power extra cooling on hot summer days or extra heating during winter cold snaps. Much of the time, there is excess capacity. This excess could be used to reduce the amount of new energy needed to power data centres.
How much energy will AI really consume? The good, the bad and the unknown
One solution is to curtail data-centre operations during periods of peak electricity consumption, and ramp up at times of lower demand. An analysis released in 2025 by researchers at Duke University in Durham, North Carolina, found that the US electric grid could accommodate 98 gigawatts of extra demand in this way, without adding any new generation capacity (see go.nature.com/4cdeknm). That 98 gigawatts would be enough to cover most, if not all, of the expected expansion in US data centres over the next few years.
There is potential for this to become a reality. In June, as part of a larger effort to modernize the grid, the US Federal Energy Regulatory Commission instructed grid operators to draw up a plan for how they will cope with extra demand from data centres. The technology industry is understandably paying close attention to how it might mitigate the problems of powering data centres. Earlier this month, OpenAI announced what it is calling a “grid protectors program”, a project to consult with US grid operators, regulators and policymakers to see how the company can work around peaks in power demand.
Meanwhile, Google is paying households and businesses in parts of the Eastern United States to reduce their electricity consumption during periods of high demand. Similar proposals are being considered in other countries.
Why open-source generative AI models are an ethical way forward for science
These are all tentative moves in the right direction, although arguably progress is not being made fast enough. Policymakers and data-centre operators must engage seriously with those who oppose the centres’ expansion. At a minimum, any new energy sources developed to power these centres must be renewable. Existing energy sources can also be better deployed, and researchers working to develop alternatives to energy-intensive data centres should be better supported. More peer-reviewed evidence is needed, especially for countries outside the United States.
There are smarter and more sustainable ways to power the growth of AI, but to achieve them, concerted and coordinated action will be needed. In this way, the harm posed to people and the planet can be minimized, and AI technologies can benefit everyone.
